# Design

## Context

See `proposal.md` - Why. 当前仓库已存在无头 `DocCore`（唯一 Buffer/History、单个打开块、输入组、模式和只读访问状态）、M1 原生只读文档会话与虚拟阅读/源码行列表；原生窗口目前消费 `ReadonlySession`，并未接入编辑输入。M0 身份与补丁原语、M1 只读能力均不是可编辑 UI、IME 或安全保存的验证证据。参见架构 §5～6、决定 §43、验证计划 V-07/V-08。

## Goals / Non-Goals

**Goals:**

- 在现有单文档/单窗口生命周期内把只读呈现接到已确认的文档编辑协议，维护源文本唯一事实来源和明确副作用所有者。
- 将 V-08 身份/事务方案及审查作为保存/恢复与原生 IME 消费接线前的明确 go/no-go；W4/W5 change 保持详细设计和实现所有权。
- 让 M2 的阶段出口可以追溯到 PRD AC、V-07/V-08 场景、实际平台证据和仍未测项。

**Non-Goals:**

- 本伞变更不重新设计已确认的输入组、IME、文件保真、自动保存、恢复、冲突或编辑语义；V-08 前置只收敛身份/事务消费方案和边界，不代替对应专项 change 的评审。
- 不实现 M3 命令/表格/HTML 编辑，不实现 M4 资源全迁移/插件，不实现 M5 多标签/多窗口/工作区；不以应用全局架构替换现有八 crate。

## Decisions

### 1. 先冻结 V-08 身份/事务方案，再允许依赖写入的功能接线

- **问题：** M0 有 `DocumentId`、工作版本、快照身份和 create-only 文件原语，但 V-08 明确尚未冻结身份、目标、资源登记与实际写入回执的组合事务。保存、IME 发布等待和临时资源交错不能仅凭现有身份信封推断安全。
- **冻结的身份模型：**
  - `DocumentId` 只标识本进程中的文档会话；`WorkingVersion` 标识 Buffer revision 与草稿代次；`SnapshotId` 只标识快照视图来源。请求携带这三者及实际被冻结的 `CurrentSnapshot`（文本、源码选区、资源强引用），不以 `SnapshotId` 代替内容或内容哈希。
  - 每个持久化动作另有单调 `OperationId`/取消状态、目标关联代次 `PathGeneration`、所观察的目标身份与 `DiskVersion`、存储 `BaselineId`/原 bytes 证据，以及快照对应的资源清单代次和稳定资源记录键。`InputIdentity` 仅供解析/投影等派生结果采纳，不是持久化事务键。
  - `DiskVersion` 是会话代次，不能证明磁盘相等；目标类型、可取得的平台文件对象身份、实际打开句柄下读取的原 bytes/受检内容证据独立记录。mtime/size 只作快筛。覆盖确认绑定用户确认时看到的目标观察；写前必须重读并验证目标未改变。最后验证到替换之间仍可能有外部竞争窗口，不能承诺跨进程 CAS，实际保证按平台取证。
  - 恢复记录和资源清单跨进程存活，因此另设不透明稳定 `RecoveryRecordId`/`ResourceRecordId`；它们不序列化 `DocumentId`、`ResourceReference` 的指针身份，不以文档名或源路径哈希生成。恢复存储以独占创建保证新键不覆盖既有记录；记录有格式版本、完整性/预算校验，坏记录隔离且不自动删除来源不明文件。具体键字节/熵来源不得新增未准入依赖或 unsafe；若现有平台能力不能满足唯一性，先单独裁决。
- **所有权与结算：**
  - `DocCore` 唯一拥有源码、草稿/组合、选区、历史和冻结快照；`aline-source` 只执行受检字节 I/O 并返回事实；每文档 `PersistenceCoordinator`（`aline-ui`）是唯一队列、目标关联、磁盘基线、保存状态及资源事务编排/结算者。UI 控件和 `app` 仅发意图，不另持 dirty 或文件状态机。
  - 同一文档的持久化/路径改变操作串行。用户可在写入期间继续输入；成功只确认实际被冻结版本/编码 bytes，较新当前内容仍按内容等价判脏，不能按历史栈深、revision 或仅指纹标记干净。回执保存“冻结的逻辑输入”与“实际写入 bytes 解码所得存储基线”两份事实；批准的 CRLF/LF 表示规范化可造成差异，不改变 Buffer 源码、Undo/Redo 或 `encode` 的原 bytes 精确通道。
  - 回执至少区分 `NotPublished`、`PublishedAndSynchronized`、`PublishedDurabilityUncertain`，包含真实 target、冻结输入/版本、实际 bytes 和可观测的同步事实。`PublishedDurabilityUncertain` 仍是已发布 bytes 的事实，供下次目标重验；UI 显示持久性不确定/失败状态，关闭不能当作成功或清理恢复材料。目标观察事实与逻辑内容等价/dirty 是两个独立判断。取消/关闭只撤销尚未到不可逆发布点的资格；一旦发布发生，迟到、取消或关闭都不能丢弃事实，必须由协调器结算。失败不得覆盖新成功或清恢复材料；关闭 guard 等真实操作结算后，再依据最新当前版本重算 dirty/询问，不按早期快照丢弃后续输入。
- **资源与恢复事务：**
  - 保存/恢复快照在发布前完整登记其所需资源；恢复记录只有在记录与资源均完整写入并通过校验后才成为当前可恢复项，失败保留上一份有效记录及所有仍被当前/历史/恢复/在途引用的资源。恢复先进内存，不覆盖用户文件。
  - 首次保存/另存为的资源迁移是有序多步发布，不宣称多文件原子性：先按稳定资源身份计划目标，独占创建/复制资源并核验；每份资源创建/发布都是单独不可逆点，取消不能抹掉或谎报未发生；基于被冻结快照规划引用补丁并重验文档/路径/资源代次；发布 Markdown 后，结算时再次由 DocCore 对当前工作版本、选区/预期片段和资源语义重验。只有合法引用补丁、目标路径代次、实际存储基线与资源关联能在一个 UI 所有者的逻辑提交中一致更新时，才将新目标关联到当前文档。若输入在最后检查后变化，重新规划并重试；不能安全重试时保留原关联、较新输入、恢复材料和两边资源，报告部分完成，不能伪报成功或“取消且无副作用”。另存后 Undo/Redo 必须能按历史中的资源解析上下文访问旧相对/临时资源。垃圾回收只能在证明当前、历史、恢复和在途均无引用后进行。
  - 同步/权限/替换失败用类型化结果保留副作用阶段；`Written` 仅证明本次操作提供的 bytes，不证明目标当前字节、目录持久性或其他进程后续未改写。操作回滚不能抹除已经创建/发布的文件。
- **发布阶段状态：** `Queued → Frozen → Prepared → Revalidated → PublishStep* → Reconciled`。在任何单个不可逆文件发布点之前可以取消该文件动作；取消不撤销前面已发生的资源发布。发布后只能请求取消后续步骤并进入带实际回执的 reconciliation。UI 关联/保存点仅在文档存活且目标/路径代次仍匹配时更新；另存为的路径/引用逻辑提交还需 DocCore 重验当前版本、选区/预期片段与资源解析上下文。不匹配时仍记录写盘事实及目标基线，但不把旧目标挂到当前文档。多资源阶段中途失败保留产物和恢复引用，以明确部分完成状态恢复，不用统一 `Err` 隐藏已发生副作用。
- **最简单方案：** 以上身份、所有者、阶段、回执和失败边界即 W4/W5 共用契约；在本 change 与 W4/W5 design 中引用同一方案，再做独立一致性审查。发现与已确认契约冲突时，暂停受影响任务并更新工件/请求具体裁决。
- **选择：** 采用显式阶段门槛，不在本伞变更中臆造尚未批准的 V-08 事务协议。通过门槛前可推进不依赖保存/IME发布的纯编辑准备，但不得开放生产保存/恢复写路径或 W4/W5 的原生接线。
- **替代方案及代价：** 直接沿用现有 `InputIdentity`/`SnapshotId` 会把“派生采纳身份”误当“当前内容/写盘事实”；以路径、mtime/size、hash 或会话内 `DiskVersion` 单独识别目标会漏掉同尺寸同时间戳外改、别名和替换；套用派生任务的“旧结果丢弃”会丢真实 I/O 副作用。以上均不满足现有 SAFE/TA 契约。具体平台身份/原子替换能力仍需验证，超出平台证据的保证失败关闭。

### 2. 沿用既有状态所有者，按闭环逐层接线

| 能力/状态 | 唯一所有者 | 允许边界与副作用入口 |
|---|---|---|
| 源码、选区、单个块草稿、输入组、历史、模式和当前快照 | `aline-ui` 的文档核心；补丁/历史原语由 `aline-buffer` 持有 | 文档核心调用 `aline-buffer` 的受检操作；不能在 UI 子编辑器或 renderer 保存第二份可提交全文/历史 |
| 解析、保护区间、绘制与源码坐标映射 | `aline-markdown` | `aline-ui` 消费携带版本的解析和映射 API；不手算坐标、不让引擎依赖 GPUI |
| 纯变更计划和拒绝 | `aline-edit` | 计划绑定工作版本/源范围；实际提交只由文档核心执行，拒绝零副作用 |
| 磁盘字节和安全文件原语 | `aline-source` | 只提供受检 I/O 原语；文档保存/资源协调副作用由 `aline-ui` 按 W4 协议编排 |
| 原生按键/IME/焦点/布局事件适配 | `aline-ui` 与 `app` 的既有平台装配边界 | W5 消费同一文档核心与映射；不在引擎 crate 放 GPUI，不创建第二个输入状态机 |
| 窗口呈现与虚拟阅读 | `aline-ui` | renderer 仅读当前快照/派生布局；用户意图走文档核心受检入口 |

M2 采用 Functional Core / Imperative Shell 的既有分层，而不引入新模式包装：纯解析、映射、计划、历史转移无窗口验证；`aline-ui` 持有事务和平台副作用。只有确有多个状态生命周期或独立故障注入边界时才增加内部模块/接口，沿用八 crate，不增加 Service/Repository 空壳。设计沿用 CODE_STANDARDS §2～4、架构 R-3～8/10/15～17 与 Rust S-5/7/10～14、RS-02。

### 3. 让 W4/W5 保持专项变更，伞变更只管理先后和阶段出口

W4 继续拥有 V-08 文件安全替换、保存状态/自动保存、外改冲突/重载、10 秒恢复和 M2 最小资源闭环；W5 继续拥有平台输入、IME/候选/焦点和真实中文输入法证据。伞变更不复制对应需求细节或任务，而把它们作为依赖节点纳入阶段追踪：V-08 方案门槛完成 → W4/W5 设计复核与接线 → 单文档操作链集成和 M2 出口检查。若分支任务间出现范围或行为冲突，先更改 OpenSpec 工件并依现行规范裁决，不私自扩大行为。

### 4. 先纯逻辑再原生消费，兼容既有只读生命周期

首个实现切片复用现有 DocCore/Buffer/Markdown/Edit 状态协议，先补可编辑行为的无头状态与拒绝矩阵，再将 M1 `ReadonlySession` 消费替换/扩展为可编辑单文档生命周期。每一步保持打开/替换/失败保留旧文档/关闭及过期结果拒绝语义；不在 renderer、高频命中或按键路径全文解析、文件 I/O 或全文哈希。存储保真仍由 `aline-source` 已确认契约和 W4 实际保存消费执行，不从 AST 序列化 Markdown。

**2026-11-20 切模式输入恢复（3.1 局部修复）：** 真实窗口发现模式按钮借焦后未归还正文，Source 输入须重新点击才能接收；目标行进入编辑态又跳过定位测量，导致恢复一直待定。沿用具体函数修复：成功切模式才归还正文焦点，组合 Deferred/失败保持原上下文；编辑行同阅读行走现有高度测量与源码锚点恢复，复用同次渲染的输入投影、文本布局与实际边界；过期身份或无法映射的输入几何不能回退到块首。可编辑文档明确切模式时，以当前源码选区 head 作为恢复目标，避免旧视口锚点覆盖光标；普通重排继续沿用视口锚点协议。切回 Visual 复用 `open_visual_at` 的受检开块入口，开块不改字节、版本或历史，保护区仍只定位。解析尚未就绪时，窗口仅保留一次 `VisualInputRestore` 的 DocumentId、WorkingVersion、解析配置代次和方向性源码选区，沿既有解析刷新结果尝试恢复；新输入、选区、模式、文档/配置变化使请求失效，关闭释放。它不持文本、第二份历史或新解析任务。代价是保留一个有界恢复请求；验证包括迟到/外会话/选区与版本改变拒绝、保护区不开块、输入行定位完成，以及真实 `A → Source直接B → Visual直接C` 三段输入与三步共享历史。真实结果和未测边界回填验证计划，不以此替代 W5 完整 IME 矩阵。

### 5. 首次开放编辑时验证代码块横向滚动

决定 §43 把真实代码块横向滚动列为 M2 入口待办。首次开放编辑或指针驻留代码块时，按 V-07 对照真实行为与原生滚动入口；若发现缺陷则本 change 内修复，并保留可复查的中文 UI 操作证据。代码路径/布局检查不能替代该证据。

### 6. 待定输入与独立命令用 Buffer 两步候选提交

- **问题：** `StringBuffer::apply` 每次立即发布一个批次。DocCore 在有普通待定输入组时，若直接返回 `PendingInput`，无法完成 PRD EDIT-06/07 要求的剪切、粘贴等独立命令；若先提交输入再执行命令，后续命令拒绝会留下已提交输入；若把两者合成一个批次，则输入和命令只能撤销一步。Undo 补偿也无法恢复已推进的 revision、被截断的 redo 分支、历史裁剪结果或调用前草稿。
- **状态所有者与接口边界：** `aline-buffer::StringBuffer` 增加一个专用、同步、独占借用的两步候选提交入口，不增加可脱离 Buffer 生命周期的通用事务对象。入口接收已绑定当前快照的待定输入批次及其方向性前/后选区；随后通过一次性只读候选回调提供“待定输入已应用”的候选快照与选区。回调只能按该快照重规划第二个受检命令批次，并返回变更、无变化或拒绝；不得持有/修改真实 Buffer，也不得产生剪贴板、文件等外部副作用。IME 组合活动时不调用该入口，仍由 W5 的等待/拒绝协议负责。
- **候选与历史：** Buffer 在候选状态中先建立已封口、不可与旧 pending 输入节点合并的输入历史步，再基于其后快照建立独立命令历史步；第一步的 before-selection 取 `TypingGroup.before_selection`，第一步 after-selection 取命令发起时实际方向性选区，第二步 before-selection 取第一步 after-selection，第二步 after-selection 取命令计划结果。成功后一次替换真实文本、选区、revision、行索引和历史状态；Undo 第一次只撤命令并恢复命令前选区，第二次撤输入组并恢复组前选区，Redo 逐步重放。不得因编辑器当前活动选区与输入组基线不同而伪造第一步选区。历史裁剪沿用既有保存点保护规则，只允许裁掉不受保护的旧节点；本事务产生的两个节点都必须保留，预算容不下两步或保存点阻断裁剪时整笔拒绝。
- **拒绝与无变化：** DocCore 在构造候选前复验实际 DocumentId/WorkingVersion、工作快照和当前方向性逻辑选区；Buffer 候选发布前再次确认绑定的实际 revision/快照。两批补丁及其 UTF-8 范围、期望片段、候选版本/选区、行索引、revision、历史裁剪/预算、宿主工作版本和块状态更新以及所需受检分配都必须在发布真实 Buffer 前完成。候选回调拒绝、取消、空选区上的 Cut、第二批无变化、任一预算/身份/保护校验失败或可报告的预留失败，都丢弃整个候选，并保留调用前真实文本、待定草稿、工作版本、选区、redo 分支、保存点和历史；折叠选区上的有效粘贴仍按两步事务执行。Cut 仅在整个文档变更成功后才写入调用时冻结的选中文本。已由 Typing 草稿创建规则丢弃的更早 redo 不复活；所谓“保留调用前状态”指保留命令调用瞬间实际存在的状态。不得先发布再用 Undo 补偿。
- **最简单方案与代价：** 只为当前确认的“待定普通输入组 + 一个独立命令”路径增加此入口；候选中复用 Buffer 的批次、行索引与历史构造/裁剪规则，历史节点描述按预算受检复制并共享既有 `Arc<HistoryStep>` 补丁数据。候选构造可能带来显式命令路径上的临时文本/索引/历史描述开销，必须纳入注入预算和性能复核；不引入第二份持久化全文/历史、泛化事务框架或撤销补偿机制。剪切只在文档提交成功后才写系统剪贴板；文档与系统剪贴板不是一个物理原子事务。
- **验证：** 以反向选区和 redo 分支 fixture 核对连续两次 Undo/Redo 的文本、选区、revision 与历史裁剪；折叠选区粘贴后连续两步撤销分别恢复命令前和输入组前状态。用只有一个可用节点的预算和保存点阻断裁剪的状态验证两步不可被压成一步或越过保存点。对第二批保护拒绝、旧身份、非法 UTF-8 端点、文本/索引/历史预算失败、取消、空选区上的 Cut 和无变化逐项比较调用前 Buffer 与 DocCore 全状态；只有 Changed Cut 才允许按冻结文本更新剪贴板，其它结果无剪贴板副作用。独立审查覆盖 API 范围、唯一 Buffer 所有权、历史保存点/redo 裁剪和拒绝零副作用。

## Risks / Trade-offs

- [V-08 身份/事务方案审查暴露已确认规范之间的缺口] → 在依赖接线之前停止相关实现，更新提案和专项规范并取得具体裁决；不以“沿用现状”视为默认批准。
- [从只读会话切换为可编辑会话导致打开、替换或关闭语义回归] → 保留单文档原子发布与旧请求失效契约；分层测试打开、失败替换、编辑期间替换和关闭交错。
- [跨模式/IME/查找与保存并发导致旧范围写入] → 计划、投影、目标文档绑定实际版本；变更后重算或拒绝，保持输入和历史原状。
- [M2 范围被 M3/M4/M5 功能膨胀] → 每个能力追踪 PRD 阶段归属；范围外能力单独变更，不以“可编辑”名义越界。
- [两步候选增加显式命令路径的临时分配和状态复制] → 入口限于单个待定组加一个命令；复用历史补丁 `Arc`，按注入预算预留并在真实状态发布前完成全部失败点；不能把进程级 allocator abort 宣称为可恢复错误。
- [macOS arm64 证据被误读为完整阶段通过] → M2 出口按 V 项和平台列实测/未测，保留三平台发布要求与决定 §43 的范围限定。

2. 先完成纯引擎/文档协议及拒绝测试，再逐步接入双模式基础输入、映射、历史和查找替换。
3. 通过前置门槛后按 W4/W5 各自任务接入保存/恢复与原生输入；逐步集成单文档操作链。

## 高频输入采用后台只读准备与主线程复验发布

- **问题：** 原生 Backspace/Delete、普通输入组封口及 IME 确认可在输入回调内解析真实 Buffer，再解析候选文本并重建行索引；提交后才启动的后台阅读刷新无法避免回调阻塞。仅复用旧 `Parsed`、只改无待定组删除或跳过候选复读会破坏 MD-11/版本保护。
- **所有权与身份：** `DocCore` 仍唯一持有 Buffer、输入草稿/组合、选区、输入组、模式和历史。输入回调只将受检普通输入或平台候选放入 DocCore 草稿，不写第二份 UI 文本；UI 把不可变的真实 Buffer 快照、当前 `InputIdentity`、源范围/方向性选区、模式/块站点、组代次和请求代次交给后台纯准备。后台不得持有或复制可变 `DocCore`/`StringBuffer`，不得做 I/O，也不得发布状态。候选凭据必须绑定产生该候选的实际快照身份；不得用同文本新建快照冒充 Buffer 候选身份。
- **后台准备：** 将现有完整基线解析、命令计划、MD-11/UTF-8/预算检查、候选复读解析以及 Buffer 候选文本/行索引准备移出按键、命中和渲染路径。待定普通输入加一个独立命令继续沿已确认的固定两步历史语义；第二步必须基于第一步实际生成的候选快照规划。只允许实际需要的单批或固定两步候选，不提供通用事务 API。
- **发布：** 后台结果回到 UI 后，`DocCore` 在唯一所有者线程复验会话/文档存活、DocumentId、真实 WorkingVersion 与 SnapshotId、解析配置/请求代次、方向性选区、模式/块站点、输入组代次以及组合/等待状态。Buffer 在发布前基于当前真实历史复验历史预算/裁剪，并原子安装已准备的文本、行索引、revision、选区和历史；任何未准备的可失败工作不得留在发布段。过期、拒绝、取消或预算失败只丢弃候选，保留已登记的输入草稿/组合与调用前已提交文本和历史，不用 Undo 补偿，不伪报 Buffer 已提交。
- **准备期间继续输入：** 回调到达顺序由 DocCore 的单一草稿/组合状态持有；输入继续进入该所有者并推进 WorkingVersion/请求代次，使旧准备结果失效。普通输入按既定 900ms 分组和源范围顺序续写；不按旧 UTF-16/投影坐标重放。最新草稿重新提交准备时重新冻结站点和快照。错误/取消不得清空待改草稿。ED-01 等待仍保留原组合/上下文，并只在 W5 平台自然确认/取消结算后读取当前快照。
- **边界与代价：** 局部草稿内可由既有有界映射和类型检查完成的轻操作保持局部同步；解析、候选全文物化、候选复读与行索引构建均不得回退到高频回调。显式格式/剪贴板等低频命令仍遵守相同候选凭据与零副作用规则。首次实现保留现有全部检查与解析轮次，只改变调度；延后合并重复解析，避免把性能优化与正确性变更混在一起。后台候选会暂留受预算限制的只读文本/索引，生命周期仅到发布、取消或失效。
- **验证与阶段门槛：** 无头测试按可控完成顺序覆盖连续删除、待定组+删除两步撤销、900/901ms 分组、方向选区、MD-11 拒绝、预算/历史失败、重复/过期结果、模式/站点变化、关闭及取消零副作用。真实平台回调在准备期间的查询、标记/选区可见性、确认后继续组合及队列背压仍按 W5 取证；在证据取得前不开放被 V-08/W5 门槛禁止的生产 IME/保存接线，不宣称 V-05 热路径通过。

## 平台坐标输入意图冻结接收时来源（2026-11-20 批次，2026-11-21 评审修复）

- **问题：** 显式命令推进工作版本后，排队/在途的平台回调（Select/Mark/带范围 Replace、组合期无范围 Replace）若按重建后的新投影解释旧 UTF-16 坐标，会写到错误位置；而一律静默拒收所有 `StaleResult` 又会吞掉核心受检入口本应反馈的编辑拒绝。
- **方案：** `ScheduledInput::capture` 在接收时冻结 `PlatformInputOrigin`（不可变 InputView＋原方向选区；绝对 Select 不依赖原选区）。入口三分类、捕获与排水复验共用 `InputIntent::carries_platform_coordinates(composing)` 单一谓词：非组合无范围 Replace 只表达当前选区键入，入口与排水同口径按语义重绑；组合期无范围 Replace 目标是组合范围，按平台坐标拒收。`checked_view` 失败返回来源专用 `InputStep::StalePlatformOrigin`（静默拒收该条、保留后续语义输入），核心受检拒绝（含 StaleResult）仍走 `edit_error_key` 反馈。自身封口成功后 `after_own_seal` 仅在源码站点/模式/方向选区一致时续用触发回调来源，不给其它排队回调更新资格。
- **失败恢复纯判定：** `InputScheduler::plan_failure_recovery` 每次只判定一条失败的活动输入。平台来源失效时仅返回 `DropStaleOrigin`，等待队列原样交给窗口现有排水入口。该入口用当前输入帧逐条复验，无效平台坐标拒收，语义输入按入队顺序执行。仍适用语义输入的后台失败处理「重试一次→封口同步退化/直接清空」。单条动作可无头断言，无需分配动作列表或在判定阶段提前取走下一条输入。
- **验证：** 无头覆盖 stale 触发丢弃＋语义队列保留、Retry/SyncFallback/Clear 既有语义、封口续用失败（选区/站点变化、缺帧）、来源拒收与核心拒绝分离、双 composing 维度入口矩阵。窗口薄壳 feedback 赋值行由真实窗口取证覆盖（W5 4.1 / M2 3.2），不以无头模拟替代。

## 关闭与替换前的正文输入结算

无草稿的删除在后台发布前不会改变文档脏状态。窗口在关闭或采纳替换候选时读取输入调度器的在途与等待状态，与现有文档关闭资格共同门控。输入未结算时保留文档和输入任务，提示用户稍后重试。候选读盘期间仍可继续编辑，因此替换资格须在采纳时复验。此处只传递当前判定，不在文档会话另存调度状态。验证延迟发布的删除在拒绝关闭和替换后仍能进入原文档，并参与既有脏状态门控。

## 首次保存/另存为受检迁移与侧目标事实（2026-11-20 批次，2026-11-21 评审修复）

- **问题：** 引用重写若在写盘前提交进文档，写盘失败/取消会留下已改写引用与未就位资产的不一致；已发布但关联被拒的侧目标若不登记，重试可能盲目覆盖外改。
- **方案：** `prepare_migration_change` 只读预演引用补丁候选（不落地版本/历史），`publish_migration_change` 在写盘回执后全量身份复验才提交；候选只能被已发布回执消费（`WriteCompletion::is_published()`），冲突/失败/取消保留候选供同一目标重试。`reconcile_association` 对代次耗尽/候选拒绝走 deferred 分支登记 `partial_association`＋`PublishedUncertain`，并对任何「已发布但未采纳」的当前关联回执兜底登记；重试经 `association_expected` 逐字节复验侧目标后才允许覆盖。资源覆盖按当前文本＋逐步骤历史状态（含 redo 分支与待定 typing_redo）判定，`AssetProof` 以身份＋冻结字节三明治复验（残余同 inode 改回窗口方向安全，注释明示，不作强一致保证）。
- **边界：** 当前生产提交路径每历史节点单步（record 新节点即封口旧节点、staged 两节点各一步），多步骤节点仅 buffer 直连 API 可达；逐步骤 visit 为防御性正确接线，其重放正确性由 buffer `history_node_steps` 契约测试保证。覆盖按归一化引用字符串比较，同文件不同写法触发保守重试。结算路径的资产复验＋历史重放属组提交调度而非 render 高频路径，V-05 预算证据归 M6。
- **验证：** 无头覆盖未发布保留候选＋重试写重写引用、侧目标登记＋重试携带基线、当前/已提交/待定 redo 三态资源覆盖、同尺寸不同内容＋新身份替换拒绝、写盘后编辑 deferred＋外改重试冲突。平台自然取消组合后继续保存意图与 engine-design §ED-01 一致（`AssociationCommand::Cancelled` 替代路径已删除）。
