# Design

## Context

动机见 proposal。DocCore 已维护普通输入、唯一组合槽、发布等待及身份；原生窗口仍只读，未接平台文本输入 handler。无头组合成功不代表系统候选窗和焦点成功。依据 PRD §5.3、引擎 §7/8/10/17、UI §6/13、架构 §5/13、R-4/8、CODE_STANDARDS §2～6；W5 研究步骤只作线索。

M1 出口已于 2026-11-13 按[决定 §43](../../../docs/decisions.md#43-2026-11-13-m1-阶段出口裁决macos-arm64-范围)在 macOS arm64 范围收口；M2 可编辑块与输入投影仍是接线前置；W4 真实保存消费者是发布交错平台验收前置。当前允许准备锁定 API 证据、独立坐标/事件样本，不在 M1 提前开放输入。

## Goals / Non-Goals

**Goals:** 唯一 DocCore 组合所有者，版本化输入投影，真实平台 callback 明确结算；候选窗、marked 和焦点有可复核生命周期。

**Non-Goals:** 不增加新输入模型/历史，不实现跨块组合或 M3 命令全集，不改变 ED-01，不把离屏或合成输入列为真实 IME 通过。

## Decisions

### 1. 具体适配和状态边界

DocCore 唯一拥有草稿/组合/输入组，平台适配持当前投影身份及弱宿主目标，转发平台 UTF-16 查询/替换/marked 事件。渲染只消费派生组合视图，不拥有第二份可提交候选。M2 打开块和 Source 输入共用受检提交及历史。采用具体 adapter 与明确 enum 状态；锁定 GPUI trait 实现只在 UI，不能把平台 trait 引入引擎。新增模块按输入生命周期/坐标几何职责分离，不按行数机械拆分；没有真实消费者不扩大公开 API。

### 2. 三坐标和投影身份

平台端点使用 UTF-16 受检封装，glyph/layout 索引视为该布局中的 UTF-8 字节，普通移动删除以字素；都必须声明 document/working/projection/block/config 身份并经统一映射，不手算块首/行首。半代理对、半 UTF-8、旧投影和无法对应范围拒绝且保留原状态。跨块选区按既有可编辑投影能力向平台报告，不能虚构一个可跨块写入的 marked 范围；若锁定平台无法表达，先拒绝并保留，不擅自裁剪输入或新增产品语义。

### 3. 生命周期协调

普通输入和 IME 分别复用 DocCore 既定协议。候选更新推进草稿代次，确认独立一次历史，取消恢复前态且旧投影不复活。菜单暂借焦点保留上下文；实际失焦、切块、模式/窗口转换须先协调平台自然结果，再清理失效 marked 并执行目标操作。不能将研究中的“一律 unmark”理解为强制确认/取消；Blur/Escape/计时器不能决定组合结果。未得平台自然结果时保留上下文并等待或拒绝目标动作，反馈可取消的发布请求但不取消输入。

回调复验目标存活和完整输入身份；关闭作废采纳资格并释放 handler/订阅，晚到事件不重开目标。Undo/Redo/写入口也遵守组合门控，不在平台与 DocCore 各自提交一次。发布请求使用既有 wait handle；W4 负责写盘，W5 只提供自然结束后当前快照资格。

普通输入/删除/IME 确认如需解析候选，按 `../m2-editable-core/design.md` 决定 7 执行：平台 callback 只更新唯一 DocCore 草稿/组合，不在 callback 内解析全文或写 Buffer；后台候选绑定实际输入 identity、源站点、选区、组合/输入组及请求代次；主线程复验后发布。准备期间新回调按既定事件次序更新同一 DocCore 状态并使旧候选失效，不把旧 UTF-16 范围排队后应用到新投影。ED-01 等待保留原组合与平台上下文。具体平台在准备期间对 marked/query 的可观察值、确认后立刻开始下一轮组合、重复/迟到回调和背压行为必须通过锁定 GPUI 源码与真实 macOS 探针验证；未测时拒绝依赖该行为的原生接线，不通过 unmark 或合成确认规避。

### 4. 候选窗几何与揭示

几何来自当前 prepaint 文本布局、元素 frame、滚动及窗口坐标；输入投影与布局必须对应同一身份。折行/滚动/缩放/字体代次变化失效旧几何，再计算候选插入点矩形。跨屏按平台窗口坐标契约，不把屏幕坐标直接传给 handler。组合揭示沿用统一 Reveal，避免直接修改虚拟列表偏移形成竞争所有者。具体锁定 GPUI callback 名称和坐标单位在接线 spike 中留 verbatim 源码锚点，不能按较新 GPUI API 猜测。

## Risks / Trade-offs

- 原生 IME 回调顺序与焦点行为未知 → macOS 中文输入法逐项观察/事件记录，记录身份和错误、不记录正文/候选敏感内容；模拟测试只证协议。
- 旧布局候选窗错位 → identity 检查与几何失效，虚拟列表边缘、折行、DPI、多屏实测；缺平台则保留未测。
- unmark 语义可能触发平台提交 → 先以锁定源码和真实事件取证，保持自然结束/原上下文契约；若能力确实不足，列具体最小冲突，不能用假确认绕过。
- 输入路径热计算 → 不在按键/render 全文解析或 I/O；复用局部输入投影，性能按 V-05 量测。

## Migration Plan

先加受检投影与无头事件金样，锁定平台能力 spike，再在 M1 出口后接 M2 输入；仅适用入口启用，所有写入口持续受 MD-11 保护。任何替代路径/旧 handler/无消费者 fake/导出应清理并查引用。回撤 handler 前先结算自然组合结果并保存当前上下文，不能通过销毁 UI 丢候选。W4 未接通时仅完成等待协议测试，真实保存交错保持未完成。

## M2 V-08 身份/事务与输入发布边界

持久化请求身份、不可丢弃写盘回执、路径/资源代次和关闭结算以 `../m2-editable-core/design.md` 决定 1 的共同方案为准。W5 的输入候选/组合事件另以 DocCore 的投影身份和自然结束协议校验，不能把 `InputIdentity` 当作文件保存事务身份。ED-01 显式保存等待在平台自然确认/取消后才生成当前快照；等待取消不改变输入，窗口/文档关闭和旧回调不能丢弃已发生的写盘事实。共同方案仍须完成伞变更 task 1.2 独立审查后，才允许本 change 的真实 IME/发布接线。

## 真实平台组合结束时序（2026-11-19 实测）

- 源码锚点：`gpui-pre-macos-0.3.9/src/window.rs:2883-2888`。每个
  `PlatformInput::MouseDown` 在进入 GPUI 分发之前先交给
  `inputContext handleEvent:`；因此真实鼠标按下的组合结束由平台/输入法决定，
  不由应用回调决定。
- 实测结果：组合期真实鼠标按下时，微信输入法把 marked 预编辑**原样自然提交**
  为文本（例如拼音 `ni` 提交为 442 字节，而不是候选汉字）；GPUI
  `prevent_default` 只能拦截内部分发与自动焦点转移，不能阻止这次平台提交。
- 本 change 的门控语义据此固定为：
  - 未产生平台自然结果的动作（菜单、模式切换、Undo/Redo 等）在组合期间
    **拒绝且零副作用**，保留组合、草稿、源码、选区与历史，并给出可取消的
    反馈；不得用 Blur/Escape/计时器伪造结束。
  - 真实鼠标按下先接受平台自然提交，再执行目标动作；提交后块若仍打开，
    后续键入只能形成**新一轮组合**，不得复用或丢弃已提交草稿，也不得重复提交。
- 实现对应：模式按钮在组合活动时于捕获阶段 `prevent_default`，阻止 GPUI 的
  自动焦点转移（否则输入框失焦会连带丢弃 marked 草稿）；组合反馈行的容器
  同样阻止默认焦点转移；点击仍冒泡为 `document.composition_pending` 反馈。
- 证据：`logs/validation/m2-editable-core/2026-11-19-native-run/m2-17`（修复前，
  无 `ni` 提交、只提交「好」）、`m2-18`～`m2-20`（修复后均先提交 `ni` 一次）；
  最终干净运行为 `m2-20`，逐项时序见该目录 `run-notes.md`。
- 边界：仅 macOS 27.2 arm64 / 微信输入法拼音 / Orca 投递实测；其他输入法与
  候选窗折行/DPI/多屏未测；候选窗位置见 2026-11-20「候选改选与候选窗几何」
  实测。窗口失活已由下节 2026-11-20 实测覆盖；选区上开始组合见
  2026-11-20「选中文字上开始组合」实测；组合跨虚拟滚动见 2026-11-20「组合
  跨虚拟滚动」实测；组合期「文件」菜单借焦点与 Escape 取消见
  `logs/validation/m2-editable-core/2026-11-20-composition-wait/run-4`。

## 窗口失活时的平台自然结果（2026-11-20 实测）

- 实测：真实中文组合（微信输入法拼音 `ni`）进行中，经 System Events 让 Finder
  成为前台，平台把 marked 预编辑**原样自然提交**为字面文本 `ni`
  （100→102 字节、撤销深度 0→1）；应用未自行取消组合，也未在重新激活后重放。
- 重新激活本实例后原块仍打开、插入点保留在提交之后；继续键入 h/a/o 只形成
  新一轮组合，空格确认提交「好」一次（102→105、撤销深度 1→2）；应用侧采样
  无文本长度回落，最终源字节为基线的单点连续插入 `ni好`。
- 门控语义与鼠标按下路径一致：失活期间等待平台自然结果，不伪造结束；重新
  激活后沿用原块上下文，不回放已提交内容。失活提交会使文档变脏并触发 1 秒
  自动保存，后续显式保存与关闭结算按 W4 规则处理。
- 证据：`logs/validation/m2-editable-core/2026-11-20-deactivation/run-2`（驱动
  `scripts/drive_m2_deactivation.py`）；`run-1` 为失活期间读取窗口导致 Orca
  稍后抢回前台、重新激活误判的失败轮。
- 边界：仅 macOS 27.2 arm64 / 微信输入法拼音；候选窗展开时失活与菜单借焦后
  失活见下节 2026-11-20 实测；多屏候选窗、候选窗折行/DPI 仍未测；组合跨虚拟
  滚动见 2026-11-20「组合跨虚拟滚动」实测；组合期 Redo 见后续节。

## 候选窗展开与菜单借焦后的失活（2026-11-20 实测）

- 方法：同一 106 字节合成夹具、微信输入法拼音，按两段执行。每段用系统 HID
  事件流投递 `n`/`i`（注入前核对前台 unix id 为被测 pid），经 CGWindowList
  只记录候选窗 owner/layer/bounds/alpha/onscreen，不读取窗口名称或候选正文；
  失活/激活经 System Events 真实切换 Finder/本实例；菜单展开时不做区域截屏。
- 场景 A（候选窗展开时失活）：组合 `ni` 时候选窗 owner「微信输入法」、layer
  2147483629、bounds `(450,307,510,32)`、onscreen=true；Finder 成为前台
  （前台 unix id 679）后同一窗口列表无已上屏输入法窗口。平台把 marked `ni`
  原样自然提交一次（106→108、插入点 14、撤销深度 0→1），应用未自行结束或
  重放。重新激活（前台回被测 pid）后原块仍打开，继续 `hao` 组合并由空格
  提交单个候选字一次（108→111、撤销深度 1→2）。
- 场景 B（菜单借焦后失活）：第二段组合 `ni` 时候选窗 bounds `(485,307,510,32)`；
  经 System Events 真实点开「文件」菜单（退出码 0），菜单展开时窗口列表出现
  应用自己的 layer 101 窗口 `(14,-41,373,398)`、onscreen=true，同时候选窗已
  不在上屏列表（两轮均如此；菜单展开期间采样无文本变化，组合仍保留）。在
  菜单仍展开时让 Finder 成为前台，窗口列表无已上屏输入法窗口；平台把 marked
  `ni` 原样自然提交一次（111→113、插入点 19、撤销深度 2→3）。重新激活后继续
  `hao` 组合并空格提交单个候选字一次（113→116、撤销深度 3→4）。
- 结果：四次插入在采样中首尾相接（位置 14→16→19→21），文本长度无回落；
  两次继续组合实际提交「号」（`e58fb7`），与 run-1 相同；最终源字节为 116
  字节、基线在 14 的连续插入 `ni号ni号`（`6e69e58fb76e69e58fb7`）。自动保存
  与显式 `cmd+s` 后，关闭采样 `source-after.bin`/`stored-after.bin`/
  `disk-after.bin` 与磁盘目标同 sha256（`814c4799…d71786`）、
  `disk_equals_source=true`/`disk_equals_stored=true`；恢复存储无 Active 完整
  代，进程 exit 0。
- 证据：`logs/validation/m2-editable-core/2026-11-20-candidate-menu-deactivation/run-2`
  （驱动 `scripts/drive_m2_candidate_menu_deactivation.py`）。失败轮 `run-1`
  保留：四段提交与几何事实相同，但驱动把继续组合首候选写死为「好」、实际
  提交「号」，按失败保留；本驱动只要求单个非 ASCII 可打印候选字。run-1 还
  观察到第二次组合初次候选窗位于 `(0,942)`，随后继续组合回到 `(504,307)`；
  候选窗位置稳定性不作本记录结论。
- 边界：仅 macOS 27.2 arm64 / 微信输入法拼音 / 当前显示缩放与单屏；候选窗
  折行、DPI、多屏与滚动中的候选窗位置仍未测（归 3.3）；菜单展开后候选窗
  退场只记录本机观察，不推广为平台契约；其他输入法与 Windows/Linux/Intel
  未测。

## 组合期 Redo 拒绝（2026-11-20 实测）

## 组合跨虚拟滚动（2026-11-20 实测）

- 虚拟化事实分两步取证：组合期 `cmd-alt-l` 被输入上下文吞掉、不产生布局报告，
  故先在无组合时用同一像素滚轮序列取得 debug 布局报告。18,875 字节、400 节、
  1604 个阅读行的长夹具首屏为 `rows=1604`、`rendered=13`、`top_row=0`；3 次
  真实像素滚轮向下（每次 -900）后为 `top_row=56`、`rendered=15`，原首行已
  移出虚拟渲染集合；按报告补滚 1 轮（3 次 +900）后回到 `top_row=0`、
  `rendered=13`。
- 在标题行偏移 11 开始组合 `ni`（采样 seq 2–3：`composition_start=11`、
  `composition_end=11`、草稿 1→2 字节），组合期间文本保持 18,875 字节、
  版本 0、撤销/redo 0、块打开。组合中执行同一 3 次向下滚轮，截图 step-036
  显示 Section 0043–0046，原行已不在渲染范围；向上补滚 12 次后 step-049
  显示首行重新挂载且 marked `ni` 保持，平台未提交或丢弃组合。
- 空格确认只提交一次「你」：18,875→18,878 字节、版本 1、撤销深度 1、

## 候选改选与候选窗几何（2026-11-20 实测）

- 前置失败：窗口失活时按 pid 定向投递的方向键/数字键两轮（run-1/run-2）与
  确认前台后的 HID 数字键一轮（run-3）都没有改选候选；run-3 中数字键 `2` 把
  marked 原文 `ni` 提交（`6e69`、102 字节），失败保留。
- 成功路径：确认被测实例在前台（组合前后前台 unix id 均为被测 pid）后，用
  系统 HID 事件流投递 `n`/`i` 开始真实拼音组合，再用下方向键移动候选选中项、
  空格确认。对照提交首候选「你」一次（seq 4、位置 11、`e4bda0`、版本 1、
  撤销深度 1）；`cmd+z` 撤销回基线并留下 redo 分支（seq 6、版本 2、撤销 0、
  redo 1）；重新组合时文本保持 100 字节、版本 2、redo 分支保留（seq 10–11、
  草稿 1→2 字节）；下移后空格提交「尼」一次（seq 12、位置 11、`e5b0bc`、
  版本 3、撤销深度 1、redo 0）。两次均为同一位置的单点连续插入且字符不同，
