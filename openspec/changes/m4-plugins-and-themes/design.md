# Design

## Context

`aline-plugin/src/lib.rs` 为编译边界占位，`aline-app-core` 已有双语 catalog。UI 已有 `fonts` 的有效字体代次、`document/resources` 临时资源及迁移，`aline-edit` 有版本检查及 IME 后快照入口。M3 核心表格命令继续作为表格编辑责任方。详见 proposal.md。

## Goals / Non-Goals

- 复用既有快照、命令、资源和文件事务，明确进程设置、文档与派生任务的所有权。
- V1 保持静态内置提供者，M4 单窗口承载图片预览，M5 接入完整标签、文件树和多窗口生命周期。

## Decisions

1. **注册和派发。** `aline-plugin` 按稳定身份与能力登记提供者，校验重复身份、独占能力冲突和无效声明。多实现通过共同输入、结果和错误契约派发，优先使用具体类型，只有多实现确有替换需求时才引入 trait。公共注册可装载测试提供者；各内置选项以有类型的模型保存，无需动态加载 ABI。解析扩展按插件规范 §4.3 冻结快照能力边界，核心 Markdown 解析仍使用现有 parser。
2. **任务与事务。** `aline-ui` 调度防抖、剪贴板及原生文件交互，并在结果采纳处比对文档、版本、任务身份、插件代次和适用主题/资源代次。导出复用 ED-01 等待，冻结快照后由插件生成，UI 负责取消、覆盖确认、临时产物和最终提交。Mermaid 独立图像任务拥有独立门控，复用生成服务。文件与图片迁移复用现有失败补偿和引用保活。拒绝、失败、取消、过期有明确区分。
3. **纯配置与原生发布。** `aline-app-core` 拥有设置、包清单、样式校验、合并和有效值解析；应用宿主拥有有效设置实例和持久化，UI 执行包安装、字体注册、平台外观读取及广播。校验在发布前完成，字体有效后才推进字体代次；实际影响布局的变化重排并以源码锚点定位。W6 语义 token 接续现有消费点，通过固定角色发布，避免每个控件复制求值规则。
4. **生命周期和依赖。** UI 负责图片路径/视口和降级汇总，Markdown 文档继续由既有会话和补丁接口拥有。插件向下依赖现有编辑/解析及纯配置能力，产生资产和意图，核心不回调 UI；UI/应用在窗口层结算副作用。优先按配置、提供者、事务、视图与字体生命周期组织模块。独立审查公共边界、异步采纳、主题安装及输出提交。
5. **前置裁决。** V-02 冻结页面、样式、离线资源及后端；V-03 冻结真实解码、动画、SVG、公式/Mermaid、复制、协议与设置边界；V-04/V-06 先测 schema 数值、包体解压、字体及资源预算。需要新增依赖或 vendor 的路径按架构 §3.2 与引擎 §18.2 审计后单独裁决。相关失败样本可先在隔离环境取证。
6. **阶段推进与核心控件。** 代码块语言/复制控件属核心编辑能力（PLUGIN-05），由 `aline-ui` 在两种视图共用的代码块呈现层提供，高亮插件只贡献语言识别与着色，关闭时控件、行号与编辑保留。`ui/main-window-layout` 以 MODIFIED delta 把设置页、导出/主题入口与状态栏外观模式推进到 M4，标签栏、侧栏与文件树仍归 M5。M3 已登记的列表开块重复呈现按 V-09/EDIT-02 在 M4 修复，因其与 M4 行渲染改动重叠；修复不改变既有归档文本，只回填引用。

## Risks / Trade-offs

- 后端覆盖面和原生字体能力待实测 → 用真实文件、恶意或失效样本以及锁定 GPUI 的运行时矩阵验证。发现冲突记录证据，暂停依赖该决定的实现。
- 文档、配置或插件状态在任务执行中变化 → 复用身份校验，增加各任务确实依赖的代次，在所属边界结算。
- 主题/资源安装中途失败 → 先准备并校验，按既有事务生命周期发布；使用故障注入核对磁盘快照和用户状态。

## Migration Plan

既有 Markdown 与磁盘主题用户副本原样保留。首次启动补齐缺失内置主题，非法或旧原型包按正式规范拒绝；配置旧值按有效设置规则读取，无效值采用既定回退。多平台原生能力分别记录，不从当前 macOS 结果外推。
