# Design

## Context

见 proposal 的动机。`shell.rs` 已定义大部分 M1 色值；`readonly_reader.rs` 还有链接/滚动条字面量，窗口按钮含透明边框。UI §3.2 已要求 token 化且不改变视觉；完整主题仍归 M4 与 theme-package-spec §5/7。

## Goals / Non-Goals

**Goals:** 把当前具体色值集中，组件以用途命名；通过独立数值预期检查 RGB/RGBA 包装保持一致，禁止生产组件新增散落字面色。

**Non-Goals:** 不新增主题服务、trait、公开 API、配置代次或依赖；不改变排版、颜色、窗口状态、源码/映射/历史、主题包 schema。M1 的候选色仍是候选。

## Decisions

1. 新建私有 `native_window/tokens.rs`：内部 `palette` 保存有来源注释的精确原始色阶；外层语义常量是组件唯一消费面。具体常量足够解决当前耦合，不引入可变调色板/抽象框架。shell 只保留元素装配职责；阅读器/窗口与 shell 分别依赖 tokens。所有者是 UI 模块，无运行期状态或副作用，也无取消/旧结果问题。
2. 保留现有 `u32` 和调用点 `rgb`/`rgba`，避免隐式颜色转换变化。代码表面、目录、notice、scrollbar rail 可引用同一原始色；用途名分别保留，后续 M4 才决定正式字段。透明色显式命名为 `TRANSPARENT_BORDER`；其 RGB/RGBA 语义不混用。
3. Python 专属守卫只检查 `crates/aline-ui/src` 的 Rust 生产源码。用词法遮罩排除注释/字符串与 `#[cfg(test)]` 模块，检查十六进制颜色数值和直接数字颜色构造。token 模块是唯一允许生产字面色的位置；测试可保留独立预期。用正例和最小违反样本验证检查器；不是 Rust 类型检查器，变量计算或外部常量须由评审补充。
4. 验证值相同不等于真实渲染相同。保留重构前后 macOS 中文窗口截图比较，记录同夹具、窗口/缩放/模式与 binary 身份；若真实截图未取得，任务保持未完成。既有 M1 单窗探针与采样不受本重构影响。

## Risks / Trade-offs

- [ARGB/RGBA 混用] → 原样保留转换调用，测试完整原始值；透明与弱强调单独使用 RGBA。
- [守卫只做源码扫描] → 明确覆盖范围，正反例覆盖注释/测试边界；编译与评审补充。
- [真实平台不可用] → 不用数值测试代替截图，不关闭视觉验收；Windows/Linux 未测。
- [后续主题扩展] → 现为私有具体常量，M4 可在唯一配置服务边界替换；没有新的持久化格式或兼容迁移。

## Migration Plan

先固定当前数值预期，再提取常量/替引用、清旧常量，执行守卫和 Rust 检查；真实窗口截图完成后回填 V-09 的 token 化分项。失败在本地修复；不修改引擎或正式主题模型，不提交/推送/归档。
