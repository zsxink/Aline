# Proposal

## Why

Aline 已有八成员 workspace、无头引擎和 `aline-ui/document`，但 `app/src/main.rs` 仍是查询应用名后退出的 M0 薄入口，没有原生窗口。按 `docs/v1-architecture.md` §13 和 `docs/development-process.md` §1～3，下一阶段需要把现有源快照、解析与映射接到可检查的原生单文档阅读闭环。

2026-11-02 用户将 M0 出口及 M1 准入记为通过，性质是**验收豁免和风险接受，不是证据补齐**（`docs/decisions.md` §20、`docs/v1-validation-plan.md`「当前 M0 状态」）。逐包人工复核、E2/E4/E5/E7 整项、E3 全量、E6 未测项及 V-01～V-09 仍未执行或未整项完成；本变更不重开 M0、不关闭这些缺口。

## What Changes

- 原生单窗、单个本地 `.md`/`.MD` 文件的打开、替换、关闭与无文档状态；最小入口为窗口打开按钮、文件菜单及 Cmd/Ctrl+O 的同一文件选择动作。成功后替换当前只读会话，取消/失败保留原会话。拖放、命令行、关联、全应用身份转交留 M5（PRD §5.1 FILE-01～03、§6.3；架构 §13）。
- 可视化按变高块、源码按逻辑行虚拟化，共用内容列宽和主纵向滚动入口；以源码锚点切换两种视图，零文本/历史变化。M1 的只读是阶段能力限制，不是 PRD §8 排除的第三种 Preview 模式（PRD EDIT-01/04、§6.1/7.2，UI §6，架构规范 R-10）。
- 补齐消费者真正需要的只读结构投影、局部布局到全文映射适配，以及不开编辑块的文档初始化/导航/结果采纳边界。已有 `Parsed` 只有顶层 `BlockKind` 与全文 `Projection`，不能假定已具备完整嵌套展示树；现有 `DocCore::new` 自动开块，不能直接用作只读初始化（引擎 §3/4/6/7，CODE_STANDARDS §2～4）。
- 展示基础 Markdown、表格结构、五类 Alerts、有限 HTML、灰色脚注/目录/Front matter、大纲层级及主动跳转；代码行号常显。表格仅展示，语言修改/任务框切换等写动作不可用。公式/Mermaid 和图片引用保留原文/可识别回退，不接资产后端、不建图片 tab（PRD MD-01～11、UI §5.3/7/8；架构 §6/13）。
- 建立 V-03/V-07 基础夹具，安排 V-04 中文字体与静态字体加载实验、V-05 首轮 Release 基准、V-09 主窗双语/焦点/尺寸基准，按 V-01 先执行 macOS 原生冒烟。保留 Windows 10、Intel Mac、Linux 和最低系统证据缺口（验证计划对应条目）。

### Non-Goals

不接编辑、块打开/提交、IME、撤销/重做、查找替换、保存/自动保存/外改重载/恢复（M2）；不接命令、表格操作、HTML 原文编辑、格式化（M3）；不接插件系统、编程语言高亮、公式/Mermaid 渲染、图片预览 tab、完整主题/设置（M4）；不建标签、多窗、文件树、平台集成（M5）和打包发布（M6）。M1 的源码视图也只读；不缩减后续 Source 可编辑契约。本轮不新增依赖；原生后端若确需新增依赖，须按下方待确认项先走准入并获具体裁决，本规划不预授权。不得升级 GPUI 或引入 WebView。

## Capabilities

### New Capabilities

- `ui/readonly-document`：单窗只读生命周期、双视图虚拟化与定位、语法/保护区/导航、普通代码及双语键盘行为。

### Modified Capabilities

- `engine/markdown`：新增带来源的只读结构展示及局部投影消费契约；修正已由解析器识别的脚注因导航标签匹配不一致而丢目标的契约，不另立解析器或竞争性映射真源。
- `engine/document-core`：新增不开编辑块的只读会话及导航/结果采纳契约，保留 M0 编辑初始化和输入组协议。
- `workspace/engineering-gates`：新增 M1 分项证据交接要求；复用现有门禁能力，不新建近义治理规格，不改 M0 历史验收要求。

## Impact

实施拟影响 `app` 的启动装配，`aline-ui` 的 document/单窗打开编排/render/源码行视图/字体适配，`aline-markdown` 的只读语义与映射公共边界，`aline-app-core` 的双语 catalog；必要行索引消费复用 `aline-buffer`。不扩八 crate，不把 GPUI/线程/全局状态引入五引擎，不预装插件骨架。公共 API 增量须审查真实消费方、受检坐标和兼容性。

工程约束：CODE_STANDARDS §2～6、engineering-governance 全部适用要求；架构规范 R-1～4、R-6～8、R-10～13、R-16～17；Rust S-2～5、S-7～15/16，重点为最窄可见性、零副作用拒绝、类型化错误、引擎无 panic、所有文案 `t("key")`、布局热路径和生命周期。现有 `gpui-pre =0.3.9`、pulldown-cmark 及依赖准入保持；若原生 feature 激活改变受审子图，须重新审计，不能刷新指纹以掩盖漂移（架构 §3.2、引擎 §18.2）。

实施完成后才按真实结果回填 `docs/v1-architecture.md` §13、`docs/v1-validation-plan.md` 相关 V 项及受影响的引擎/UI 公共契约；必要决定回填 `docs/decisions.md`。本轮只新增本 change 工件，不改现行 docs/config/实现，不 commit/push/archive；等用户明确“开始 apply”。

### Risks

结构投影和不开块生命周期是实际 API 缺口；必须先无头测试再接窗口。原生后端/Metal 工具、字体缺字、巨块布局和文件系统阻塞均可能阻塞实测；失败保留源码和原文件，禁止以回退冒充基础语法通过。M0 豁免的缺口可能暴露缺陷，按影响补 M1 必需回归，不倒填 M0 完整验证。

### Open Questions

架构 §13 M1 出口没有实质歧义；但原生接线存在以下已查明的技术阻塞，本规划可评审，尚不能据此直接完成窗口实施。

- **待确认：原生平台后端准入路径。** 与 Cargo.lock 校验和 `34f61c1cfd36fc9c436af09308c963822ae27a45a84feb21a77ba5c9e051f1c0` 一致的 `gpui-pre 0.3.9` 原始归档只有 `Application::with_platform(Rc<dyn Platform>)`，没有默认平台构造器或 macOS/Windows/Linux 原生 Platform 实现；当前锁文件也没有相应平台后端包。单纯打开 Cargo feature 不能补出该实现。本轮不添加任何依赖；拟在 apply 的独立前置任务中按引擎 §18.2/架构 §3.2 准备最小、与锁定 GPUI 类型兼容的安全后端准入方案（来源/版本/许可证/完整闭包/unsafe 所属/三平台目标），提交具体评审裁决前，原生窗口及后续 UI 任务保持阻塞。不得改用假平台算冒烟、静默升级 GPUI、自写未获批准的 unsafe 或自动刷新指纹。若用户要求实现期也绝对不允许任何后端准入，M1 原生出口目前无法完成。

- V-07 样例始终保留“现状”与“独立预期”两列。SoftBreak `a\nb` 保留带来源的可见换行；有限 HTML 子集之外的 void 标签显示原始标签，未知非 void 容器整段按原文显示；用户已于 2026-11-03 裁决，独立回归和契约见任务 1.2 证据及引擎 §7/11。已被解析器识别配对却因标签大小写而导航为空是引擎 §12.1 明留 M1 的缺陷，列为修复任务，不能归为正常缺失目标验收。其他样例若不能由 PRD MD-04/07～11 和引擎 §7/11 裁决，列明最小冲突并暂停该语义的实施/通过声明，交用户确认，不以本提案授权任意口径。
- V-04/V-05/V-09 的字体实际可用性、布局数值、预算/性能门槛留实验收口，不能预填为成绩或降低现行产品目标。
- `openspec/config.yaml` 的 “M0 exit remains open” 与部分 M0 主规格的历史准入措辞仍在；按已明确的 §20 用户风险接受及本轮指令解释为证据未闭合，不重开 M0。本轮不改这些现行文件。
