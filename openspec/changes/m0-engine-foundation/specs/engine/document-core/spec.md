# Spec Delta

## Purpose

为 M0 在无窗口环境中验证文档当前内容和输入历史的一致性，维护唯一草稿、单调身份和快照语义，为 M1/M2 提供可消费接口，同时明确模拟事件不代表原生输入或保存能力已经通过。

## ADDED Requirements

### Requirement: 唯一草稿与当前快照

文档所有者 MUST 持有 Buffer/History 及至多一个草稿；当前快照 MUST 包含最新草稿、工作版本、选区及所需资源引用，不封口、不改变历史。关联 TA-01、E7、K-03。

初始打开范围等于初始选区按源码字节排序后的范围。`SnapshotId` 标识快照实例或内容视图的来源，不是 `WorkingVersion` 身份；同一 ID 可跨工作版本复用，文本相同也不保证 ID 相同。消费者判断版本和派生结果有效性 MUST 同时校验文档、工作版本及实际依赖的其他身份，不能单独依据 `SnapshotId`。

#### Scenario: 快照后继续输入

- **WHEN** 打开块有未提交输入并请求快照，随后继续输入
- **THEN** 快照冻结当时完整当前内容，较新输入产生新代次，取快照不提交/压缩组或清 redo

#### Scenario: 快照来源身份复用

- **WHEN** 待定草稿撤销后工作版本推进而底层快照来源复用
- **THEN** 消费者仍按工作版本拒绝旧结果，不能将来源身份相同解释为工作版本相同

#### Scenario: 草稿基线冲突

- **WHEN** 打开块基线与当前源版本不符
- **THEN** 保留草稿与选区返回冲突，重新定位或等待，不 drop 草稿或套用旧区间

### Requirement: 分组与组合状态

连续相邻普通输入 MUST 按既定 900ms 组协议；提交与关块分离，IME 确认独立成组，组合取消恢复前态且代次失效。关联 EDIT-05/06、E4/E7、K-03。

#### Scenario: 同块多组与离块

- **WHEN** 虚拟时间推进形成多组，提交后保持开块，再离块/Escape
- **THEN** 各组单区间提交与一步历史，离块仅处理剩余组，Escape 不丢输入、不重复整块记步

#### Scenario: Undo 与组合取消

- **WHEN** 当前存在待定组时 Undo；或 Undo 已提交内容后、旧 redo 分支仍存在时开始有效非空普通输入；或组合更新后取消
- **THEN** Undo 优先撤销待定组并恢复选区；新普通输入草稿创建时立即丢弃旧 redo 分支，即使随后撤销/丢弃草稿也不恢复旧分支，待定输入期间 Redo 拒绝且保留草稿；无效/空输入不清分支；组合取消恢复组合前状态且不清 redo、不留空步，旧投影代次不复活

### Requirement: 发布等待与结果采纳

组合期显式发布 MUST 可取消地等待平台自然结束后取当前快照，自动保存延后；可替换派生结果 MUST 按存活目标及完整身份键复验。关联 ED-01、E6/E7、R-6、S-13。

#### Scenario: 确认取消与取消请求

- **WHEN** 模拟组合期显式保存/另存为/导出，分别送达确认、组合取消或取消等待请求
- **THEN** 自然结束后才取当前内容；取消等待不改变输入/历史、不发布候选，恢复保护当前输入仍是独立协议

#### Scenario: 结果乱序或目标关闭

- **WHEN** 旧解析/旧投影结果在新输入、取消或关闭后到达
- **THEN** 拒绝采纳且不恢复已关闭对象；不可丢弃写盘回执留宿主按实际快照结算，不套用派生结果丢弃规则
