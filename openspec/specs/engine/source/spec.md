# engine/source Specification

## Purpose
为 M0 文件字节与编辑源码之间建立受检、可复查的转换边界，使未改内容能够恢复原始字节，已改内容遵守现行 BOM 与行尾契约，并把编码失败、超限和存储身份与编辑历史区分。

## Requirements

### Requirement: 有效编码与存储来源

文件输入 MUST 先检查预算再验证 UTF-8，分离头部 BOM，记录原字节、CRLF 对数与未配对 LF 数；孤立 CR 和文件末尾状态 MUST 保留。关联 SAFE-01、E2/E4、S-7、K-02。

#### Scenario: 有效字节解码

- **WHEN** 有效 UTF-8 文本含头部 BOM、正文 U+FEFF、孤立 CR 或以 %PDF/PK 开头
- **THEN** 返回源码与存储元数据；正文 U+FEFF 和有效签名前缀不被删除或拒绝

#### Scenario: 非法与超限拒收

- **WHEN** 输入以 UTF-16 BOM 开头、为非法或截断 UTF-8，或超过注入的输入预算
- **THEN** 返回可区别的编码/预算错误，不有损替换、不写原文件、不返回伪空文档

### Requirement: 保真编码与内容身份

编辑源码 MUST 分离头部 BOM 并保留原始 CR/LF 字节。编码 MUST 绑定冻结文本与存储基线的受检内容证据；相等时返回原 bytes，不等时重放 BOM 和多数派行尾，平票 LF；若基线无头部 BOM 而冻结源码以 U+FEFF 开头，MUST 写出一个头部 BOM 保护该字符，预算计入，成功保存后的基线记为有 BOM。CRLF 对和未配对 LF 各为一个行尾单元，包含合法编辑新形成的 CRLF；未配对 CR MUST 保留，LF 策略下紧跟在孤立 CR 之后的 CRLF 单元 MUST 保留 CRLF，避免再解码时吞掉孤立 CR。再解码 MUST 与冻结源码在仅 CRLF/LF 表示差异上等价，不要求 String 严格相同；该存储等价 MUST NOT 替代补丁、历史、工作版本及无变化的精确源码判定。关联 AC-01/02 基础、E4、S-12。

#### Scenario: 未改或撤销回基线

- **WHEN** 含混合行尾、空白、实体和无尾换行的内容与尚未替代的存储基线相等
- **THEN** 返回逐字节相同的原 bytes，不依据曾经编辑过或历史栈深选择通道

#### Scenario: 局部修改与混合例外

- **WHEN** 对统一行尾或混合行尾输入进行合法局部修改
- **THEN** 除显式补丁和混合行尾多数派例外外保留内容，不补尾换行、不吞孤立 CR

#### Scenario: 行首正文 U+FEFF 保护

- **WHEN** 基线无头部 BOM，合法编辑删除该 U+FEFF 前的字符，使冻结源码以 U+FEFF 开头
- **THEN** 编码写出一个头部 BOM 保护该字符，再解码仍以 U+FEFF 开头；预算计入该 BOM，不拒绝正常输入、不丢字符

#### Scenario: 边界拼接往返

- **WHEN** 删除源码中 CR、X、LF 之间的 X 或在边界插入/粘贴换行
- **THEN** 新形成的 CRLF 按一个行尾单元编码，LF 策略允许冻结源码 `"\r\n"` 重开为 `"\n"`，只在此行尾表示上等价；未配对 CR 和其余字符不变，逆补丁在冻结源码上精确恢复独立预期；不隐式整理 Buffer 或拒绝正常操作

#### Scenario: 孤立 CR 后紧跟 CRLF

- **WHEN** LF 多数派基线的冻结源码中孤立 CR 之后紧跟 CRLF 单元
- **THEN** 保留该 CRLF；再解码仍保留孤立 CR，输出允许同时含 LF 与 CRLF

### Requirement: 受检文件原语失败保全

最小受检写入原语 MUST 区分 I/O/取消/冲突并保全原目标；失败 MUST NOT 发布成功基线。关联 R-15、S-7、E2，完整平台事务留 V-08。

#### Scenario: 写入准备失败

- **WHEN** 注入临时写入或替换前失败
- **THEN** 原目标完整字节和调用方内存保留，返回明确错误，不降级为原地截断或先删原文件

#### Scenario: 成功结果归属

- **WHEN** 最小受检原语成功写出冻结字节
- **THEN** 返回实际写出身份和字节事实，由宿主结算，不擅自标记较新输入已保存
