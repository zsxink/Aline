# engine/buffer Specification

## Purpose
为 M0 源码提供唯一的受检补丁基础与可逆历史原语，明确源码版本、锚点和选区的上下文，使后续文档所有者能按统一协议提交编辑，而不将磁盘、解析或展示状态混入缓冲。

## Requirements

### Requirement: 补丁批次原子性

补丁 MUST 同基线、升序不重叠、合法半开 UTF-8 范围，长度运算受检且目标选区按 after 校验；成功统一发布文本/行索引/选区/版本，拒绝整批零修改。关联 E2/E4、S-5-03～05、K-02。

#### Scenario: 变长多补丁

- **WHEN** 对 abcXYZ 以 before 坐标应用 1..2→QQ 和 3..6→!
- **THEN** 得到 aQQc!；逆补丁使用 after 坐标 1..3→b、4..5→XYZ，恢复原文与选区

#### Scenario: 末项非法或歧义插入

- **WHEN** 批次末项越界、半字符、重叠、逆序、累计溢出，或同一点多插入尚未合并
- **THEN** 整体拒绝，文本/行索引/选区/revision/undo/redo 均与调用前一致

#### Scenario: 空插入与无变化

- **WHEN** 合法空区间插入或替换为相同文本
- **THEN** 插入按协议生效；无变化不产生空历史步、不无故清空 redo

### Requirement: 锚点历史与版本

锚点 MUST 按补丁及方向偏好受检变换；正逆补丁及前后源码选区 MUST 可恢复，Undo/Redo MUST 推进单调版本。内容身份 MUST NOT 用栈深或未验证指纹替代。关联 TA-01/02、E4/E7、S-12、K-03。

#### Scenario: 替换内部锚点

- **WHEN** 补丁覆盖锚点或改变其前文长度
- **THEN** 返回依约定 affinity 的合法新锚点或明确失效，不由调用点猜长度差

#### Scenario: 同深分支与历史裁剪

- **WHEN** 保存 A 后撤销再输入 B，或裁剪保存节点附近历史
- **THEN** 不同文本不被同栈深误判已保存；等价证据待定时保守判修改，仍被历史引用的资源不失去存活证据

#### Scenario: 可撤销重载边界

- **WHEN** 按独立历史操作载入新磁盘内容，再 Undo/Redo
- **THEN** 只恢复对应内存文本/选区并推进 revision，不写盘或回退磁盘基线；旧绝对补丁仅在对应上下文应用

#### Scenario: 历史预算超限

- **WHEN** 构造历史/逆补丁计划超过注入预算
- **THEN** 受检失败或执行已声明的安全裁剪协议，不能半应用或丢弃当前输入
