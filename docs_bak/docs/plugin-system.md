# Aline 插件系统设计（V1）

> 本文定义一期内置插件的产品行为、设置归属与架构边界。插件系统总体架构见 [v1-architecture.md](./v1-architecture.md) §9；V1 功能范围见 [v1-features.md](./v1-features.md)。

## 1. 目标与范围

一期插件用于扩展编辑器的渲染、编辑和导出能力，并在设置页集中管理插件及其选项。

- 一期插件全部编译进应用，通过显式注册表注册。
- 一期不支持下载、安装或运行时动态加载第三方插件。
- 每个插件可独立启用或关闭；插件设置持久化，关闭后保留配置值。
- 插件产生的编辑必须走宿主的命令与补丁通道；插件不得直接重建 Markdown 或绕过撤销历史。
- 所有面向用户的插件名称、说明、菜单项和错误提示均使用 i18n catalog。

一期包含五个内置插件：Mermaid、表格增强、导出、公式和代码高亮。

## 2. 插件管理与设置

设置页分为“应用设置”和“插件设置”两组。“应用设置 > 插件”集中显示各内置插件的名称、说明和启用开关；每个插件的专属配置归入“插件设置”中的对应分区。启用状态与插件设置写入应用设置文件；启动时解析为类型化快照并传给插件，运行期不直接读取 TOML。

关闭插件时保留其配置值，但隐藏该插件在“插件设置”中的导航入口和配置分区；重新启用后恢复显示原配置。插件开关同时控制相关渲染器、命令、工具栏入口和菜单项；具体回退行为见 §3。

插件设置仅影响所属插件，不自动成为应用全局主题或全局编辑器设置。特别是 Mermaid 主题与 Aline 全局主题体系互相独立。

## 3. 内置插件

### 3.1 Mermaid

**功能**

- 在可视化模式预览 Mermaid 围栏代码。
- 打开编辑时使用“上方源码、下方预览”，源码变更后防抖重渲染。
- 提供图表导出为 SVG / PNG，以及复制图表的命令。
- 渲染失败时显示错误状态并保留可编辑源码。

**主题设置**

Mermaid 主题只控制 Mermaid 图表，不加入 Aline 的全局主题系统。提供跟随应用明暗模式、选择内置 Mermaid 主题，以及导入/管理 Mermaid 自定义主题的能力。

- 跟随明暗模式时，根据应用当前明暗模式选择 Mermaid 对应配色；这只读取明暗模式，不继承 Aline 的界面颜色 token。
- 手动指定内置主题或自定义主题后，应用明暗模式变化不覆盖用户选择。
- 主题选择或主题内容变化会使相关图表重新渲染，渲染缓存键包含 Mermaid 主题身份与内容版本。

关闭 Mermaid 插件后，图表显示源码，预览、复制和图表导出命令隐藏。

### 3.2 表格增强

**悬停快捷操作**

- 鼠标悬停在某一行时，该行下方边界左侧显示“＋”；点击后在该行下方插入一行。
- 鼠标悬停在某一列时，该列右侧边界上方显示“＋”；点击后在该列右侧插入一列。

**单元格右键菜单**

- 在上方或下方插入行。
- 在左侧或右侧插入列。
- 删除当前行或当前列。
- 删除整张表格。
- 复制整张表格。
- 保留表格对齐及表头行操作。

操作对象由右键所在单元格确定。每个操作通过 `aline-edit` 的表格命令生成源码补丁，并形成可撤销步骤。

关闭表格增强插件时只隐藏悬停“＋”按钮；表格渲染、逐格编辑和右键菜单中的基础增删操作仍然可用，因为表格编辑是 V1 核心能力。

### 3.3 导出

导出插件支持 PDF、Word 和 HTML。导出菜单和工具栏入口由插件启用状态统一控制；插件关闭时，两处入口均隐藏。

各格式在插件设置中使用独立分组，设置按对应格式的能力提供：

- **PDF**：页面尺寸、页面方向、页边距。
- **Word**：标题和正文样式、代码块样式等文档外观选项。
- **HTML**：是否包含样式，以及图片资源的导出处理方式。

导出使用编辑器当前的 `Parsed`、展示树和资源解析结果，保持与编辑器一致的 Markdown 语义；不得为导出再引入第二套 Markdown 解析器。异步导出结果须校验文档版本，避免较早的任务覆盖较新的导出状态。

### 3.4 公式

- 渲染行内公式和块级公式。
- 块级公式打开时采用“上方源码、下方渲染”，源码输入防抖后更新预览。
- 渲染失败时显示错误状态并保留可编辑源码。
- 提供公式背景色设置，支持跟随内容主题、透明或用户指定颜色。

关闭公式插件后公式源码仍可见、可编辑，不执行公式渲染。

### 3.5 代码高亮

- 插件负责识别 fenced code 的编程语言语法，并产出关键字、字符串、注释等语义高亮区间；V1 使用 syntect，为支持的语言提供结果，并复用于源码模式中的 fenced code。
- 代码块表面颜色及语义类别颜色分别由主题包 `highlight.json → codeBlock/syntax` 提供；代码高亮插件拥有自己的“代码高亮模式”和“代码主题”设置，两项都可独立于应用外观。代码块几何仍由 Markdown 主题控制。
- “代码高亮模式”支持“随应用切换”、亮、暗、护眼；“代码主题”支持“随应用切换”或固定选择内置/已导入主题包。两项分别解析：应用亮色 + 暗色高亮、GitHub 界面 + Vue 代码主题都可组合。
- 设置为“随应用切换”时，代码高亮模式跟随应用当前模式，代码主题使用当前界面主题家族；固定模式或主题不受应用外观变化影响。插件设置改变、其跟随的应用主题/模式改变时，使用解析出的高亮配置更新代码块颜色与语义色；对应高亮缓存键包含文档内容、语言与高亮主题/模式版本。
- 未识别语言、高亮失败或插件关闭时显示普通代码块；代码块布局、行号、复制、语言选择和源码编辑仍由宿主保留。
- Markdown 标记本身在源码模式中的着色属于 Markdown 编辑器核心，不随本插件开关关闭。

关闭代码高亮插件后，代码块仍使用当前 Markdown 主题的普通代码前景色和背景色，不显示语言语法颜色。

## 4. 插件能力与扩展点

- 插件可注册语法接入器、解析后处理器、文档修改提案提供器、块渲染器、命令、导出器和 i18n catalog；仅声明实际提供的能力。
- **语法接入器**为额外语法提供识别与结构化结果，例如扩展 front matter 元数据或接入新围栏语言。输入和输出使用源文本字节范围、纯数据节点及显式错误状态，不接触 GPUI。
- **映射式预处理**用于将扩展语法改写为 pulldown-cmark 可识别的形式；每个变换必须返回改写字节到原始 UTF-8 字节的映射。原文仍是唯一事实来源，插件不能用改写结果替换原文。
- **解析后处理器**消费核心解析结果并附加语义数据，例如建立脚注引用/定义关系，或根据标题集合生成 `[TOC]` 目录项。处理器只生成带原文范围的扩展数据，不能重解析整份 Markdown 或改变已有节点的源码范围。
- `PlantUML` 主要复用围栏语言识别、资产渲染和缓存接口；front matter、脚注、`[TOC]` 可复用语法接入与解析后处理接口，并注册各自的渲染、编辑命令和设置。
- 解析扩展为确定性纯逻辑，不访问 GPUI、文件系统或网络；注册顺序固定，扩展 ID 唯一。多个扩展声明处理同一语法时，按显式优先级选择唯一处理者；冲突记录诊断并回退核心默认行为。
- 内置插件可使用 GPUI 元素级 `BlockRenderer`。未来外部 wasm/进程外插件只使用纯数据 `AssetRenderer → RenderDesc`，不得跨边界传递 GPUI 类型。
- 插件的命令通过宿主提供的上下文执行，编辑必须产出 `Change`/补丁；插件不能直接访问或修改底层 buffer。
- 插件设置由 `aline-app-core` 表达为可序列化、可校验的类型化配置；GPUI 转换和界面控件归 `aline-ui`。
- 插件渲染及导出失败必须给出可见降级状态和诊断日志，不得让用户文档丢失或导致应用崩溃。
- 插件开关变化通过统一的设置传播机制刷新窗口，并使相关渲染缓存失效。

### 4.1 解析扩展接口归属与生命周期

- 扩展契约由 `aline-markdown` 定义为纯数据接口（例如 `ParseExtension`、`PreprocessResult`、`ExtensionNode`），由 `aline-plugin` 提供实现。`aline-markdown` 不依赖 `aline-plugin`、GPUI 或插件实现 crate。
- 应用初始化时由宿主收集已启用的解析扩展，并将只读注册表传入解析入口。解析快照记录启用扩展集合及版本；集合变化时重解析并失效相关缓存。
- 解析顺序固定为：映射式预处理 → pulldown-cmark → 核心 mdast → 插件解析后处理 → 展示树。每一阶段都保留原始 UTF-8 字节范围。
- V1 只实现现有核心语法和五个内置插件所需的能力。PlantUML、front matter 增强、脚注和 `[TOC]` 的专属插件行为留待后续；V1 已有的脚注与 `[TOC]` 基础功能继续由核心提供，不依赖未来插件。
- 外部 wasm 插件当前只预留资产型渲染 API。若将来允许外部插件提供解析扩展，必须另行定义纯数据映射协议和资源上限；不得把 GPUI 或任意 Markdown 解析器带入沙箱 ABI。

### 4.2 文档修改提案（未来 AI 插件）

AI 插件可帮助改写或整理文档，但只能提交提案，不能直接修改 buffer、保存文件或绕过用户审阅。

- 插件取得明确授权后，接收用户选择的文档快照或选区上下文；远程模型调用前，界面说明将发送的内容范围和目标服务，不得静默上传整篇文档。
- 插件返回纯数据 `DocumentProposal`：目标文档标识、生成时的 buffer 版本、摘要/说明和一个或多个源码区间补丁。补丁仍以原始 UTF-8 字节偏移表示。
- 宿主在审阅界面展示提案差异及上下文。用户可接受或拒绝；模型响应到达后不自动应用，初期可整组接受或拒绝，逐 hunk 接受留给后续设计。
- 接受时验证目标文档与生成版本仍匹配、补丁区间有序且不重叠，再通过 `aline-edit` 的普通命令/补丁事务一次应用，形成一个撤销步骤。版本过期、范围无效或校验失败时拒绝应用并要求重新生成/审阅，不自动重基。
- `DocumentProposal` 与版本校验/应用协议归 `aline-edit` 或其纯数据 API；`aline-ui` 负责差异审阅与用户确认；AI 插件只负责生成提案。任何模型提供方、网络访问和文档上下文授权按独立能力配置。
- 此能力属于 V1 之后的扩展，V1 不接入 AI 服务，也不提供自动应用提案的路径。

## 5. 一期验收

- “应用设置 > 插件”显示五个内置插件，可独立启用、关闭；各插件专属选项在“插件设置”中配置。关闭时隐藏该插件专属设置入口和分区，但保留配置值；重新启用后恢复显示。重启后状态与配置保留。
- 各插件开关会同步控制其渲染、工具栏和菜单命令，且回退行为符合 §3。
- Mermaid 的明暗跟随、手动主题和导入主题仅影响 Mermaid；不修改或注册为 Aline 全局主题。
- 代码高亮插件只产生语言语义区间；语义色从 `highlight.json` 读取，代码高亮模式与代码主题由插件设置独立配置。插件设置可以固定亮/暗/护眼模式和任意主题包，因此应用亮色界面仍可使用暗色代码高亮。
- Mermaid 图表预览、SVG/PNG 导出、复制命令与右键菜单行为一致。
- 表格悬停添加按钮方向正确；右键增删、复制及表格对齐操作范围正确，修改可撤销。
- PDF、Word、HTML 导出使用同一解析结果；导出插件关闭后所有导出入口消失。
- 公式和代码高亮关闭或失败时，文档源码仍可读、可编辑。

## 6. 与既有 V1 文档的关系

本设计将 PDF / Word / HTML 导出与 Mermaid 专属主题导入、自定义纳入 V1。Aline 全局主题包用户自定义按 [theme-package-spec.md](./theme-package-spec.md) 纳入 V1；它不等于运行时第三方插件加载，后者仍不属于 V1。

PlantUML、front matter 增强、脚注及 `[TOC]` 的专属插件行为不纳入 V1；其所需的语法接入、映射式预处理、解析后处理、扩展数据渲染与命令注册能力按 §4.1 预留。

AI 文档修改插件同样不纳入 V1；预留的文档修改提案能力遵循“生成补丁提案 → 用户审阅 → 显式接受 → 单事务应用”路径，见 §4.2。

**候选探索（未立项，不承诺实现）**：后续图表插件可评估 Draw.io 等可嵌入图表的展示能力。支持的文件/源码格式、文档中的引用与存储方式、只读展示或编辑体验、渲染与导出方案均未确定；在单独评估并决策前，不视为 V1 或后续版本承诺。
