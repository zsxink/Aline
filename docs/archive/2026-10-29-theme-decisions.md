- **影响：**§3/4/12、版本错误、作者迁移说明、TH-T01/03。
- **可选方案：**A（**建议**）正式从 1 开始，原型须按新表重新打包；语义清楚但编号回到较小值。B 用新号 4 与历史连续且隔离；版本较大不代表已兼容。C 延用 3，但需明确格式标识/迁移边界，不能对历史包宽松试读，额外复杂。
- **是否阻塞：****阻塞主题包实现**（版本识别与正式分发兼容）。
- **暂行处理：**示例以 1 展示候选，不建立真实 schema/迁移代码；未知版本错误和四文件职责可先设计。回写本稿及 V-04 格式产物，PRD 不需改产品范围。

### TH-04 · 包预览的允许格式

- **问题：**V1 主题包预览是否统一为静态 PNG？

- **影响：**资源 allowlist、预览路径、作者转换、SVG 攻击面、TH-T18/19；不影响 Markdown/图片 tab 自己的支持矩阵。

- **是否阻塞：****阻塞主题包实现**（资产校验与合法样例），不阻塞预览 UI 结构。
- **暂行处理：**例子采用 PNG 候选；没有将 SVG 支持或绝对禁止宣称为已确认，危险 SVG/外部加载在任何方案中都禁止。裁决回写本稿/V-04；V-09 仍验三图真实性。

### TH-06 · 用户主题的同 ID 升级流程

- **问题：**除普通导入遇同 ID 必须拒绝外，V1 是否另提供保留 ID 的显式升级流程？
- **背景与依据：**THEME-05 已定冲突不覆盖，THEME-08/V-04 要定义升级；旧稿只有“移除或改名后重试”，没有备份/失败恢复/当前使用时的升级事务。
- **影响：**版本语义、用户修改保护、升级/回退事务、注册表、作者维护、TH-T09/21。
- **可选方案：**A（**建议**）V1 不另开覆盖升级命令；普通同 ID 一律拒绝，作者用新 ID 分发或用户备份后在目录手工替换并刷新校验。简单但同身份更新步骤较多。B 新增显式“升级”动作，展示版本/修改影响、备份旧包、完整候选验证与可恢复替换；是独立流程，普通导入仍拒绝冲突，需上游新增行为确认。

### TH-07 · GitHub 继承根与可修改内置副本

- **问题：**缺省继承和失效回退是否始终使用随应用受保护的 GitHub 根资源，而将用户目录的内置主题视为可保留修改的副本？
- **背景与依据：**THEME-05 要 GitHub 缺省，THEME-09 要补缺内置/升级保修改/失效回可用默认；架构已有编译期资源与目录发现，但尚无“修改 github 会否改变所有包缺省”的身份裁决。只有磁盘副本时删除/损坏 GitHub 会使回退递归失败。
- **影响：**根基线版本、用户修改归属、内置升级/恢复、默认可用性、所有缺省包外观兼容、TH-T05/10。
- **可选方案：**A（**建议**）受保护的应用 GitHub 是继承/最终安全回退根；目录副本允许保留修改，来源记录区分，不静默覆盖；应用更新可能改变缺省，需回归/版本说明。B 磁盘 GitHub 参与用户继承，另保最小受保护紧急默认；修改会传播到所有部分包，需要明确提示、失效/恢复及基线版本。两者都必须保留升级不覆盖用户修改的既定要求。
- **是否阻塞：****阻塞主题包实现**（根默认/发现/内置维护与可靠回退）。
- **暂行处理：**§6 用 A 示意，不能据此改上游；损坏目录不当缺失覆盖，恢复/替换动作未获授权不执行。裁决后回写架构 §8.2、UI §11.2、V-04 的根资源与升级样例。

### TH-10 · 失效后的主题选择记忆

- **影响：**应用/固定代码设置、有效回退与用户意图分离、重启/修复后的状态、TH-T11/23；不影响 PL-02 的关闭后配置保留决定。
