## 1. 用途、适用范围与权威关系

本文规定 V1 六内置插件的产品行为、职责边界、注册与启停、设置归属、宿主交互、错误回退和验收。插件系统是可扩展的核心能力，六内置实现是本期提供者；不能把当前清单写成系统永久限制。本文不取代产品范围、crate 架构、解析映射机制、UI 编排或主题包格式，也不定义未来外部 ABI。

权威按职责划分：[AGENTS.md](../AGENTS.md) 规定铁律与工作规则，当前 PRD 规定产品范围与行为，已确认的[架构指引](./v1-architecture.md)、[引擎指引](./engine-design.md)、[架构规范](./architecture-guide.md)、[UI 规范](./ui-spec.md)及专项规范约束实现，[验证计划](./v1-validation-plan.md)记录方法、证据状态与待验证边界；决定记录和确认归档用于追踪选择。阅读顺序不是同级规范的裁决优先级，同级资料无法按职责解释的冲突须列出，不能按日期、文件位置或实现便利自行选择。历史设计不自动取得规范效力，已删除目录不作开发必需输入。

| 标记 | 本稿效力 |
|---|---|
| **必须** | 当前铁律、已确认产品行为或其正确性边界；开发必须满足 |
| **建议** | 可替换实现方式或待裁决的推荐；不得当作用户已同意 |
| **待验证 V-xx** | 已授权验证的支持能力、资源参数或样本契约；没有实验结果，不猜最终值 |
| **待确认 PL-xx** | 现有材料无法决定的插件行为；只暂停相关分支，不能用默认实现替代裁决 |

接口名、模块名沿用架构草图，表示所有权和数据语义，不冻结 Rust 签名。精确 API 在所属模块实现时形成受检契约，不因尚无签名而新增产品问题。TA-01～TA-03、RS-01～RS-05、ED-01、UI-01～UI-06 和 PA-01 的既有决定不重开；第 12 节保留 PL-01～PL-03 已确认摘要，原问题与方案归档保留。

[现行主题包规范](./theme-package-spec.md)已按 TH-01～TH-10 确认 schema 1、封闭字段、静态 PNG、继承与管理行为，依据见[主题确认归档](./archive/2026-10-29-theme-decisions.md)。数值/资源限额、字体/透明度/图标原生能力仍待 V-04/V-06/V-09。历史主题稿只作证据，不覆盖现行字段。PL-02 行为不变：关闭高亮回当前内容主题普通表面，独立高亮每个缺色从受保护 GitHub 高亮同模式补齐，不临时回内容主题取色；字体/行高/布局仍取内容主题。固定代码包失效保留身份/固定模式、有效配色暂回默认对应模式，修复/重装/刷新/重启不自动重新应用，须用户显式选择，旧身份不盖回后续新选择。

## 2. V1 插件模型与非目标

**必须：**V1 使用随应用编译、显式注入注册的内置提供者，经过共同的注册、生命周期和能力分发通道。能力查询不能在系统公共代码中硬编码六个插件种类；架构 §8.1 要求的测试提供者用于验证可扩展性，不是第七个产品插件。

V1 不交付运行时第三方插件加载、安装/商店、用户可执行脚本、AI 服务或 AI 自动修改文档；不预建 Wasmtime/WASI、WIT、动态库宿主、外部 SDK 或沙箱。禁止借插件化引入 tokio、notify、regex、第二个 Markdown 解析器或未经准入的依赖。执行器与任务调度归 UI；五个引擎 crate 无 GPUI、零线程、零可变全局状态。

PlantUML、Draw.io、Front matter 属性增强、脚注/目录专属增强插件均不在本期清单。脚注、目录和 Front matter 的基础识别/灰色只读展示/导航仍是核心 MD-02/04/06/11；不能因为没有专属插件而删掉，也不能借解析扩展把它们变成可视化可编辑能力。Markdown 格式化属于核心 FORMAT-01～02，不是导出插件。

未来外部提供者独立分发、无需重编译应用即可接入的方向已由 PA-01 确认；协议、执行环境、权限隔离、兼容与交付阶段没有确认。V1 内部 Rust/GPUI 接口不得被宣称为可分发的外部协议。

## 4. 注册、接口与唯一责任方

### 4.1 所有权和访问边界

依据：[架构 §4/8](./v1-architecture.md#8-插件主题设置与导出接线)、[架构规范 R-1-01～03、R-13、R-14](./architecture-guide.md#14-插件宿主与导出边界)。

| 所有者 | 输入、输出和可访问数据 | 必须守住的边界 / 错误出口 |
|---|---|---|
| aline-plugin 公共系统 | 身份/来源/能力声明；注册、查询、启停、配置代次；路由请求并返回意图/资产/产物/诊断 | contracts 不含 GPUI 实体或可变 Buffer；registry/lifecycle/dispatch 不逐项硬编码六实现；重复 ID、无效声明和冲突可诊断，不能以注册顺序默默覆盖 |
| aline-plugin 内置提供者与桥接 | 宿主注入的只读文本片段/资源上下文、有效配置、预算；可使用内部 Rust/GPUI 渲染接口 | 不依赖 aline-ui，不获取任意可写 Buffer、文件队列或完整窗口可变状态；向 UI 返回语义意图，由宿主处理 |
| aline-markdown | 源快照、解析配置/扩展集合、预算 → 带来源的语义和诊断；持有纯数据解析扩展契约 | 不依赖 plugin/GPUI/宿主全局表；不读磁盘/网络，不执行资产生成；映射或扩展失败按引擎退原文 |
| aline-edit / buffer | 源快照、命令与选区 → Change/拒绝；DocCore 调用受检补丁/历史原语 | 插件只发意图；不能绕过 DocCore 修改文档，不开放裸可变句柄 |
| aline-app-core | 插件设置纯数据模型、校验与默认值；主题有效参数、显式 locale 查询 | 零 GPUI；不读取应用全局状态、不安装主题/字体、不直接广播窗口 |
| aline-ui 应用配置服务 | 校验配置后发布唯一有效快照/代次，编排持久化、跨窗传播 | 不让各插件各读/写配置文件；错误反馈区分校验、运行生效和落盘失败 |
| aline-ui 文档/资源/导出服务 | 当前文本与草稿、身份/路径、任务和资源引用；调度、采纳、剪贴板、目标文件发布 | 文档内容归 DocCore；资源与目标文件由相应协调器统一管理；平台/路径错误由 UI 本地化 |
| app | 初始化与平台服务、菜单接线、目录服务注入 | 调用 UI 服务，不复制配置、保存或导出状态机 |

插件读取源码必须拿带身份/工作版本的只读快照或片段；文件路径通过受控资源上下文提供解析基准，不能据此任意读写磁盘。渲染数据注明来源版本，不能反向写回源。UI 注入桥接所需的最小上下文或动作处理，插件不持有可操纵整个 Workspace 的对象。类型 home 与确切签名按架构公开 API 规则形成；本稿不新增通用任意代码回调 API。

### 4.2 注册、分发与冲突

宿主初始化收集内置提供者 → 公共系统校验身份和能力声明 → 配置服务给出有效启用集合 → lifecycle 激活相应能力 → 菜单、视图和请求通过能力查询接线。错误按第 9 节返回；受影响能力不可用时不能报告注册成功，其他已校验能力和文档继续可用。具体失败隔离机制须由实现测试证明，不能把进程内插件等同于已具备崩溃沙箱。

同一动作必须有唯一的语义责任方和命令身份。发现冲突须诊断并保持核心安全回退，不从旧稿继承“显式优先级获胜”或“后注册者覆盖”的协议。V1 仅注册六项所需能力；未来多提供者替换/选择策略另行设计，不先增加公共 API。

### 4.3 解析扩展生命周期

**必须：**扩展契约归 aline-markdown 的纯数据层；宿主从公共注册结果形成只读解析配置，按确定顺序注入。引擎不读取 plugin 注册全局对象。处理只作用于解析副本，修改段有回原 UTF-8 源码的映射，保留版本和受保护语义；失败退可定位原文，禁止第二解析器或 AST 写回。

阶段和映射算法以[引擎 §6](./engine-design.md#6-解析管线及预处理映射)为准，不把旧稿的 ParseExtension、ExtensionNode 或“插件后处理”固定为必须存在的 Rust 类型/阶段。只有实际改变解析语义的扩展集合/配置变化才要求新的解析配置代次及重解析；仅关闭预览/配色不应删除核心源码识别和保护语义。任何时候不以旧映射执行新文本编辑。

确定性、重复 ID/冲突、集合变更和旧解析结果拒收应可无头测试。解析实现的纯逻辑部分不能因内置提供者可用 GPUI 而向引擎泄漏窗口、文件系统、网络或执行器。

## 5. 公共启停、设置与状态传播

### 5.1 设置归属和默认值

| 项目 | 已确认默认与作用域 | 显示与归属 |
|---|---|---|
| 六插件启用状态 | 全部开启；全应用共享并持久化 | 唯一开关在“应用设置 > 插件” |
| Mermaid 主题 | 随应用明暗，护眼映射亮色；可固定内置/自定义静态主题 | 插件专属分区；不注册成应用主题 |
| 导出选项 | PDF 默认 A4/纵向；HTML 默认含样式；其余未定默认不猜值 | 插件专属分区内 PDF/Word/HTML 分组，详见 §6.3 |
| 公式背景 | 随内容主题；可透明/自定义 | 插件专属分区 |
| 代码主题 / 高亮模式 | 两项分别初始随应用，可分别固定 | 插件专属分区位于整个设置内容底部 |
| 表格增强 / 图片预览 | 无 PRD 规定的专属配置 | 仅公共开关，不制造空分区；缩放和平移是图片 tab 视图状态 |

插件配置全应用持久化，不是窗口级或文档级；图表源码、表格内容和代码语言是文档内容，图片缩放/平移是 tab 状态，不能混存成全局插件配置。窗口布局独立。导出每次选项与全局配置如何编排继续按 UI §11.3、V-02/V-09 样本收口，不擅加“文档内插件配置”或额外记忆规则。

设置使用主窗口内单一连续滚动页、固定导航和返回编辑入口，按 [UI §11](./ui-spec.md#11-设置主题选择与插件配置)；开关不在专属分区重复。关闭隐藏该插件专属导航和内容，配置值保留；无配置插件无空页。若被隐藏分区正获焦点，UI 转到仍可用位置，具体焦点/滚动样本归 V-09；不能吞掉其他窗口当前输入。

### 5.2 启用、关闭与再次启用

1. 设置服务先校验用户意图，发布有效配置与新的插件代次；lifecycle 更新实际能力，持久化结果独立反馈。界面区分“用户配置开启”和“能力初始化失败”，不能显示有效开启但实际永远不工作。
2. 关闭即撤销对应请求/命令/视图能力，按 §7 回退；UI 作废相关在途结果、撤订阅并按 §9 结算。只失效相关派生数据，不能删除源文本、草稿、组合输入、选区、历史或恢复资源，不触发保存/格式化或制造撤销步。
3. 再次启用恢复原有效配置，按**当前**内容/路径/主题重建相关展示；off→on 推进代次，关闭前任务即使文字相同也不能复活。图片 tab 按已确认 PL-03 自动恢复：适应模式按新视口重算，手动模式恢复原缩放并按当前文件/视口约束平移；资源变化/失败说明并保留路径。
4. 重启读取保存的开关/配置，按同一校验和注册路径激活；这是配置恢复，不能因此恢复整套标签会话。正常启动仍遵循 FILE-07；异常恢复独立。

全局开关会更新所有窗口的相应呈现，这是其作用域；各文档的文本、dirty、选区、历史、路径和其他插件状态仍独立。局部加载失败不能把全应用插件开关写成关闭，也不能清除其他文档的资产。

设置文件损坏、字段类型/范围错误时使用可用的有效默认并说明原因，不能阻止启动；运行期无效编辑不发布，保留上一有效配置。持久化失败不能称“已保存”，也不能丢弃当前有效配置。具体文件格式不沿旧稿锁定 TOML；插件运行/渲染路径只消费类型化快照，不反复读文件。

### 5.3 语言与主题传播

配置/主题服务一次发布有效快照，窗口和插件按实际依赖更新；主题不能改插件开关、编辑语义、命令或快捷键。用户显式字号/行高仍优先，分区重置只清本区覆盖。语言即时影响插件名称、说明、设置、菜单及错误，均走 t("key") 和 zh-CN/en catalog；源码和文件名不翻译，纯引擎返回错误枚举。传播不改内容、草稿、历史或源选区（R-13-01～05）。

## 6. 六内置插件责任卡

各卡共同遵守 §4～5、§8～9 的保存/历史/查找/资源/任务约束；相关 AC 是覆盖计划，非已通过结果。唯一责任方按语义划分，允许共用底层服务，禁止重复维护同一份权威派生状态。

### 6.1 Mermaid

| 项目 | 责任与契约 |
|---|---|
| 名称 / 需求 / 用户问题 | Mermaid；PLUGIN-01/07、MD-05、EXPORT-06；在本地 Markdown 中阅读、编辑和交付图表 |
| 输入 / 输出 / 状态 | 带来源的 Mermaid 围栏正文、当前版本、有效图表主题和预算 → 图表资产或诊断；加载/成功/错误及缓存均为派生状态 |
| 依赖 / 修改权限 | markdown 提供围栏/正文范围，UI 调度资产、剪贴板与输出发布；插件不改图表源码、Buffer 或源文件，源码编辑仍走核心输入事务 |
| 入口 / 设置 / 默认 | 可视化图表、图表菜单；默认开；独立主题分区，初始随明暗，护眼映射亮色；固定内置/自定义主题不被应用变化覆盖，不继承界面强调色 |
| 启用 / 关闭 / 再启用 | 打开时上源码下预览，300ms 防抖由 UI 调度，组合期不提交候选预览；关闭源码仍可改，隐藏预览/复制图像/图表导出，普通文本源码复制保留；再启用按当前源码和保留主题重建 |
| 失败 / 超限 / 未支持 | 保留可编辑源码与错误，不能把旧图冒充新成功；改源码/换有效主题后可重试；图类型、主题格式/管理/重名/删除及复制表示由 V-03 固化，预算 V-06，不承诺全部 Mermaid |
| 交叉影响 / 验收 | 不改保存点/历史/查找口径；主题只影响图表，失败不波及其他 tab。SVG/PNG 与图像复制由 Mermaid 贡献用户能力，可复用 export/diagram 产物服务但由 UI 单一发布；仅受 Mermaid 开关控制，不依赖 export 开关（PL-01 已确认 A）。正文导出中的图表状态按 V-02；AC-11/12/14/16，V-02/03/05/06/09 |

图表源码复制和图像复制必须分名；无可用当前资产时不能复制旧图并报新图成功。SVG/PNG 输出与图表右键、命令共用门控和错误出口。主题导入是静态数据校验/管理，不能执行脚本或加载外部资源；非法主题不能改变应用主题或清空图表源码（UI §12.4）。

### 6.2 表格增强

| 项目 | 责任与契约 |

## 8. 文档修改、历史、保存、查找与导出的关系

### 8.1 内容与命令

**必须：**插件只提交带目标/工作版本/语义前置条件的命令意图，宿主经 aline-edit 计划、预检/预演后由 DocCore 应用源码区间补丁。跨模块源码/绘制/UTF-16 坐标使用 RS-02 的分型/受检范围，所有转换经过映射层。拒绝整批零副作用，保护草稿/组合/选区/undo/redo；可视化 MD-11 和 HTML 格式拒绝不能被插件绕过。

普通块输入按 900ms/IME 分组单区间提交，块范围排除尾换行；成功表格结构命令可多补丁但一次操作一步历史。图像复制、资源预览、启停、配色和导出不构成文档修改，不额外封口输入组、不清 redo。不能将旧 AI 提案“每次差异审阅”强加给普通表格命令；手动格式化仍按 FORMAT-01/02 单独差异确认。

查找始终按包含当前草稿的源码，关渲染/高亮不改变匹配口径；过期命中不能修改文档，受保护区按 FIND-02 定位 Source。保存由 UI/source 使用同一当前文本协议，启停不改变 bytes、磁盘基线或保存成功判定。未编辑文件仍逐字节写回；局部编辑只允许既定补丁和 BOM/行尾策略，不从资产或 AST 重建文本。

### 8.2 发布快照与唯一导出流程

用户请求 → 校验当前能力/目标 → 若处于 IME 组合，进入 ED-01 可取消等待 → 平台自然确认或取消后取**结束后的当前**快照 → 冻结文本/语义、配置、资源基准和 request_id → 插件计算产物 → UI 重验请求/目标/覆盖授权并发布 → 反馈实际版本及成功/失败/取消。

等待期间不生成/发布预编辑候选，不强制确认或取消组合；用户取消的是发布请求，当前输入与历史不变。快照不等于保存点，不要求先离块或先保存 Markdown。等待结束实际执行时重新检查能力、身份、路径、目标和资源，不能使用请求发起时过期的候选。

后续正文编辑不使冻结导出自动无效：可交付明确版本的旧快照，但旧任务不能覆盖新请求状态或未经再次确认的目标。插件关闭/文档关闭则按 R-6-06 作废**相关**任务的结果采纳资格；已开始的 I/O 必须结算真实结果，不用丢回调掩盖写入。已经成功发布的文件不因后来关闭插件而删除。

Mermaid 负责图表能力；export 的 diagram 适配可共用 SVG/PNG 产物计算，UI 负责单一剪贴板/输出发布，不能两插件各开写队列。正文格式输出归 export，表格关闭增强和图片关闭预览均不应移除核心表格或内嵌图片。math/mermaid/highlight 关闭后的具体格式表现仍须 V-02 冻结，不能先写成统一“源码导出”或“照常渲染”。PL-01 已确认独立图表命令仅受 Mermaid 控制；共享 diagram 服务不能只绑定 export 生命周期，关闭 export 不作废独立图表请求。

### 9.1 可观察失败和恢复路径

| 不支持语法/输入不完整 | 保留原文、安全源码入口；不截断、不删除、不阻止其他内容编辑 | 改源码/提供支持内样例；V-03/07 |
| 超限/生成资源失败 | 明确错误、原文/占位/拒绝；输入/输出/CPU/内存均受预算约束，不只是隐藏超时结果 | V-06 测限额及真实终止；减少输入或修改资源后重试，无自动有损截断 |
| 用户关闭/平台能力不可用 | 关闭用 §7 回退；平台失败显示真实可用状态，不能静默缩减 V1 并报通过 | 重新启用/修复原因；能力仍达不到基线须新产品决定；AC-11/16 |
| 过期/取消/目标关闭 | 不回填、不复活能力；活请求取消可见，已关闭目标不必 toast，但须结算资源/I/O | UI 验键；新请求独立，不能把取消报成功；P-T03/10 |
| 导出/剪贴板/输出发布失败 | 成功、失败、取消明确区分；无伪成功文件/勾号，不破坏原有输出或源文 | UI 单一发布；修正资源/位置/权限后新请求，覆盖授权重验；V-02/03/08 |

所有失败均保留当前输入、文档源码、选区/历史和仍被引用的恢复材料。正常基线夹具若只能回源码仍算能力未达标，安全回退不是完成证明。第三方异常隔离只能辅助资产边界，不能以 catch_unwind 代替引擎输入安全，也不能宣称所有进程崩溃均已隔离。

### 9.2 异步采纳与启停交错

依据[架构规范 §6～7](./architecture-guide.md#6-并发异步结果与任务生命周期)。UI 是唯一调度/采纳者；后台只拿不可变输入/私有任务数据，不捕获可变 Buffer 或另建运行时。

| 任务 | 必须校验的依赖 / 失效行为 |
|---|---|
| 解析扩展结果 | 文档/工作版本及解析配置代次匹配；集合变化后旧结果拒收 |
| 公式/Mermaid/高亮 | 目标存活、内容/语言、有效主题/背景及插件代次；off→on 后旧回调仍拒收 |
| 图片 tab | 资源身份、文件版本、路径代次、目标 tab 存活及预览能力代次；旧路径图不回挂，关闭预览不作废正文内嵌图片的消费者 |
| 导出/图表复制 | 对应 request_id、冻结输入/配置/资源、相关能力仍有效及目标授权；不能只用“当前文本 revision 相同”判断 |

关闭及取消发出后先撤采纳资格，实际计算/I/O 完成或确认停止并结算后才释放在途资源引用。资源由 UI 统一追踪当前文本、历史、恢复和任务引用；缓存淘汰、插件关闭和撤销插图都不能提前删除仍需的文件。文档/路径/窗口销毁的结算按架构及 V-08，不新设退出超时。

### 9.3 共享资源与失效

资产与布局缓存归相应 UI 服务，提供者可消费带键的只读结果，不各存竞争性权威缓存。语义高亮依赖内容/语言，配色另依赖有效主题；图表依赖主题身份**及内容版本**，公式依赖有效背景；图片依赖资源文件版本/路径代次。字体、宽度、缩放、软换行属于布局依赖。不能仅用 theme_id 或块下标判等。

内容/语言/路径/主题/配置/开关变化由状态所有者立即推进来源键并通知相关消费者，使用与回填时再验键；重算前不能以旧内容冒充成功。是否重解析依 §4.3 的真实语义依赖，不因每个开关强制重解析全文。跨文档共享可重建资产必须验证相同输入与环境，并保留各自采纳资格；一 tab 关闭不能销毁其他消费者仍引用的资源。缓存/并发/队列/时间/输入输出限额由 V-05/V-06 实测，不写旧 64 KiB 等猜值。
