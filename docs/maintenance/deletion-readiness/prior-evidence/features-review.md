## 5. 缺口、重复和替代关系

### 5.1 真实缺口

本轮未确认任何 D 类产品缺口，因而没有建议向 PRD 补写的新产品行为。检索和逐项比对覆盖旧文件 67 个复选项；对未逐字出现在 PRD 的内容，继续核对专项及其处置账本，而非直接判作遗漏。

特别复核的非缺口：

- 旧 HTML5/a互斥、实体与空白机制：引擎 §11.2 有有限算法候选及 V-07 金样；决策 D13/MIG-R01 已解释其效力，不需要恢复完整浏览器兼容承诺。
- 旧插件 catalog 注册和“语法后处理/扩展节点”：注册、文案、本期解析扩展边界已有架构/插件/引擎承接；未来动态 catalog ABI、具体类型/阶段不预建，不是遗失的当前产品能力。
- 旧未来 AI 提案 API：当前插件 §13/14 和 D21 明确移出 V1，通用受检意图/补丁约束保留；不申请重新纳入。
- 旧社区语言包、最近记录、B+：分别为未来候选或已明示可选；没有证据成为本期基线，不需要用户再次否决。
- 旧同步解析/后端/缓存：产品结果和实验责任存在；实现细节不要求在 PRD 重复出现。

### 5.2 重复内容

文件、双模式、命令、常见语法、图片、导出、主题、多语言及性能目标已在 PRD 有需求/AC；实现约束在当前专项有归属。继续维护旧 checklist 会产生第三种“空框进度”和旧默认口径，无法补足任何当前验收证据。它应作为迁移来源保留，不再更新为现行清单。
