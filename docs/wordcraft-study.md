## 3. 路线差异与明确不采用内容

| 方面 | WordCraft 观察/旧稿描述 | Aline 当前约束与处置 |
|---|---|---|
| 文档真源 | 多格式导入到内部样式化文档，Markdown 是转换格式 | 源文本唯一真源，Parsed 为投影；只用区间补丁，不走 AST → Markdown 全文重建。[引擎 §2/9](./engine-design.md)、AGENTS 铁律 2 |
| 解析 | 手写 CommonMark 子集、按行预处理并消费标记 | **不采纳其解析器**；唯一 pulldown-cmark，缺失语法在解析副本上作带来源映射的适配。[引擎 §6](./engine-design.md)、铁律 5 |
| 坐标/保真 | 未提供 Aline 所需的源码↔绘制映射；导入转换会改变表示 | 不能用“可见文本相等”代替映射/不可见源码保全；源码字节唯一持久坐标，绘制/UTF-16 经映射层，跨模块分型（RS-02）。[引擎 §7](./engine-design.md)、[Rust §5](./rust-style-guide.md) |
| 撤销 | Arc 共享的结构快照 | **不采纳快照 undo 替代补丁历史**；只读共享快照可用，物化成本待 V-05。不能由 Arc 便宜推断全部快照便宜，也不能断言补丁总比快照更省。[引擎 §4/9](./engine-design.md) |
| 渲染 | 分页布局、CPU 页光栅缓存、egui | **不采用页级缓存作为 Aline 既定结构**；采用 GPUI、变高块/源码行虚拟化，按真实依赖失效。通用缓存经验可改造，见 W5 |
| 全局/线程 | 导入诊断 thread-local，engine 恢复 worker | **不采用引擎线程和可变全局状态**；显式预算/诊断输入输出，UI 经 GPUI 执行器调度。零线程只约束五引擎 crate，不禁止宿主后台 I/O。[架构规范 §6](./architecture-guide.md) |
| 容错 | 命令 catch panic 后恢复结构快照 | 引擎生产受检错误/拒绝，用户输入永不 panic；资产隔离不等于命令回滚批准，WC-02已确认不新增通用catch。RS-03、S-7-06 |
| 保真量化 | 按格式估计保真百分比、流量权重、棘轮 | **不采用百分比替代字节级门禁**；未改原 bytes、改后仅显式补丁及 BOM/行尾例外。导出另验语法×格式矩阵，不以分数代替 AC-14 |
| 扩展范围 | Office 多格式导入、CLI/MCP、422 命令、密码保护 | **不因参考项目纳入 V1**；PRD §3/8、PA-01：六内置与未来外部方向，V1 无第三方加载/AI；不引入运行时/第二解析器/额外依赖 |

WordCraft 的不识别即文本策略只是保真动机的先例，不具备 Aline 的原 bytes 通道。它的 tab/CR/BOM 处理不可原样搬入 Aline 保存链。其密码 Debug 打码/zeroize（旧 `io.rs:66`）仅供参考，不形成 Aline 新增加密能力。

## 4. 按主题复核调研发现

### 4.1 解析、未知语法与双向映射

E02 的块起点判断说明独立扫描若误识别围栏/定义，会误删作者正文。Aline 已要求字面区避让、块+Gap 完整覆盖、隐藏定义仍有源范围（引擎 I-03/06、§6/11；R-12-01～04）。脚注/目录/Front matter 在 Aline 是灰色只读展示，仅源码可改；不能沿用 WordCraft 的脚注一律普通文本，也不能因可视化只读阻止源码编辑。其他未知语法显示原文，映射失败局部原文或整体源码回退，诊断与超限有区别。

E03 的预算、索引、失败记忆化适合 Aline 自研 pass、HTML 提取和着色扫描；不需重写 pulldown。旧“风险全在自研部分”“pulldown 已证明线性”缺乏本轮证据，第三方解析及输出增长同样须纳入 V-05/V-06。索引额外占内存且必须随输入身份失效，失败缓存也不能跨错误版本复用。4×输入≤8×耗时只能作回归信号，不能作为线性复杂度证明。

这些扫描技巧不能替代 sources 映射：转义、实体、合成片段、UTF-16 边界和源码隐藏区仍需来源金样、端点检查及版本绑定。任何局部解析或复用先与权威全量路径差分，远处链接/脚注/围栏依赖不能因头尾配对被漏掉（引擎 §12、R-12-04）。

### 4.2 格式化、转义与读回恒等

旧“V1 无导出、formatter 待定、M3 决定是否立项”已被 Q-02/Q-10 和 PRD FORMAT-01～02/EXPORT-01～06 替代。格式化已是基线：菜单手动全文触发、差异确认、版本复验、应用一步撤销；保存/切模式不触发，取消零修改。未知语法与 HTML 保留，无安全计划则拒绝；不能把整篇 AST 序列化当格式化实现。

E04 可作为规格测试输入：链接目标中的反斜杠/实体/尖括号；超过 64 个反引号的围栏冲突；行首 `#`/`>`/列表/主题线注入；强调边缘空白。**读回目标要按命令定义**：格式化保留要求的语义和源片段，不表示格式化后字节与格式化前相同；单看绘制文本也不够。通过同一解析器的语义检查、独立金样与源片段保护相互补充，具体风格/转义方案交 V-07。导出 PDF/.docx/HTML 的语义/资源保真另交 V-02，不能套 Markdown 回读判据宣称通过。

### 4.3 丢弃显式化与日志风险

E05 的收益是解释降级且防日志风暴。当前已采纳类型化诊断、保留源码/引用、安全入口及 UI 翻译（引擎 I-12/§13、R-16-02/03/07、S-7-07）；**WC-01已确认新增有归属/版本/容量/生命周期、按类去重的会话内存汇总**，由UI呈现，见PRD APP-06和第8节。

按已确认A，诊断须有文档/版本归属、容量和生命周期，不能保存正文/IME 候选、完整敏感路径或资源内容；不能把 thread-local 位图搬入引擎，不能为计数复制全文。降级记录不能变成“允许丢弃原文”的许可证，也不应让重复 toast 阻断输入。宿主在既有领域诊断之上维护内存汇总，关闭释放/版本变化不回填旧结果；不新增持久账本，容量和UI样本仍归V-06/09。

### 4.4 数据模型、快照、撤销与异常

E06 支持只读共享、避免每键全文复制的思路，不能证明某种 Arc 粒度适合 Aline。Aline 的 Buffer+唯一草稿、900ms 普通输入组、IME 独立确认、正逆补丁、保存内容身份和磁盘版本分别受 TA-01/TA-02、引擎 §8～10 约束。快照不封口、不改变历史；dirty 不能用栈深。旧恢复先 flush 并制造单步历史的说法已被替代。

旧 W8 在 panic 后只还原文本并 drop_open 会遗漏草稿、选区、redo、输入组、组合态、资源引用和已发起 I/O。受检预检/预演在真实写前运行，整批应用或拒绝已是当前基线。WC-02已确认本期不新增通用UI命令异常边界；不能借“最后保险”放宽引擎无 panic，也不能把第三方资产隔离条款扩大为通用回滚许可。

### 4.5 增量渲染与缓存

E08 项目文档报告 2026-10-06 对 188 页文档增量重排 1.4ms；本轮未复测，未提供可比设备/输入/计时边界，不能证明 Aline 的块复用路线或 GPUI 性能已达标。Aline 当前先全量正确、头尾配对复用派生块，使用前/回填重验实际依赖键；解析、布局、资产拥有不同失效因素。hash 命中不能代替内容正确性证据，缓存不能无上限。

主题、字体、宽度、换行、插件、路径/资源变化都要入失效样例；块虚拟化不能解决单个巨段/巨表。优化只有在等价性、失效正确性和 V-05/V-06 的 CPU/内存报告齐备后才可评价，见 R-7-01～03、R-12-04。

### 4.6 文件 I/O、原子保存与恢复

E07 证明的工程要点是先完成待写 bytes、临时文件独占创建、失败保护原文件和可检查的权限处理；**不是所有平台的断电/锁定保证**。其文档明确目录未显式同步，Windows/Linux 运行、ACL/扩展元数据、真实磁盘满/网络盘/断电尚未验证；并发独立保存最后成功替换者胜出，不等于冲突检测。

源码还有旧稿漏写的例外：同目录临时文件权限拒绝时，仅目标不存在可 `create_new` 直接新建，失败再清理；已有文件绝不原地覆盖。Aline 不据此新增直接写回退，仍遵守架构 §7.3 的受检替换/失败保全。权限复制不支持时的有条件继续策略已按WC-04 A确认，安全访问语义仍需平台证明，不能从 WordCraft 平移。

Aline 当前链路包括每文档串行写队列、写前内容版本校验、覆盖确认绑定版本、成功仅登记实际快照、冲突暂停自动保存、TA-02 可撤销载盘且磁盘基线不退。mtime/size 仅快筛，检查与替换仍有跨进程竞争窗口，V-08 需记录平台边界。BOM/有效 UTF-8/孤立 CR/行尾多数派和平票 LF 以引擎 §5 为准，不照搬多编码导入。

W3/W4 的阻塞工作由 UI 宿主经 GPUI 执行器调度，source 只给同步纯处理/受检 I/O 原语；不在 source/markdown 自建线程，不引入 libc/tokio。打开结果还要验证打开请求/目标身份，不能只验旧 buffer stamp。恢复属于独立写目标，仍使用相同版本/资源协议并结算关闭中的 I/O。

恢复最小安全闭环已在 M2，不能全推 M5。每 10 秒恢复与自动保存不同；当前快照不强制结束 IME 或制造历史，显式保存/另存为/导出按 ED-01 可取消等待平台自然结束。恢复记录须含身份、路径、存储元数据和可达临时图片清单，先资源齐备再发布；恢复先内存、不覆盖磁盘，损坏条目隔离。取消/失败/异常/已恢复未保存保留材料，当前/历史/恢复/在途任务仍引用的资源不得早删（PRD §5.12、R-15-08～12）。多条目可识别、提示恢复/丢弃已有 UI §12.3 承接；列表具体布局交 V-09，WC-05已确认不新增“全部丢弃”动作。

### 4.7 性能案例库与测量方法

旧案例按病因保留：#13 每段扫描全集合/两两冲突比对 → lookup+sweep（旧稿报告 32,000 个 content controls 保存约 4 秒→十分之一秒，非本轮实测）；#3692/#3708 每字符解析 → 按变更处理；#3713 每引用复制目标 → 共享与预算；#3411 逐文档重复查关系 → 从主文档已解析信息取；#586 恢复字节数组膨胀 → base64；未闭合括号 → 扫描预算/记忆化。除第 2 节注明的直接观察外，这些是旧稿转述，issue 编号只是追索线索，本轮未复现优化前后对比。
