## 0. 用途、范围与权威关系

本文规定本仓库 Rust 代码的工具链、模块组织、命名、类型、错误、所有权、测试、性能、安全、依赖与提交纪律，供实现、评审和后续 CI 接线使用。适用 `app`、`crates/*` 及其测试、示例和基准；尚未创建的路径是实施规划。

权威按职责划分：AGENTS.md 规定铁律和工作规则，当前 PRD 规定产品范围与结果，已确认架构及专项规范约束实现，验证计划记录方法、证据状态与待验证边界；决定记录和确认归档用于追踪选择，历史材料不自动取得规范效力，已删除目录不作开发必需输入。阅读顺序不是同级规范的裁决优先级；同级资料无法按职责解释的冲突须列出，不能按日期、文件位置或实现便利自行选择。TA-01～TA-03 和 PA-01 沿用既有确认；2026-10-29 用户确认本稿 RS-01～RS-05 与 ED-01 均采用建议方案 A，见[确认归档](./archive/2026-10-29-rust-style-decisions.md)。相关决定已回写引擎/架构/PRD，其它建议及技术参数仍不等于已冻结或验证。

AGENTS.md 的旧文档地图、“docs 优先”总述及旧章节号不能覆盖上述权威职责。Rust 规范不重定义 crate 所有权、编辑/保存事务、产品范围或主题 schema；这些内容分别由架构、引擎及专项文档负责。旧稿里的版本、API、强制标签和第三方成绩也不自动成为现行规则。

首轮迁移仅新增本文并更新 README；本轮依据用户确认回写规范、AGENTS.md 及受影响的 PRD/架构/引擎/验证入口，并将原问题保留于确认归档。不改 docs_bak、不创建代码或配置。具体类型与接口名称仍为契约示意，不代表已有实现。

## 2. 工具链、格式、lint、测试与 CI

### 2.1 已确定的检查命令

**S-2-01（本地门禁，C-01）：**M0 建立 Cargo workspace 后，每次 Rust 实现提交前按 AGENTS.md 执行以下完整命令；只跑单测不能代替它们：

```sh
cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
```

局部排错使用 `cargo test -p <crate> <test_name>`。`--all-targets` 覆盖当前目标的测试/示例/基准等 Cargo targets，不表示检查了全部 OS target；它也不穷举 feature 组合。`cargo test --workspace` 不等于执行性能基准、真实输入法或全部平台实验。

**S-2-02（环境可复现，C-01/C-07）：**依[架构 §3.2](./v1-architecture.md#32-栈与依赖的状态)，M0 记录实际 Rust/Cargo、edition、rustfmt/Clippy、GPUI 快照及平台补丁；本地和 CI 使用同一登记环境。工具链/依赖升级必须作为显式变更，记录版本、兼容影响及完整检查结果，不能让 CI 浮动升级后静默改写格式。若声明 `rust-version`，须验证该最低版本能构建相应目标，不能把它当当前工具链的锁定字段。

旧“最新 stable 自动跟进”“edition 2024”“rust-version 1.85”不作为已冻结基线。**建议**以满足锁定 GPUI 和平台要求的 stable 工具链为候选，edition 2024 作为候选；具体组合在 M0 构建中确定，不在本稿猜一个版本号。不能为导入排序单独引入另一套 nightly 格式化器。

2026-10-30 第 1 组实际取证：Rust/Cargo 1.98.1、edition 2024、rustfmt 1.9.0、Clippy 0.1.98 的 GPUI 0.3.9 核心库消费方在 macOS aarch64 构建、fmt/Clippy 与 test-support 编译检查通过；最小 edition 2015+async 反例被 E0670 拒绝。见[候选审计](./validation/m0-engine-foundation/admission-2026-10-30/report.md)。未声明或验证 MSRV；原生后端、正式八成员 lint/CI 和其它平台未验证。工具组合供第 2 组显式登记，不把候选消费方检查当作正式 workspace 门禁。

| 编号 | 强制要求及例外 | 检查 |

| S-2-05 | workspace lint 落地时须确认每个成员实际继承或具有可审查的等价策略；按引擎/UI/测试区分的规则不得靠一份无效的成员覆盖样例实现 | C-01/C-05：清单审查及能故意触发诊断的最小实验；检查目前尚未建立 |

旧附录 A 的 `imports_granularity`、`group_imports` 在复核时的[官方 rustfmt 选项表](https://rust-lang.github.io/rustfmt/)仍标为不稳定，本稿不沿用其配置片段；最终按锁定版本复验。workspace lint 是成员显式继承机制，根表的存在不等于每个 crate 已受约束，见 [Cargo workspace lint 文档](https://doc.rust-lang.org/cargo/reference/workspaces.html#the-lints-table)。成员差异应验证所选配置/源码属性确实生效，不照搬旧“继承后另加同名表即可覆盖”的写法。

RS-01 已确认逐项配置策略；`missing_docs`、`expect_used`、打印/调试宏、转换 lint 的具体配置级别仍须 M0 验证登记。公共 API 文档和受检转换的语义要求已生效。禁止从旧白名单照抄全局 `cast_possible_truncation = allow` / `cast_sign_loss = allow` 来绕过坐标检查。

### 2.3 CI 的要求与当前状态

**S-2-06（CI 与出口证据，C-01～C-08）：**M0 接入 CI 时至少执行 S-2-01，并逐步接入实际建立的依赖/GPUI 闭包、禁用依赖、引擎安全和 catalog 检查。相关实现的保真、映射、拒绝与状态机回归必须有可执行入口；失败不能仅靠更新金样消掉。尚无自动化的规则保留具体人工记录，不宣称已受 CI 拦截。

当前尚无应用工程的 workflow、Rust 检查脚本、hook 或依赖审计任务；现有文档/原型维护核对器不属于 Rust 实现门禁。旧附录 C 的 `macos-latest`、GitHub Actions 版本与缓存 action 均不复制为工程配置；macOS 作业不能代表 Windows/Linux 验证通过。按 V-01 先完成 macOS 验证，再验证 Windows/Linux，正式 V1 三平台门禁均须通过。CI runner、安装器和测试能力以实际矩阵登记。

`cargo audit` 是**建议**的后续依赖审计候选，不是当前必跑命令；安装、数据库、频率和失败处置尚未建立。旧 criterion/insta 命令也不进入现行门禁，见第 12/19 节。

## 3. crate、模块、文件与可见性

后续实现同时遵循 [OpenSpec 执行规范 §3～6](../openspec/CODE_STANDARDS.md)的模块职责/规模判断、抽象与设计模式记录及交付要求；其工程验收见[工程治理主规格](../openspec/specs/engineering-governance/spec.md)。这些补充不改变本章最窄可见性、八 crate、mod.rs 布局及行数仅作人工复核信号的规则。

职责和允许依赖边以[架构 §4](./v1-architecture.md#4-crate-图职责与公开边界)及[架构规范 §1～2](./architecture-guide.md)为准：

```text
app → aline-ui → aline-plugin → aline-edit → aline-markdown → aline-buffer
app / aline-ui → aline-source（独立；buffer 不依赖 source）
其余层按需 → aline-app-core（无反向业务依赖）
GPUI 仅允许：app / aline-ui / aline-plugin
```

| 编号 | Rust 侧要求及例外 | 检查 |
|---|---|---|
| S-3-01 | 五引擎 crate（source/buffer/markdown/edit/app-core）完整依赖闭包无 GPUI，签名/字段不泄漏实体、窗口或执行器；禁止反向依赖和借测试/feature 加边 | C-02：实际 Cargo metadata、`gpui-pre` package/别名及目标/features/dev/build 依赖审查；无窗口构建/测试 |
| S-3-02 | 模块、字段默认私有；同父模块内优先私有或 `pub(super)`，确需 crate 内消费用最窄可见性，`pub(crate)` 不用作跨 crate API；跨 crate 消费才用 `pub`，API 从 `lib.rs` 导出 | C-02：每个公开项标明消费方，检查有效可达性、导出与集成测试；不为测试暴露可变内部状态 |
| S-3-03 | 会破坏不变量的字段不直接公开可写；只读方法暴露必要视图。纯数据字段只有在所有组合都合法，或消费边界统一校验时才可公开 | C-02/C-03：构造/修改路径及非法输入用例；`Selection`、`Change` 等领域名本身不构成放行理由 |
| S-3-04 | 新模块注明职责、状态所有者、输入输出和消费方；新 crate 或依赖变化先记录架构影响，不自行扩展八 crate 边界 | C-02/C-08：架构规范 R-1-07；不按文件行数或目录美观自动拆 crate |
| S-3-05 | 文档写入仍经 DocCore 的受检入口，文件事务由 UI 协调器编排；禁止借 getter、内部 trait、闭包或 `pub` 字段暴露可随意写 Buffer 的通道 | C-02/C-04：调用链及公开可变句柄评审；不重新定义文件/buffer/主题/设置所有者 |

架构 §4.3 当前目录规划采用 `mod.rs`；新增嵌套模块沿此布局，若拟更换须同步说明架构目录影响。叶模块使用具名 `.rs`，不把“全用 mod.rs”误解为每个文件都要多建一层目录。

**建议：**一个文件聚焦一项职责及私有辅助类型；旧约 500 行只作为人工复核信号，不是 lint/CI 拆分门槛。文件排序可用 `//!` → imports → 常量/类型 → impl → 辅助函数 → tests，不为顺序制造无意义移动。

**建议：**显式列出导入名；测试模块可 `use super::*`。外部 prelude、宏生成或已有构建器 trait 导入如需通配，记录来源及消歧理由，不虚构 rustfmt 能禁止通配导入。

## 4. 命名与标识符

| 编号 | 强制要求 | 检查 |
|---|---|---|
| S-4-01 | 标识符英文；类型/trait/枚举变体用 `UpperCamelCase`，函数/方法/模块/变量用 `snake_case`，常量与静态项用 `SCREAMING_SNAKE_CASE`；crate 包名沿架构 `aline-*`，Rust 路径使用对应下划线名 | C-01/C-08：编译器命名 lint 加人工语义审查；外部 FFI 名称在最小适配层保留并说明 |
| S-4-02 | 源/绘制/UTF-16 偏移与范围显式区分，偏移变量禁裸名 `pos`、`idx`；相关版本、单位和快照归属能从类型/API 文档得知 | C-03：签名及运算审查，不靠全仓关键字禁令误伤一般集合索引或像素几何 |
| S-4-03 | 同一领域概念沿当前引擎/架构用词；不同身份不复用同一字段，例如 revision、draft_generation、request_id、路径代次不可统称 `edits` | C-02/C-04：版本/任务结果签名及失效用例 |

**建议命名：**只读 getter 用名词，不机械加 `get_`；布尔谓词用 `is_`、`has_`、`can_`、`needs_`、`should_`；事件入口可用 `on_`。`get` 若表示可失败查找应保留其查找语义，不为禁前缀改成含糊名。

转换区分借用视图 `as_`、生成目标值 `to_`、消耗所有权 `into_`；可失败转换用明确动词/`try_` 或 `TryFrom`，返回类型表达失败。不要用“as_ 一律零成本”承诺所有实现。迭代入口按所有权使用 `iter` / `iter_mut` / `into_iter`。

避免无语义缩写和 `Manager`/`Utils` 兜底命名；`src_off`/`drawn_off`/`utf16_off` 是铁律中的领域命名，允许使用。删除旧“源码位置用 at/offset 均可”和“一律禁 off 缩写”的相互冲突规则；普通集合索引可叫 `block_index`，像素可叫 `pixel_x`，不能把像素 `x` 禁令冒充源码约束。

## 5. 坐标、范围、版本与语义类型

| 编号 | 强制要求及边界 | 检查 |
|---|---|---|
| S-5-01 | 持久选区/补丁/历史均用所属源码快照的 UTF-8 字节坐标；跨模块/跨 crate 的源码、绘制、UTF-16 偏移与范围采用 newtype/受检封装（RS-02），禁止以类型别名充当分型；`drawn_off` 是投影 UTF-8 字节，`utf16_off` 是输入投影 code unit，不是字符/glyph 编号 | C-03：类型/签名/文档及中文、emoji、实体用例 |
| S-5-02 | 跨坐标转换只走 `Inline::source_at` / `drawn_at` / `aligned` 或同一映射模块的等价入口，含局部/全文和恒等路径；UI 不手算块起点差或自建 UTF-16 表 | C-03：调用点审查及 E-T04/05；映射内部可做受检运算。补丁后锚点变换归 buffer，磁盘/BOM/行尾转换归 source |
| S-5-03 | 所有外部范围验证 `start <= end <= len`、两端 UTF-8 边界、输入版本/投影身份；UTF-16 中间代理对拒绝。越界/过期不靠 clamp 或猜测映射成可执行删除 | C-03/C-04：空文本、末端、半字符、反向选区、过期投影及最大长度测试 |
| S-5-04 | 范围为半开区间；空范围可插入，不能把空范围当无效。补丁同基线、升序不重叠；同点多插入先合并为确定计划或拒绝；目标选区按 after 文本校验 | C-03/C-04：E-T03，批次末项非法时整批零修改 |
| S-5-05 | 坐标/长度/容量转换和加减受检：用 `checked_*`、`TryFrom` 或已证明边界，失败返回类型化结果；不以 `as` 截断、负数转无符号或饱和运算掩盖非法范围 | C-03/C-05：转换点审查与溢出/下溢夹具；像素/非坐标的有意钳位须单独写明语义 |
| S-5-06 | 映射返回来源、精确性、方向及版本语义；Hidden/Synthetic/多对一不能伪装精确编辑区间，失败保留输入并回原文入口 | C-03/C-04：实体/隐藏标记/合成换行、重复文本/多字符实体金样；不要求任意源码字节严格互逆 |

RS-02 已确认跨模块/跨 crate 坐标 API 强制分型，不等到 B+；偏移和范围使用 newtype/受检封装，构造入口验证边界、快照及投影身份。`type SrcOff = usize` 只是别名，不能阻止混用。模块内部单坐标计算允许明确命名的 `usize`/`Range<usize>`，来源和校验仍须明确。

AGENTS.md 规定的补丁存储形状 `Vec<(Range<usize>, String)>` 保持不变：只在该表示的受检边界转入/转出原生范围，并携带 Change 的版本/前置条件，不能将其当作跨模块裸坐标通道。本稿不冻结 `SrcOff` 等具体名称、底层整数宽度或类型归属；按现有依赖方向选定 home，不能让 buffer 反向依赖 markdown。

无论采用何种表示，裸整数不得充当“已校验范围”的证据。建议由构造/验证方法封装校验结果，字段私有，消费方重验版本；不得为增加 newtype 让 buffer 反向依赖 markdown。元组补丁的表示要求不等于允许裸 tuple 绕过 Change/事务元数据。

字符列/字素边界/像素是不同量；引擎中的纯 LineMap 或映射服务可持有行信息，不能照搬旧“行列号绝不进入任何引擎 API”的禁令。显示列按 V-07 的用户字符口径，不用 src_off 冒充。具体来源关系和合法锚点见[引擎 §7](./engine-design.md#7-源码绘制文本与其他坐标)。

## 6. 格式、表达与代码组织

| 编号 | 强制要求及边界 | 检查 |
|---|---|---|
| S-6-01 | 涉及命令覆盖、映射、渲染分派及 catalog 的封闭内部枚举，采用穷尽分支或会失败的覆盖检查；无语义兜底不得 `_ =>` 吞掉新增变体 | C-01/C-03/C-06：编译或覆盖测试，关联架构 R-2-04；开放插件提供者按能力校验，不枚举六个种类封死系统 |

rustfmt 处理空白与换行；默认行宽作为起点，不设人工“超 100 字符拒绝”门禁。复杂表达式可按命名责任拆开。大量转义时可用 raw string；用户界面文案仍经 catalog，不能因示例用了字面量就硬编码产品字符串。

## 7. 错误、Option/Result、拒绝与 panic

### 7.1 返回值与跨 crate 错误

| 场景 | 要求与边界 |
|---|---|
| 合法的“没有结果” | `Option<T>`，例如未找到命中、目标已释放；不能用 None 掩盖非法范围、I/O 或活动任务失败 |
| 可诊断失败 | `Result<T, ErrorEnum>`；引擎错误一律枚举，保留类型化原因及受检上下文；不以字符串比较驱动逻辑 |
| 命令不适用、受保护、版本失配 | 返回可区分的 EditRefusal/Changed 等正常领域结果；与 I/O、解码或内部缺陷区分，拒绝零副作用 |
| 取消、过期、目标关闭 | 显式结算为对应任务状态；可按契约无 toast，不能伪成功或覆盖新任务 |
| 可恢复解析/资产失败 | 原文/引用保留并给类型化诊断，按所属契约局部或整体降级；不是返回空文档 |

**S-7-01（错误协议，C-02/C-04/C-06）：**跨 crate 错误保留类别、来源及必要的偏移/版本/操作上下文；封装时不丢 source 链或分支信息。UI 决定交互及 `t("key")`，错误的 `Display` 不直接成为用户文案。引擎不携带已翻译文案或窗口通知；公开 Result 别名只有错误边界稳定时才引入，不强制每模块建立一个同名别名。

**S-7-02（拒绝契约，C-04）：**不依赖 `Result::Err` 的惯常失败处理把拒绝升级成系统异常；调用方须能区别拒绝、失败、取消、过期。具体可采用独立 outcome 枚举或清晰分层返回类型，不在本稿冻结 enum 布局。拒绝比较调用前后的文本、草稿、组合、选区、undo/redo，无空历史步、不清 redo；`reread` 必须在真实写入前。

旧“需要用户决策的失败不走 Result，只走事件”删除：写盘冲突可类型化返回再由宿主提示。旧“所有 Err 都需要日志/弹窗、拒绝一律静默”也删除，呈现按产品严重度，不能吞掉需说明的命令拒绝。

**建议：**错误实现可先手写枚举与 `std::error::Error`；`thiserror` 是减少样板的候选，`anyhow` 仅作为 UI/app 不需模式匹配的最终上下文汇聚候选，均须按第 15 节准入。UI 仍需识别的 Conflict/Cancelled/Refusal 等不得先擦成动态错误。库选择属于实现验证，不另造产品待决题，不预装日志库。

### 7.2 panic 与断言边界

| 编号 | 强制要求及例外边界 | 检查 |
|---|---|---|
| S-7-03 | 五引擎 crate 禁 `unwrap()`，包括新增测试、示例和基准；不以 `cfg(test)` 放宽铁律 | C-05：Clippy 候选 `unwrap_used` + 源码/宏展开入口审查；无论 lint 是否覆盖都须满足。测试可返回 Result 并用 `?` |
| S-7-04 | 用户输入、文件、主题包、剪贴板、外部资源及其派生范围不得走 `expect`、`panic!`、`unreachable!`、失败断言、未受检索引/切片等 panic 出口；不以“应该合法”作证明 | C-03/C-05：逐路径评审、非法输入/敌意/预算用例；不因测试中运行而放宽被测代码 |
| S-7-05 | `debug_assert!` 只校验内部已建立不变量，不能替代运行时输入检查；先受检返回错误/拒绝，再断言内部表示。不得在断言条件里放必要副作用 | C-03/C-05：debug/release 路径审查及测试；内部已验证范围可索引，但要能追溯证明和版本 |
| S-7-06 | 不用 `catch_unwind` 替代引擎正确性/资源限制；WC-02已确认V1不新增通用UI命令panic捕获/回滚；第三方资产隔离若需要异常边界，失败产物隔离且不改文本，仍验证输入预算与终止策略 | C-05/C-07：异常/超限出口，关联引擎 E-T16 与 V-06 |

**RS-03 已确认：**引擎生产代码不使用 `expect` / `panic!` / `unreachable!` 或发布期保留的 `assert!`（含 assert_eq!/assert_ne!）退出，内部缺陷也以受检错误/拒绝 + `debug_assert!` 表达。测试的预期断言允许；测试夹具与 UI 初始化确需上述操作时，逐处证明不由外部输入触发、失败影响可控，并按第 16 节记录最小 lint 例外。引擎测试/示例/基准仍禁 unwrap；例外不允许用户输入路径 panic，也不构成引擎生产 expect 白名单。该要求纳入 S-7-04 的 C-05 审查。

`unwrap_or_default()` 仅在缺省值确为合法契约时使用；失败不得转空字符串、零偏移或空文档。忽略 Result 必须有明确“已关闭/预期过期”等依据并结算相应状态，禁止活任务 `.ok()` / `let _ =` 吞错。

### 7.3 日志与提示

**S-7-07（诊断归属，C-05/C-06）：**下层返回结构化错误，宿主负责最终记录/提示，避免每层重复 error + toast；引擎不初始化日志器、不读全局日志状态。默认日志只记文档/任务身份、版本和错误类型，不记全文、IME 候选、隐私资源内容或完整敏感路径；必要片段须最小化并说明用途。用户提示均翻译，技术诊断文本不能成为机器协议。

WC-01已确认宿主维护有会话/文档/版本归属、去重/容量/生命周期的内存汇总；纯引擎仅返回结构化诊断，不持thread-local/全局集合，隐私与版本失效按架构R-16-09/V-06/V-09检查。

## 8. 所有权、借用、集合与分配

| 编号 | 强制要求与边界 | 检查 |
|---|---|---|
| S-8-01 | 只读输入优先使用能表达所需能力的借用；需要拥有/跨任务存活时显式转移或建立不可变快照，不用延长生命周期/泄漏内存回避所有权 | C-02/C-08：签名及数据生命周期评审；容器自身能力确有需要时可接容器引用 |
| S-8-02 | 不为绕借用检查复制第二份可编辑全文、添加全局单例或 `Arc<Mutex<DocCore>>`；快照、存储原 bytes、冻结导出、唯一草稿按架构归属保留 | C-02/C-04：可写句柄与来源身份审查；不是禁止 UI 出现任意 String |
| S-8-03 | render/布局不反复物化全文 String/Vec；热路径新增深拷贝/收集须说明规模、频率和必要性，并在相关性能变更中提供 V-05 证据 | C-07：分配随全文/可见范围的增长、巨型单块及冷/热数据；局部可见几何分配不一概禁止 |

**建议选择：**文本只读用 `&str`，序列视图用 `&[T]`，平台路径用 `&Path`，取得所有权时用具体拥有类型；`impl Into<T>` / `AsRef<T>` 只在调用方确有不同输入形式时使用，不要求所有拥有参数泛型化。`Range<usize>` 按值/借用依实际消费决定，删除旧“永远不得借用 Range”的规定。

| 类型 | 建议使用条件与复核点 |
|---|---|
| `String` / `Vec<T>` | 单一所有者的连续数据；clone 是复制，确认大小/频率；可估上界时预留容量，先受检预算再分配 |
| `Rc<T>` | 仅在单线程确有多个只读持有者时；不能进入要求 Send 的后台捕获 |
| `Arc<T>` | 跨任务共享不可变快照的候选，不强制 Parsed 一律 Arc；引用计数 clone 有原子计数成本，也会延长资源生命周期 |
| `Cow<'a, T>` | 常见借用、少数需拥有且能减少复制时；不为省一次复制扩散复杂生命周期 |
| `Box<T>` / `Box<dyn Trait>` | 递归/尺寸或已确定的动态分派边界需要；不是规避所有权的默认容器 |
| `HashMap` / `BTreeMap` / `Vec` | 按查找/有序遍历/连续访问需求选；若结果需确定顺序，显式排序或用有序结构，不依赖 HashMap 遍历顺序 |

删除旧“SharedString/Entity/Arc clone 免费”条款；各 GPUI 句柄 clone 的语义按锁定实现核验。[标准库 Arc 文档](https://doc.rust-lang.org/std/sync/struct.Arc.html)说明共享所有权与原子计数，不能据此承诺零成本。保留强句柄还可能导致生命周期错误，见第 13 节。

**建议：**循环拼接用 `push_str` / `write!`，需要物化才 collect；迭代器并非自动更快。派生 `Debug`/`Clone`/`PartialEq`/`Eq`/`Hash`/`Default` 按实际语义，不默认全派生；带敏感内容的 Debug、昂贵 Clone、没有合法默认态的 Default 必须单独审查。

## 9. 泛型、trait、动态分派与宏

**建议：**从具体类型开始；同一行为出现第二个真实消费方时再提取共享抽象。已确定的 Buffer 替换边界、宿主平台服务注入、可测试时钟/磁盘缝、插件能力契约可以先定义 trait，不要求为了满足“两个实现”制造假实现。

| 编号 | 强制要求及边界 | 检查 |
|---|---|---|
| S-9-01 | trait、泛型及回调不绕过所属状态所有者/命令入口，不向引擎泄漏 GPUI；公开 trait 说明实现者、对象安全需求、错误与线程约束 | C-02/C-08：签名和实现方审查、公共 API 集成用例 |
| S-9-02 | 插件公共能力不与六内置实现硬绑定，也不把 `dyn Trait` / Rust 布局视为未来外部分发 ABI | C-02/C-06：独立测试提供者和 PA-01 边界；不预建动态宿主 |
| S-9-03 | 自写宏须保持调用点可检查的控制流/失败路径，不隐藏 unwrap、线程、全局状态或不受检转换 | C-05/C-08：宏定义及代表展开审查；派生宏也核输入和依赖来源 |

静态分派、动态分派按可替换性和实际成本选择，不沿用旧“dyn 只能用于注册表”的绝对禁令。引擎热路径引入动态分派要附测量理由，不能仅凭风格偏好宣称慢。sealed trait 仅用于确实不允许外部实现的契约；开放提供者不能为省兼容工作直接封死。`#[must_use]` 用于忽略会丢失计划/校验结果的值，不能代替处理 Result。

## 10. unsafe 与平台互操作

**RS-04 已确认：**本仓库自有代码默认 `unsafe_code = "forbid"`。真实平台互操作确需 unsafe 时，另提最小例外方案，记录必要性、所属 crate/模块、有效 lint 配置、保留其余 lint 的方式及验证，经明确例外裁决和独立安全评审后实施。本次同意 forbid 基线不自动批准未来例外。旧“依赖都是纯 Rust，因此无需 unsafe”没有证明力；Rust 依赖可含 unsafe/FFI，下游 unsafe 不是自有代码的许可。配置尚待 M0 创建与验证。

**S-10-01（unsafe 证据，C-05/C-08）：**任何拟新增 unsafe 必须先提交安全 Rust/已有安全封装不能满足的原因、最小隔离边界、调用方前置条件、所有权/生命周期/线程要求和验证方案。未获具体例外批准前不得引入平台 unsafe/unsafe impl 或放宽 lint。获准例外后，每个 unsafe 操作以中文 `// SAFETY: …` 写明前置条件如何成立，公开不安全 API 说明调用者义务；不以“已经检查过”空注释代替证据。

获准后的 unsafe 集中于最小适配边界，对外提供受检安全 API，危险边界独立评审；测试包含错误长度、空/失效句柄和释放顺序，纳入 S-10-01 检查。Miri/sanitizer 等如适用再登记验证，不宣称 GPUI/平台代码都可在其中运行。

`forbid` 与 `deny` 的差异必须在配置设计时处理：前者不能由内部 `allow` 降级，不能沿旧文用“模块内 allow”打开例外；也不能通过取消成员继承悄悄丢掉其余 lint。规则语义见 [Rust Reference](https://doc.rust-lang.org/reference/attributes/diagnostics.html#lint-check-attributes)，最终用锁定 Cargo/rustc 验证配置。第三方 unsafe 风险另随依赖准入审查，workspace lint 不代表审计了依赖源码。

| 字节保真 | UTF-8/BOM、统一/混合行尾和平票、孤立 CR、无末尾换行；未编辑逐字节相同，编辑只动补丁及行尾例外 | E-T01/02，SAFE-01～03，AC-01/02，V-06/07 |
| 补丁/历史 | 随机合法批次及逆补丁恢复 bytes/选区；末项非法整批拒绝；900ms/IME 组、快照不封口、同深分支保存点、可撤销重载且基线不退 | E-T03/06/07，TA-01/02，AC-03～06，V-07/08 |
| 映射/Unicode | 原样边界往返、规范锚点稳定、对齐幂等、来源及精确性；隐藏/合成/实体/重复文本、UTF-16 代理对/字素 | E-T04/05，AC-03/09，V-01/07 |
| 解析/保护/命令 | 块 + Gap 覆盖、字面区避让、HTML/未知源码保留；拒绝完整状态不变，MD-11 所有写入口保护；命令输入→补丁/选区金样 | E-T08～13，AC-04/08/09/17，V-03/07 |
| 复用/异步 | 与全量权威结果差分、复用后坐标重定位、乱序/取消/关闭和配置变化不采纳旧结果 | E-T14/18，架构 K-04/06，V-05/07 |
| 敌意输入/资源 | 深栈、巨段/巨表、未闭合 HTML、无效资源，预算内终止且不 panic/截断/半提交 | E-T16，AC-16，V-05/06 |
| 集成/产物/平台 | 文件失败/恢复/临时引用、多窗口与路径竞争；真实 IME、主题、PDF/.docx/HTML 与安装矩阵 | 架构 K-04～07，AC-05～07/10～16/18～20，V-01～09 |

保真是发布门禁，不能仅比较可见字符串。映射不使用 `source_at(drawn_at(x)) == x` 对所有源码字节断言；实体内部偏移没有该双射。拒绝不能只断言文本没变，还须比较草稿、组合、选区和历史。增量优化要对权威全量路径做差分，不把“只跑修改块”作为正确性证据。

**建议：**属性测试保存最小失败样例/可重现 seed；proptest 是历史候选，不要求每个 crate 为形式引入它。快照适合复杂结构回归，更新须人工审查语义差异；insta 尚未准入，`cargo insta review` 不是当前命令。基准可在 `benches/`，criterion 只是候选。GPUI `TestAppContext` 须先核锁定版本/feature，纯状态机模拟、GPUI 交互与真实系统输入法验证分别报告。

## 13. 并发、GPUI、锁与运行时

| 编号 | 强制要求及边界 | 检查 |
|---|---|---|
| S-13-01 | 五引擎 crate 不 spawn 线程/任务、不持共享可变锁、不访问 UI 全局、执行器/计时器；同步计算及 source 受检 I/O 原语由宿主调度，显式接收预算/时间/配置 | C-02/C-05：依赖/调用及无头测试；引擎不能用“封装在工具函数”绕过零线程 |
| S-13-02 | 引擎无运行期全局状态，包括 `static mut`、隐藏 `OnceLock`/`LazyLock` 注册表、全局 locale/缓存；编译期不可变实体表或常量允许 | C-02/C-05：状态创建/访问点审查，不能仅按语法扫所有 static 一律报错 |
| S-13-03 | 重任务由 UI 使用锁定 GPUI 能力安排，返回后验证目标存活及相应文档/工作/请求/路径/配置身份；不从后台直接改文档/窗口。ED-01 已确认：组合期显式保存/另存为/导出请求可取消地等待平台自然结束组合，再取当前快照；取消请求不改输入/历史，不伪造确认或发布候选 | C-04：乱序、关闭、取消、路径变更与配置切换用例；不同任务按架构 R-6-05 分类采纳，V-02/V-07/V-08 验组合确认/取消及取消请求 |
| S-13-04 | 跨实体回调/订阅不能意外强保活目标或形成引用环；声明拥有者、取消/释放点，关闭后安全结算，不用 `.ok()` 吞掉活任务失败 | C-04/C-05：句柄图、关闭后回调及资源释放测试；WeakEntity 等具体 API 按锁定版本，不一概禁止合理拥有关系 |
| S-13-05 | UI/plugin/app 若确需锁，先说明共享所有权不可替代的原因；锁内不做 I/O/解析/渲染、不跨 await、不调用外部回调；如必须多锁，须有固定锁序及竞争证据 | C-04/C-08：临界区/死锁/取消评审。此项不为引擎持锁开例外 |
| S-13-06 | V1 禁用 tokio、notify、regex、Wasmtime/WASI、动态插件宿主；仅允许架构 §3.2 已批准的 GPUI 0.3.9 精确例外，五引擎、自有直接及其它引入路径继续禁止；不以平台/测试/构建路径绕过，也不因 GPUI 某 API 不便自行加入另一运行时 | C-02：完整图与分 target/features 的实际 tree 交叉审查、全入边/路径及身份/校验和核对；未经批准的新路径/漂移/解析失败均不通过 |

**建议：**先用所有权/事件传递，确需共享再评估锁；不普遍规定 Mutex/RwLock 二选一。后台捕获最小不可变数据，`Send`/`Sync` 约束按实际跨任务边界，不到处添加，也不写不安全 impl 绕过。

旧异步“三件套”的 `spawn(AsyncFnOnce(...))` / `background_spawn` / `weak.update`、`InputComposition` key、text input configuration 接口来自 Zed 主线证据，不能写成当前 gpui-pre 可直接编译的强制签名。IME 使用统一映射/输入状态机、不伪造确认/取消；平台调用和生命周期核验属 V-01/V-07，见[历史 Zed §0](./archive/migration-evidence/zed-notes.md)。

## 14. 性能、缓存与内存预算

| 编号 | 强制要求及边界 | 检查 |
|---|---|---|
| S-14-01 | render/布局、按键/选区移动等高频 UI 路径不做全文解析、指纹/等价比较、统计、序列化、配置读取或文件 I/O；不同步解码资源 | C-07：调用链与 V-05 分段测量；提交触发昂贵计算仍由所有者按预算调度 |
| S-14-02 | 缓存有明确所有者、实际输入/环境键、失效触发和预算；使用/回填重验键，不以帧数/时间、notify 或未核验 hash 作为内容正确性的证明 | C-04/C-07：架构 R-7-01～03，主题/字体/路径/插件/草稿变化用例；不强制一律全文 hash |
| S-14-03 | 性能变更提供正常/极端样本、锁定版本、设备/OS、Release、冷/热、计时边界、P50/P95、最长 UI 停顿和内存；优化通过正确性回归，不以删功能换达标 | C-07：V-05 报告；局部微基准不代替输入至呈现，排队不得隐藏 |
| S-14-04 | 分配/扫描/构树/解压/解码前及增长中检查预算，超限保留源码/恢复路径，不截断或部分发布；取消须有实际资源限制，不能只隐藏结果 | C-05/C-07：V-04/V-06 故障/超限，巨型单块不能靠块虚拟化豁免 |

PRD §7.2 的文本处理和块提交预算是目标，不是 Aline 成绩。同步 128 KiB、全文防抖 300ms、40rem overdraw、零分配缓存命中、回归 10% 等历史说法不冻结；MD-05 公式/图表的 300ms 预览与全文解析防抖不同。资源/历史/缓存限额待 V-05/V-06。

删除旧“release 开 overflow-checks 就保证偏移安全”的推论；该开关会改变溢出故障表现，不能替代 S-5-05 的受检错误。是否启用作为 M0 profile 验证事项，不能用它放宽无 panic。**建议：**定位热点再用 `partition_point`、预分配或 `#[inline]` 等手段；二分必须先证明排序前提。扫描复杂度用步数/规模曲线辅助验证，不把每个操作都强制“一趟过完”。

## 15. 依赖准入、版本与提交

### 15.1 依赖

**S-15-01（准入，C-02/C-08）：**新增/升级依赖先对照[架构 §3.2](./v1-architecture.md#32-栈与依赖的状态)、[引擎 §18.2](./engine-design.md#182-依赖准入与未解决实现风险)；[历史依赖清单 §2.12](./archive/migration-evidence/engine-design.md)仅作候选来源证据。变更记录列用途、所属 crate、为何不能复用、精确解析版本/源码来源、许可证、features/目标及直接/传递重叠、构建/运行风险与 V 证据。未使用的候选不预装。

**S-15-02（单一技术栈，C-02）：**仅 pulldown-cmark 解析 Markdown，不引第二解析器；同类功能不得第二库。GPUI 全 workspace 单一来源精确锁快照，升级记录补丁及平台影响；历史 `=0.3.9` 本身不构成冻结证据，本次按架构 §3.2 的实际审计登记，正式 workspace 锁定于第 2 组核验。第三方版本集中根 workspace、成员继承，应用 Cargo.lock 随实际依赖提交；仅有 lockfile 不能证明 GPUI 来源唯一。

禁用库按 S-13-06 检完整图；2026-10-30 用户批准的 GPUI 例外以架构 §3.2 的精确清单和[审计身份](./validation/m0-engine-foundation/admission-2026-10-30/gpui-package-identity.json)为准。正式锁文件可新增合规节点，不得让新路径借用既有 GPUI 例外；metadata 未实际选中的过近似路径须留证而非扩张例外。发现其它传递依赖冲突须解决或提交上游裁决，不能以“我们没 import”忽略。导出/ZIP/平台与 Unicode 分段等新依赖分别按 V-02/V-04/V-01/V-07 收口，不照搬旧调研“无 ZIP/无导出”的风险判断。

**建议：**审查维护状态及公开安全通告；工具审计覆盖不了功能重复和架构反向边。普通升级显式登记并回归，若改变铁律/产品边界先裁决；本仓库尚无依赖审批机器人或既定自动审计流程。

### 15.2 提交与变更说明

**S-15-03（提交，C-01/C-08）：**使用 Conventional Commits，涉及单一 crate 时 scope 用完整 crate 名：

```text
feat(aline-markdown): 为改写片段保留源码映射
fix(aline-edit): 拒绝跨只读区域的替换
test(aline-buffer): 覆盖同栈深历史分支的保存点判定
```

**建议类型：**`feat` / `fix` / `refactor` / `perf` / `test` / `docs` / `chore` / `build`；一个提交表达一个可审查意图。变更说明给出原因、相关 S/R/需求/AC/V 编号、检查结果及未覆盖范围。Rust 实现提交前执行 S-2-01，纯文档提交检查链接/一致性并注明未运行 Cargo 的原因。

RS-05 已确认有限真实 scope：纯文档用 `docs`，workspace 工程配置/公共工程规则用 `workspace`，应用包使用 M0 实际 package 名（若为 `app` 则用 `app`）；单 crate 保持完整 crate 名。跨 crate 的必要原子变更用主责 crate scope，正文列其它影响范围；如无单一主责且属于公共工程配置则用 `workspace`，不以省略 scope 规避归属。新增非 crate scope 须显式更新范围约定，不能随意扩散；不为格式拆散一个必要事务。本轮未创建提交。上述范围要求与 S-15-03 一同检查。
