## 2. 目标、非目标与不变量

基线是点击块编辑、标记低对比度显示、Visual/Source 共享文本与历史。打开块可保持打开，按 900ms 连续相邻输入组提交，IME 确认独立成组；离块只处理剩余组。折叠标记增强不是 M5 任务或发布前提。

引擎不负责像素布局、窗口焦点、磁盘写队列、资源复制、设置页面、主题安装或导出文件发布；不实现第二个 Markdown 解析器、AST → Markdown 全文序列化、WebView、Split/Preview 模式、PlantUML、远程图片请求或 V1 外部插件加载。

| 编号 | 必须保持的不变量 | 证明入口 |
|---|---|---|
| I-01 | Buffer 的已提交源码 + 唯一受控草稿构成当前内容；Parsed、展示树及资产都是不可变投影，无反向序列化写回 | E-T02、E-T06 |
| I-02 | 内容变化仅由 `Vec<(Range<usize>, String)>` 表示；同基线预检、整批应用或整批拒绝，普通块输入组只产生单区间提交 | E-T03、E-T06 |
| I-03 | 块可编辑范围排除尾部换行；顶层块和显式 Gap 共同完整覆盖源码，嵌套节点范围包含于父范围 | E-T02 |
| I-04 | 唯一持久坐标是相应源码快照的 UTF-8 字节边界；跨模块/跨 crate 的源码、绘制、UTF-16 偏移和范围以 newtype/受检封装区分，转换均经所属映射层 | E-T04、E-T05 |
| I-05 | 未修改往返原 bytes；编辑不改无关源码，只允许明确的补丁与约定的存储行尾例外；不隐式补末尾换行 | E-T01、E-T02 |

“零全局状态”不禁止编译期不可变实体表，禁止隐藏的可变注册表、`OnceLock<HashMap<…>>` 等运行期共享状态；需要的配置、预算和索引由调用方显式传入。`debug_assert!` 用于实现内部已建立的不变量；用户提供的范围、字节和资源必须返回受检错误，不能靠断言拒绝。

## 3. crate 与宿主边界

依赖方向沿用架构 §4：`app → aline-ui → aline-plugin → aline-edit → aline-markdown → aline-buffer`；允许沿链使用下层公开 API。`aline-source` 独立，由 ui/app 调用，buffer 不依赖它；`aline-app-core` 是可按需依赖的零 GPUI 基础层。只有 app/ui/plugin 允许 GPUI。

| 所有者 | 最小输入与输出 | 不承担的工作 |
|---|---|---|
| source/decode、encode | 原 bytes → 有效源码与存储元数据；冻结源码 + 基线 → 待写 bytes 或错误 | 不持有 Buffer、历史、IME，不调度保存。受检 I/O 原语虽也在 source，文件事务由架构 §7.3 管 |
| buffer/patch、history、selection、anchors | 合法源码快照、补丁批次、源选区 → 新 revision、逆补丁及位置变换 | 不解析 Markdown，不理解保护区或磁盘路径，不调用 source |
| markdown/pre、build、tree、protection | 源码快照、解析配置、预算 → Parsed、映射、语义/保护范围及诊断 | 不创建线程，不认识 GPUI、主题颜色或插件注册表 |
| edit/command、check、find、tables、formatter | 当前快照 + 匹配版本 Parsed + 源选区 + 命令 → Change 或 EditRefusal | 不自行写 Buffer/磁盘、不弹差异对话框、不调用执行器 |
| app-core | 显式 settings/locale/token 数据及校验结果 | 不存全局当前语言，不引入 GPUI 字体/颜色类型 |
| ui/document 的 DocCore | 唯一可写 Buffer/History、OpenBlock、组合状态机和当前快照；串行采纳 Change | 不让子输入控件另建文档历史；跨模块编排状态可由无窗口驱动测试 |
| ui/editors、render | 像素命中、平台 UTF-16 回调 → 映射 API/输入状态机；语义 token → GPUI | 不在回调中自行减块起点、重建 UTF-16 表或直接套旧源码范围 |
| plugin + ui/assets/export/resources | 源范围/冻结快照 → 资产、意图或产物；宿主校验/调度/落盘 | 不绕过补丁、保护、版本及文件事务；内置 trait 不是外部 ABI |

解析扩展契约定义在 markdown 的纯数据 API，由宿主注入配置快照；不要求 V1 运行任意插件解析代码。PA-01 已确认未来外部接入方向，加载环境、权限和阶段另行设计，不能恢复旧 Wasmtime/WIT/tokio 路线。

**2026-10-31 M0 接口基础记录（任务 3.3）：** 与本任务八接口相关的已落地公开面包括 source 的只读 `StorageSnapshot`/`StorageRange`/`BaselineId`/`DiskVersion`/`StorageBudget`、buffer 的 `TextSnapshot`/`SrcOffset`/`SrcRange`/`SrcSelection`/`DocumentRevision`/`CheckedBatch` 及预算/错误类型、markdown 的恒等 `Projection` 与坐标/预算/错误类型、UI 的 `DocumentId`/`WorkingVersion`/`InputIdentity`；app-core 的 catalog 与 app 的 `ExitCode` 入口不属于八接口（完整公开面见 3.3 记录第 2 节）。`decode`/`encode` 与最小写盘原语未实现，buffer 不 apply，edit/plugin 无公开接口，DocCore 未实现。上表中各所有者的输入输出是已确认契约，不是已实现能力。完整冻结与消费者追踪见[任务 3.3 记录](./validation/m0-engine-foundation/group-3/step-3.3/report.md)。

## 4. 核心模型与版本

### 4.1 数据所有权

| 概念 | 最小语义与不变量 |
|---|---|
| `SourceBaseline` | 原 bytes、对应解码源码的只读身份、BOM、LF/CRLF 计数、选定行尾策略及磁盘内容版本；是存储基线，不是第二份可编辑文本 |
| `SourceSnapshot` | 不可变 UTF-8 源码视图 + 输入版本。建议用共享存储或分片视图，是否物化 String 由 V-05 决定，不在每键复制全文 |
| `DocumentRevision` | 已提交内容变更的单调代次；Undo/Redo/重载同样前进，不能用历史游标倒退代替 |
| `OpenBlock` | 基线 revision、受检源范围、基线片段、唯一草稿及 `draft_generation`、源码选区、输入组状态；表格单元格也是同一打开槽位 |
| `WorkingVersion` | `(DocumentRevision, draft_generation)`；标识 Buffer 加草稿的当前逻辑文本，组合更新/取消也必须使相关结果作废 |
| `Selection` | 源码 anchor/head、方向和所属版本；V1 单选区，跨块仍是文档级一个选区。视觉列记忆是布局提示，不是另一种源码坐标 |
| `Parsed` | 对应快照/配置代次、带范围语义树、顶层块及 Gap、展示节点、映射、保护区、导航索引、降级诊断；不允许独立可变的 `Parsed.text` 真源 |
| `Block` | 编辑单元的源范围、语义 kind、展示及映射引用；表格/列表内部节点可嵌套，不将所有后代当顶层平铺 |
| `Inline` | 绘制文本、以 drawn 字节表示的语义样式/链接区间、到源码的片段关系；不包含 GPUI 颜色或实体 |
| `Change` | 预期工作版本、同基线补丁、预期源片段/语义前置条件、目标源选区、操作/历史分组原因；不是裸 tuple |
| `HistoryStep` | before 源码坐标的正补丁、after 源码坐标的逆补丁、前后源选区与内容身份、分组原因；选区恢复方向不能丢 |

`DocumentId`、路径代次、`DiskVersion`、解析配置代次、查询代次和任务 request_id 各有含义，不能复用一个 `edits` 计数器。需要跨快照移动的锚点经过 buffer 的补丁位置变换；未经变换的绝对偏移只对原版本有效。

`draft_generation` 必须在同一 revision 下避免重用：组合取消后文字虽恢复，也不能让旧结果再次命中；可采用文档会话内单调草稿代次。输入映射另带投影身份（Source/具体打开块与局部范围），不能仅凭相同全文版本把上一块的 UTF-16 局部映射用于下一块。

### 4.2 块、间隙与保护范围

顶层内容区间是半开区间，范围端点必须为 UTF-8 边界。块末属于分隔的换行独立记为 Gap；块内列表/代码/HTML 的内部换行仍属于块内容。空行、引用定义和只产生隐藏展示的文本也不能从源码覆盖账本中消失。

例如源码 `甲\n\n乙` 的顶层覆盖为 `Block(0..3)`、`Gap(3..5)`、`Block(5..8)`，直接拼两个 Block 不等于全文。空文档可没有真实 Block，由 UI 用映射层提供的文档起点锚定空输入入口，不能伪造越界块。结构命令需要增删分隔时必须显式规划 Gap 补丁；普通块输入组不隐含拥有尾换行。

保护范围包含 Front matter、目录/脚注内容和脚注引用；HTML 区域、代码、公式、未知/降级片段另有语义身份与命令能力。保护不是布尔的“全部只读”：MD-11 可视化内容修改拒绝，Source 可改；HTML 可原始编辑但格式/块命令拒绝。原始语义范围不能因展示树合并为 Paragraph 而消失。

脚注引用可嵌在普通段落内；不能因一个引用就把整段正文变成只读。建议打开该段的源码输入投影并保护引用子区间，其余正文可改；输入规划使用字符边界安全的共同前后缀收窄单区间补丁，使未变的保护片段不被整块替换范围误判为修改。若实际删除、插入或粘贴的作用范围触及保护子区间，仍必须拒绝并定位 Source；不能只比较编辑后引用字符相同就放行跨保护区操作。直接修改引用或定义统一切 Source，具体边界插入样例归 V-07。

**2026-10-31 M0 接口基础记录（任务 3.3）：** `SourceBaseline`、`Parsed`、`OpenBlock`、`Change`、`HistoryStep` 仍仅契约未验证；已落地的包括 `TextSnapshot`、`SrcOffset`/`SrcRange`/`SrcSelection`、`DocumentRevision`、`CheckedBatch`、`StorageSnapshot`、恒等 `Projection` 与 `InputIdentity`（`WorkingVersion` 是 `InputIdentity` 使用的身份类型）。块、Gap、保护范围及其金样留第 6 组；本记录不把上述任何模型写成已完成。详见[任务 3.3 记录](./validation/m0-engine-foundation/group-3/step-3.3/report.md)。

## 5. 文件文本进入引擎与存储保真

### 5.1 解码与坐标边界

source 必须先验输入预算，再验证有效 UTF-8。按已确认WC-03，不仅因`%PDF`/`PK`等签名拒绝一个有效UTF-8的Markdown文件；无效编码的拒收不变。允许文件头 UTF-8 BOM，记录并从编辑源码分离；文中 U+FEFF 不当作 BOM 删除。以 UTF-16 BOM 开头的输入、未知编码、截断多字节序列返回 DecodeError，不使用有损替换、不提供额外只读转码入口、不写原文件。无 BOM 的 UTF-16 若字节本身是有效 UTF-8，会按 UTF-8 文本接受；M0 不新增启发式检测，该限制由 4.1 金样固定。

2026-10-31 用户批准原始行尾表示替代原 CRLF→LF 建议：解码分离头部 BOM，源码保留原 CR/LF 字节；统计原始 CRLF 对数及未配对 LF 数，CRLF 中的 LF 不重复计数，孤立 CR 不计入二者。多数派选择 CRLF 或 LF，平票（含均为零）选择 LF。源码补丁和历史按实际源码精确执行，不在 Buffer 外隐式规范化。

例：bytes `BOM + 甲\r\n乙` 与编辑源码 `甲\r\n乙` 因头部 BOM 的偏移不同，CRLF 在源码中仍占两个字节。编辑、查找、历史只使用编辑源码的 src_off；磁盘偏移转换仅由 source 的存储映射接口负责。markdown 的映射输入是编辑源码，不再次去 BOM 或规范化行尾。

用户粘贴/平台输入中的换行必须经过统一入口确定表示，再生成补丁和逆补丁；不能事后无历史地整理整个 Buffer。源/存储映射须覆盖编码策略引起的 CRLF 两字节与 LF 一字节转换、范围端点及孤立 CR；解码本身保留原始行尾；输入边界拼接成 CRLF、End/Delete 和粘贴换行的具体金样归 V-07。禁止用全局 `trim()`、吞 CR 或自动补尾换行解决边界。

### 5.2 编码、保存身份与例外

| 场景 | 必须结果 |
|---|---|
| 打开后不改、主题/模式切换后保存 | 返回原 bytes，包括 BOM、混合行尾、空白、实体写法、孤立 CR、无末尾换行 |
| 相对存储基线有实际文本变化 | 重放 BOM 与读取基线的行尾策略；CRLF 对和未配对 LF 各为一个行尾单元，包含编辑新拼接 CRLF；未配对 CR 逐字节保留，不重排 Markdown |
| 基线无 BOM 且冻结源码以 U+FEFF 开头 | 写出一个头部 BOM 保护该正文 U+FEFF，预算计入；成功保存后的新基线记为有 BOM，再解码仍保留该字符 |
| 统一 LF/CRLF 文件局部修改 | 除显式补丁及其编码表示外，其他部分不变 |
| 混合 LF/CRLF 文件修改 | 按多数派统一，平票 LF；LF 策略下紧跟在孤立 CR 之后的 CRLF 单元保留 CRLF，以免再解码时吞掉孤立 CR，结果可以仍含混合行尾；未编辑行也可能改变行尾，这是 SAFE-03 的全文件规范化例外 |
| Undo 回到尚未被新保存替代的原始基线内容 | 恢复该基线的原 bytes 通道；“编辑过一次”的粘性标志不能破坏内容回到保存点的语义 |
| 保存期间又输入 | 只登记实际成功写入的冻结快照及对应 bytes，当前较新内容仍脏；失败不替换基线 |
| 混合行尾已成功统一后再 Undo | 相对新的实际磁盘基线判断；不能偷偷恢复早已被替代的旧磁盘 bytes，也不回退 DiskVersion |

编码不能使用会把已有 CR 再扩成额外 CR 的无条件全文替换。基线无 BOM 而冻结源码以 U+FEFF 开头时，只在输出前补一个头部 BOM 保护该正文字符（2026-10-31 裁决），不删除源码首字符，也不把它解释为基线原有 BOM。存储基线须绑定成功写出的 bytes、冻结源码身份及受检行尾等价关系。编码后再 decode 只允许 CRLF/LF 行尾表示差异，不要求 String 严格相同：例如 `"\rX\n"` 删除 X 后的 `"\r\n"` 在 LF 策略下保存重开为 `"\n"`，这是用户已批准的新拼接行尾语义；未配对 CR 及其余字符不变。此存储等价不得用于补丁无变化、历史或工作版本判定，逆补丁仍对实际冻结源码精确执行。原 bytes 通道只由同一基线对象上的精确源码相等决定；宿主另记成功写出的冻结输入事实，不以行尾等价放行该通道，也不接受调用方无来源的 bool；失败不更新。边界金样仍须在 V-06/V-07 实际验证，分析演算不等于实现通过。

“未修改”是内容相等事实，不是栈深或 revision 相等。建议保存节点身份作快速证据，其他路径用受版本保护的内容等价检查；指纹只能筛选，不用未经核验的哈希命中宣称内容一致。保真原 bytes 选择与 dirty 计算消费同一内容事实，但存储策略独立保存，不因更改历史游标丢失。

### 5.3 最小文件层接口

`decode(bytes, budget)` 返回源码、只读存储基线及诊断；`encode(snapshot, baseline, equality_evidence)` 返回完整待写 bytes 或错误。两者都不修改 Buffer/History。UI 负责获取最新草稿快照、安排受检写盘、检查外改、成功回调与恢复资源清单；source 提供同步纯处理/受检 I/O 原语，调度在 UI。

这里的 snapshot 是只读文本输入的语义统称，source 不导入 buffer/UI 的快照类型；由 UI 解包成 source 接口接受的 `&str`/共享文本和 source 自有元数据。内容相等证据必须绑定该文本与相应基线身份，不能由调用者传一个无来源的 `unchanged: bool` 跳过保真检查。

原子替换、权限、磁盘满、另存为资源迁移、恢复清理与串行写队列遵守架构 §7.3～7.4、V-08。本文件不把一次 rename 称作跨进程 CAS，也不把这些事务放进 markdown。WC-04已确认有条件继续策略：权限复制错误明确属于不支持且临时文件/替换访问语义经平台证明安全时才可继续，并反馈实际保证；其他权限失败停止且保全原文/内存。source返回受检错误类别/可证明能力，UI协调决定是否满足条件；mode不等于ACL/xattr，不能忽略所有权限错误，V-01/V-08仍须证明。

### 5.4 M0 编码与最小 I/O 实施状态（2026-10-31）

4.1～4.4 已在 `aline-source` 落地并留证：`StorageSnapshot`/`StorageRange`、`decode`、`SourceBaseline`、`encode`、`prepare_atomic`/`Written`。实现保持以下边界：

- 解码先验预算，再拒绝 UTF-16 BOM 与非法 UTF-8；只剥离一个头部 BOM，源码保留原始 CR/LF，孤立 CR 逐字节保留，不提供有损替换或额外只读转码入口。
- 编码只由同一基线对象上的冻结源码相等决定原 bytes 通道；否则重放 BOM 与多数派行尾，CRLF 对和未配对 LF 各为一个行尾单元；基线无 BOM 而冻结源码以 U+FEFF 开头时补写一个头部 BOM 保护正文。
- `StorageRange` 是当前唯一公开的存储字节范围类型，显式绑定 `BaselineId`，并注明不等同源码 UTF-8 范围；source 不提供以磁盘偏移索引编辑源码的接口。
- 最小 I/O 只实现 create-only 发布：同目录 `create_new` staging → 分块完整写入 → `sync_all` → `hard_link` 到尚不存在的目标。目标已存在普通文件返回 `MetadataPreservationUnverified`，符号链接/目录/其他非普通文件返回 `ExistingTarget{kind}`，检查后的竞争返回 `Conflict`；不覆盖、不截断、不删除，也不回退为原地写。

证据：4.1～4.4 的金样、测试与门禁见 `docs/validation/m0-engine-foundation/group-4/`；K-08 偏移人工复核见 `step-4.5/report.md`。未验证：ACL/xattr/权限复制、目录 fsync/断电、跨进程 CAS、现有文件覆盖保存、Windows/Linux、网络/外接卷与真实应用保存闭环。V-06/V-07/V-08 与 M0 出口均未据此判通过。

## 6. 解析管线及预处理映射

### 6.1 阶段契约

```text
有效源码快照（含版本）
  → 字面区域/Front matter 等受检识别
  → 可选映射式改写（仅解析副本）
  → pulldown-cmark 带偏移事件
  → 带原源码范围的 mdast
  → 语义修正、展示树/Inline 映射、保护区/导航索引
  → Parsed（版本、配置、诊断、块 + Gap）
```

| 阶段 | 输入 → 输出 | 映射责任与失败出口 |
|---|---|---|
| 入口 | 不可变 SourceSnapshot + ParseConfig + ParseBudget | 版本/配置键随产物返回；超预算不分配无限树，保留源快照 |
| 识别 | 源码 → 代码/HTML 等字面范围、文首配对围栏及扩展候选 | 不编辑源；识别不确定则保留原文，不让公式/emoji 扫描误入字面范围 |
| 改写 | 上一阶段文本 → rewritten + RewriteMap + 合成片段来源 | 每一改变都有源区间或明确的 synthetic 锚点；映射失败退回安全原文，不能透传改写偏移 |
| 解析 | rewritten → 带 span 的 pulldown 事件 | features 与 Options 显式配置；事件 span 仍是改写文本坐标，不直接当 src_off |
| build | 事件 + RewriteMap → mdast | 合成围栏/占位剥离，所有有效节点范围回到源快照；栈闭合/范围异常返回诊断，不 panic |
| tree/索引 | mdast + 源片段 → 展示、Inline、保护/语义区、导航 | 样式只含语义；所有实体/转义/空白处理产生映射关系；局部映射失败使相应区域退为原文 |
| 校验/发布 | 候选 Parsed → 可采纳结果 | 校验源范围、覆盖、边界、预算及输入身份；UI 再验当前版本才挂载 |

中间树不必公开其全部字段；事件构树建议显式栈，限制嵌套与节点数量。Markdown 不完整通常是合法的未闭合输入，按解析器/产品夹具呈现或原文回退，不等同“解析异常”。内部缺陷和资源超限必须有区别诊断。

### 6.2 解析器配置与扩展

唯一解析器锁定 pulldown-cmark。首轮**建议配置**为关闭默认 Cargo features，按需启用 TABLES、FOOTNOTES、STRIKETHROUGH、TASKLISTS、MATH 对应 Options；Cargo features 与运行期 Options 不混为一谈。smart punctuation、heading attributes 等未列入需求的行为不默认开启，不能改变源码显示口径。

自动链接、Alerts、emoji、`[toc]`、公式定界符和 Front matter 按 PRD 补齐。是否使用原生选项或小型自定义扫描，由 M0 的锁定版本夹具决定，不能把旧“不开 ENABLE_GFM、自研全部 autolink”当不可更改决定；不引入另一 Markdown 解析器。公式的具体定界符/支持清单由 V-03 固化，旧 `\(...\)`、`\[...\]` 是候选覆盖，不能仅据旧稿宣布已冻结或已支持。

### 6.3 改写器的必需能力

| 旧方案 | 复核后的实施条件 | 验证 |
|---|---|---|
| flow：独立 `$$` 改为数学围栏 | 仅在锁定解析器不能直接表达所需语义时使用；围栏冲突、缩进/引用上下文、未闭合输入均有原文回退 | V-03、V-07 |
| tex：用控制字节 stand-in 适配定界符 | 不是既定算法；必须证明与真实 U+0001～U+0008 输入无碰撞且可追溯，不能依赖“用户不会输入”；建议优先显式片段表 | V-03、V-06、V-07 |
| front：等长空格掩蔽 | 只在忽略 BOM 后文首完整配对 `---`/`+++` 时识别；掩蔽保留换行及完整字节映射，另外保留原始只读节点；未闭合不得吞全文 | V-07 |

扫描需跳过围栏代码、缩进代码、行内代码和 HTML 字面上下文。不能仅用朴素正则全局替换，也不能声称一次扫描已经正确识别全部 CommonMark 上下文。**建议**先用同一个 pulldown-cmark 建字面区间，必要时再解析改写副本；若采用独立扫描器，须与参考全量路径在同一语料上比较。选哪条路线及多次扫描成本由 V-05/V-07 证明，不冻结“全流程永远只解析一次”。

RewriteMap 是区间关系，不要求把删除/合成字节虚构为一一对应：原样片段精确映射，替换片段记录完整原区间，synthetic 围栏只能映到合法边界且不可被当作用户文本。多 pass 的映射须逐级复合回源快照，重叠改写按固定顺序处理或显式拒绝，不只累加长度 delta。

pulldown 一个事件可能跨多片段，必须保留子段来源，不能仅映射 span 两端便推断内部恒等。等长空格不说明字符语义恒等；UTF-8 多字节字符换成空格时，映射端点仍须回到原字符边界。任何 pass 无法证明来源时，禁止开放该投影的直接修改，回到原文视图。

## 7. 源码、绘制文本与其他坐标

### 7.1 坐标与映射记录

`src_off` 是某一源码快照的 UTF-8 字节边界；`drawn_off` 是某个投影文本的 UTF-8 字节边界，不是 glyph 编号或字符数；`utf16_off` 是该输入投影的 UTF-16 code unit 边界。按已确认 RS-02，跨模块/跨 crate 的这三类偏移和范围必须用 newtype/受检封装区分；模块内部单坐标可用明确命名的 usize。补丁原语仍为 `Vec<(Range<usize>, String)>`，仅在统一受检边界解包/封装，不让裸整数绕过版本、投影和字符边界校验，也不新增反向依赖。类型名、底层宽度及归属由实现依既定分层确定。块局部字节、磁盘字节、用户字符列、像素均须明确命名和版本，不使用裸名 `pos`/`idx`。

旧 `(drawn_start, source_range, Escapes)` 可作压缩存储建议；Plain/Markdown/Html/Pipes 是不同解码来源，不能丢失。它本身不足以表达零宽隐藏、合成换行、一源多字符和精确可编辑性，必须能通过记录或可验证的解码过程恢复下述关系：

| 片段关系 | 例子 | 定位/选区契约 |
|---|---|---|
| 原样 | `中文`、普通代码 | 合法 UTF-8 边界精确对应；禁止落到字符内部 |
| 解码/压缩 | `\*` → `*`、`&amp;` → `&`、表格转义管道符 → 可见管道符 | 记录完整源区间与可见锚点；点击实体回到 `&`，Markdown 转义文字锚点可在转义后字符，编辑覆盖另用完整来源区间 |
| 一源多字符 | 一个命名实体生成两个 Unicode scalar | 每个可见字符有共同来源区间；非唯一的中间边界显式标为不精确，不编造源码内部落点 |
| 多源合并 | HTML 多个空白 → 一个空格 | 记录被消费的空白范围，前后边界经 affinity 决定；不能只凭字符值向后搜索 |
| 零宽/隐藏 | Markdown 标记、HTML 标签/注释、链接目标 | 仍有语义源范围；`drawn_at` 可给相邻锚点及 Hidden 状态，整区无可见内容则给源码入口，不能冒充精确命中 |
| 合成 | 块级 HTML 标签产生换行、图元占位 | 记录来源/边界锚点及 Synthetic 状态；不可据此直接删除一个虚构源码字符 |

普通 Markdown 的三种换行必须分开：SoftBreak 来自段内源码换行，投影为换行或空格的样例/默认口径由 V-07 冻结，旧 `lines=true` 不是当前决定；无论哪种，都记录该源码换行的来源，不按像素宽度猜。HardBreak 来自两空格加换行或反斜杠加换行时，投影为换行并覆盖完整源标记/换行区间；`<br>` 则走 HTML 标签来源/合成锚点。窗口宽度产生的自动折行只属于布局，没有新增源码或绘制字符；命中折行边缘仍回到原投影的合法锚点。V-07 夹具还需区分行末空白、行首缩进与代码内 tab/换行的字面保留，不能对所有 Inline 一律 trim 或合并空白。

建议映射结果除目标坐标还含 `Exact / Aligned / Hidden / Synthetic` 等精确性信息及来源范围，错误使用单独 Result 表示。具体类型可调整，但调用者必须能区分“合法近似锚点”和“可直接用于编辑的精确区间”。

**存储实现建议（待 V-05/V-07）：**原样片段可仅存源起点及长度，变换片段再存相对偏移/来源记录，避免所有文本逐字分配映射表。[Splat 源码案例与限制](./splat-study.md#43-坐标映射光标与选择)提供了实际紧凑表示，不能据此采用其字符扫描对齐或静默吸附末尾的算法。压缩前后必须具有相同的来源范围、精确性和合法锚点；相对偏移位宽及累计运算受检，不因压缩丢掉一源多字符、隐藏/合成或版本信息。

**2026-10-31 M0 接口基础记录（任务 3.3）：** 恒等投影的 `source_at`/`drawn_at`/`aligned`、局部/全文与 UTF-16 转换已实现并有外部消费者与编译夹具证据；当前仓库扫描未发现调用方手算 `at - range.start`、自建 UTF-16 表或映射外转换，但公开坐标访问器仍可被绕过，扫描不构成结构保证。`Aligned`/`Hidden`/`Synthetic`、实体/HTML/合成换行与块局部映射仍仅契约未验证（第 6 组）；当前没有 UI 生产消费者，不证明真实命中或 IME。详见[任务 3.3 记录](./validation/m0-engine-foundation/group-3/step-3.3/report.md)。

### 7.2 操作语义

| 操作 | 输入、输出与边界 |
|---|---|
| `source_at` | 同版本 Inline + drawn_off + affinity → 合法源锚点/来源信息；字符来自实体时落实体起点，末尾位置是合法边界而非越界字符；不精确时不能只返回一个无标志整数 |
| `drawn_at` | 同版本源码锚点 + affinity → 投影位置及可见性；隐藏标记、注释不要求可见位置唯一，必要时返回无可见落点而保留源范围 |
| `aligned` | 以明确的源/绘制关系规范化候选锚点或区间，指定方向及用途；不改文本；不能把任意非法字节自动修为可执行删除 |
| `map_selection`（统称） | anchor/head 分别映射、保留方向；同时计算选中内容的完整来源覆盖及精确性；点击锚点不能代替删除范围 |
| 局部/全文适配 | 块或草稿局部字节 ↔ 当前全文源码，含草稿长度变化和插入点 affinity；恒等路径也走接口，禁止 UI 写 `src_off - range.start` |
| UTF-16 适配 | 在同一个输入投影上 UTF-16 ↔ UTF-8，再经来源关系到 src_off；拒绝代理对中间、越界或不匹配版本，不把 code unit 当字符 |
| 锚点变换 | buffer 根据补丁批次变换 before 源码锚点到 after；被替换区内依据 affinity 给结果/失效，不能让 UI 用 delta 猜 |

必须测试：所有成功结果在范围内且为 UTF-8 边界；原样段精确往返；对齐操作在相同版本/affinity 下幂等；源序有序的文字片段映射不倒退；每个可见字符来源已知或显式 Synthetic；同一来源可见锚点多次往返稳定。导航产生的脚注/目录副本要分清“文本来源”和“跳转目标”，不以重排显示顺序断言全树映射单调。

禁止对任意源码字节断言 `source_at(drawn_at(x)) == x`。`&amp;` 内多个偏移、隐藏的 `**`、多字符实体没有这种双射；正确测试应比较规范锚点/来源范围及精确性。若绘制内部边界不可唯一表示，往返到约定的规范边界即满足契约，不能声称原边界不变。

旧 aligned 从尾部按字符相等回找、LineMap 逐行校正都是**待验证实现建议**。重复字符/空白、HTML owed、tab、emoji 短代码及跨改写片段可能匹配到错误 occurrence。必须在构建时保留来源或通过金样证明对齐；失败返回 MappingError/原文回退，不能 log warning 后继续提供不完整可编辑映射。

### 7.3 点击、选择、移动和删除

UI 对相应版本的文本布局命中，取得 drawn_off 和方向偏好，交映射层返回 src_off，再检查保护区和 Parsed 版本。打开原始源码后以同一源锚点恢复选区；布局过期先重算，不套用旧点击范围。

拖选分别映射端点，文档级源码选区可跨多个块，不同时打开多个块。复制/删除/粘贴以该源码范围及能力检查为准；跨 MD-11 拒绝并提供 Source 定位。命中隐藏注释/链接目标的搜索走源码 reveal，不强迫创建不存在的可见文字选区。

键盘移动和 Backspace/Delete 不能拆坏 UTF-8、UTF-16 代理对、组合字符或 emoji ZWJ 序列；用户字符移动边界与标量边界分开。建议映射服务提供字素边界适配，Unicode 分段依赖准入及金样由 V-07 收口。正文源码输入允许用户逐步改写 Markdown 标记、实体和 HTML，不强制保持语法闭合；不得把旧 C 阶段“自动 unwrap 隐藏标记”规则带入 V1 低对比度标记输入。

**实现与回归建议：**分别测试阅读态的点击插入锚点、选区来源覆盖、跨段 Gap 和整体来源图元，不能用同一个“最近源码位置”处理全部操作。尤其在粗体末尾、链接显示文字/目标之间、实体两侧和空段落，先验证阅读投影命中，再验证开块后的源码选区；开块后的普通输入不继承富文本自动转义或空容器自动清理。源码换行、绘制硬换行和布局软折行分别建样本；纯导航到已有表格单元格不附带整理源码，末格新增行及显式整理另按命令规划补丁。问题来源与不兼容反例见 [Splat §4](./splat-study.md#4-可视化编辑的实际机制)，这些样本细化现行契约，不增加全时隐藏标记编辑模式。

## 8. 打开、输入、提交、拒绝与重解析

### 8.1 四种状态各自的含义

Buffer 是已提交源码；OpenBlock 是至多一个受控的待提交源码替换；History 含已形成的输入组和当前未封口组协议；Parsed/布局是派生状态。当前全文是“Buffer 前片段 + 草稿 + Buffer 后片段”的逻辑视图，不是从展示树构造的新文档。Source 输入也走同一历史协议，不另立子编辑器历史。

`snapshot_current` 必须返回包含最新草稿/当前输入的不可变一致快照、WorkingVersion、选区及所需资源引用；允许在消费任务开始时物化，不允许每键复制全文。取快照不提交、封口、清空 redo 或压缩历史；取完继续输入只会产生新工作版本。

### 8.2 普通输入循环

1. **激活：**验证点击所用 Parsed/映射属于当前工作文本；已有块先按相同协议处理剩余组。若文本因此改变，重新映射点击锚点/等新解析，不沿用旧块数组下标。
2. **打开：**校验目标范围、源片段和语义权限，MD-11 灰色区/脚注引用本身不进入就地编辑；普通段落内有保护子区间时按 §4.2 保留正文编辑能力。从源码切片建立 OpenBlock 和源选区。HTML 原文编辑允许，但不能丢失 Html 语义身份。
3. **输入：**局部范围经映射层转换为当前源码选区，维护唯一草稿、draft_generation 和未封口组；普通相邻输入按 900ms 协议累计，组合输入走第 10 节。每键不运行全量解析/保存/统计。
4. **封口与提交：**计时、非相邻输入或独立命令等已定边界使输入组形成单区间 Change；验证基线 revision、range、基线片段、UTF-8 边界及权限。可收窄实际变更区间，但不得越过块可编辑范围或绕过保护；源坐标计算在映射/补丁模块中完成。无变化组不记步。
5. **原子应用：**由 DocCore 唯一入口调用 buffer；成功一次记录正逆补丁和源选区、推进 revision；更新保持打开的块基线和范围，未打开块不能留下旧绝对偏移。
6. **重解析：**提交后作废相应 Parsed/查询缓存，由 UI 调度不可变快照解析；未完成前保留源码入口，旧映射不能用于新修改。块内展示可作为局部提示，但不是全局语义真源。

开块和关块自身不产生文本变化。草稿新增换行会改变块结构时，提交的仍是原输入组的单区间补丁，后续块归属由重解析确定，不能截掉新段落或把新块当第二个独立可写 Buffer。

### 8.3 事件与状态转换

| 事件 | 必须行为 | 历史/版本 |
|---|---|---|
| 同块继续输入 | 合法相邻输入在 900ms 规则内属于同组；块可保持打开 | 待定组随工作版本变化；封口提交后独立一步 |
| 点击其他块/实际离开上下文/Escape | 非组合期仅提交剩余未封口组并关旧块；Escape 不丢字 | 不重新记此前输入，不把整个打开期间压成一步 |
| 菜单/弹窗借焦点 | 保存原源选区和输入上下文，归还时恢复；不能把暂借焦点当取消输入 | 不制造多余空组；组合中不抢焦点 |
| 模式切换 | 组合安全结束后处理剩余输入，切换同一源码视图 | 切换本身零字节/零历史步，源选区经新视图映射 |
| 查找只读请求 | 搜当前快照，包括草稿；结果带工作版本/查询代次 | 不封口组；旧命中作废 |
| 修改命令/替换/格式化应用 | 先预检；处理待定组后取最终基线重新规划或受检变换 | 命令与输入分组隔离，不把旧工作范围应用到新 Buffer |
| 保存/恢复/导出读取 | 取当前一致快照，不隐式 flush/封口 | 900ms/IME 分组保持；自动保存组合期延后；显式保存/另存为/导出按 ED-01 可取消地等待平台自然确认或取消后取当前快照 |
| Undo/Redo | 当前待定组优先经统一历史协议撤销/重做，再处理已有组 | 恢复对应文本/选区，重新建立打开块基线 |
| 外部重载 | UI 按冲突协议取得候选；重载独立历史边界 | 按 TA-02，不复用旧绝对补丁；见第 9.3 节 |
| 基线失配/版本冲突 | 保留草稿及选区，返回 Changed/DraftConflict；重新定位或交冲突处理 | 不 `drop_open()`，不把草稿默默写到新范围 |

命令拒绝必须相对调用前状态零副作用。因此建议在封口待定输入前完成可判定的前置检查，并在候选状态中准备“待定组处理 + 命令”，最终校验后整体发布；不能先清空草稿/改变选区，再发现命令拒绝。若中途工作版本变化，放弃候选而保留当前真实输入。

## 9. 补丁、命令事务与历史

### 9.1 补丁批次的精确定义

每个补丁是 `(src_range, replacement)`，range 是基线快照内半开 UTF-8 字节区间，所有正补丁都使用同一 before 文本坐标。单区间输入组与多区间命令不同；全部替换、格式化、表格结构操作可以一组多补丁，但一组只记一个用户操作。

应用前必须完整检查：预期工作版本及源片段仍相同；`start <= end <= len`；两端字符边界合法；补丁按源起点升序；写入范围不重叠；新选区属于 after 文本且合法；命令上下文/保护范围有效。所有整数长度/累计偏移运算受检，不能靠 usize 回绕。空区间允许单次插入；同一点多次插入及插入与替换边界的顺序歧义，规划方须先合并为一个确定补丁或返回错误，不能依赖排序偶然顺序。

建议先剔除内容相同的替换、构建完整应用计划/逆补丁，再从尾到头应用，避免前补丁改变后补丁坐标。只有全部成功才发布文本、行索引、选区、revision 及 History；不能发生“前两个已改，第三个才报越界”。预检失败无写入；内部不变量失败也不能用改计数器掩盖文本已损坏。

**正逆坐标修正：**正补丁作用在 before；逆补丁作用在 after。例：before `abcXYZ`，正补丁 `[(1..2, "QQ"), (3..6, "!")]` 得到 `aQQc!`，逆补丁是 `[(1..3, "b"), (4..5, "XYZ")]`。第二个逆范围必须计入前一替换的长度差；旧 §2.2 的 before/after 注释写反，不能迁入。逆文本从 before 原切片取得，不从 AST 猜。

### 9.2 命令与预演

`plan_change(snapshot, parsed, selection, command)` 是纯逻辑。快照 → 能力/保护检查 → 补丁计划 → 在候选文本预演 → 必要的重读 → 目标选区 → 执行前版本复验 → 原子发布。耗时计算由 UI 安排；edit 内不 spawn 或读取窗口。

`reread` 必须在真实应用**前**运行。比较目标由命令定义：格式 toggle 保留内容文字，任务框允许完成态改变，删除本来就要删除；标题/块转换允许目标结构变化，但不能丢链接目标、注释或未知片段。只比较可见字符串不足以证明不可见源码保全，必须同时核对命令宣称保留的源片段和语义。无证明则拒绝，不用“应用后发现错了再回滚计数”替代事务。

行内取消格式删除实际存在的标记，新增才生成规范标记；列表续行保留原分隔符与可保留前缀；任务框只改目标完成标记。代码语言修改保留正文，缩进转围栏也由显式补丁完成、一步撤销。表格按源单元格/分隔符识别，不能简单 `split('|')`；转义管道、代码片段、对齐行、不齐列与空格保留通过 V-07 金样冻结。

表格结构命令即使替换整表范围，也必须根据原源片段规划重排/插入，不从展示 Table 序列化回 Markdown。只有用户显式“整理”允许按已冻结风格调整相应表格源码；不能把每次逐格输入都变成整表规范化。

### 9.3 历史、保存点及重载

History 必须支持正逆补丁、before/after 选区、操作来源、内容身份和当前待定组。900ms 只用于连续相邻普通输入；IME 确认独立、替换/命令/跨块/重载独立。时间由宿主显式传入，纯状态机不创建计时器；计时起止、移动光标后相邻性等用 V-07 金样固定，不能从旧 Zed 300ms 继承。

Undo 优先处理当前待定组，不能先制造一条重复整块提交；Redo 恢复同一组及对应选区；新增实际编辑使原 redo 分支失效。拒绝、无效命令、无变化提交和组合取消不产生空步，也不无故清空 redo。历史内存预算/裁剪策略待 V-06；裁剪必须明确保存点识别和临时资源仍被历史引用的生命周期，不能只删 Vec 后继续用旧栈深判脏。

例：A → 输入组 B → 保存当前快照 → Undo → 输入 C。B 和 C 可处同一栈深但内容不同，因此 `undo.len() == saved_at` 无效。另例：未封口组中途保存，之后继续同组合并输入；Undo 可能直接回到该组开始处，而非保存的中间快照。保存不为此封口，dirty 仍按实际已保存内容判断。

TA-02 已确定自动重载与“载入磁盘”都是独立可撤销边界。建议以受检的整段源补丁表示磁盘内容替换：这是外部字节解码结果的显式载入，不是 AST 全文重建。Undo 先回到重载前对应内容，旧历史才能在其正确上下文继续；磁盘基线始终保持最近实际读取/写入版本，不随 Undo/Redo 回退。

撤销重载带回不同旧内容时，UI 提示来源、判脏并暂停自动保存；显式保存/另存为成功或重做回当前磁盘基线后恢复正常策略。redo 回基线为未修改；任何再写仍验外改。重载发生时若有草稿/组合输入，按当前工作内容判断本地修改，不能因为 Buffer 未变误走“无修改自动重载”。

### 9.4 查找、替换与格式化

查找按当前源码，含隐藏标记、HTML 注释及链接目标；结果含源范围、实际匹配文本、WorkingVersion 和 query_generation。替换前重验版本与命中文本；Unicode 大小写、环回、空查询及退出焦点样例由 V-07 固化，不静默退为 ASCII-only。不可见命中 reveal 原始块，MD-11 命中切 Source。

全部替换先收集同快照非重叠命中，再一组补丁/一步历史；跨显示块的源码匹配不能被逐块扫描遗漏。目标触及 MD-11 时必须先定位 Source，再以匹配版本执行，不能“可视化不可编辑但搜索替换可绕过”。

全文格式化仅用户菜单手动触发。当前快照 → 保留未知/HTML/原文区的源片段补丁计划 → 展示差异 → 用户确认 → 版本复验 → 一次应用、一步撤销。取消或无法安全规划时零修改；差异期间有输入则作废重算，不把旧全文覆盖当前文本。具体风格及 MD-11 区域外的安全重写范围归 V-07，不能以“全文格式化”默许 AST 序列化或重写保护内容。

## 10. IME、Unicode、选区与字符统计

### 10.1 组合状态与平台边界

组合状态建议包含组合前的工作内容/选区身份、当前 marked 源范围、候选文本、候选内源选区及组合代次。它属于唯一输入状态机；预编辑内容保存在同一受控草稿/待定组中，不是第二份可独立保存的文档。GPUI 只提供回调和几何，纯逻辑结构不含 Entity、Window、FocusHandle 或 InputHandler 类型。

V1 打开的块显示源码（仅样式淡化标记），输入投影与块源码文字相同；平台 UTF-16 是这个输入投影的偏移，不能误用未打开阅读投影的 UTF-16。Source 模式用源码投影；任何恒等转换仍经过统一映射适配。未来隐藏标记的输入协议需单独验证，不由本稿提前冻结。

| 组合事件 | 必须行为 |
|---|---|
| 开始 | 记组合前工作状态；此前普通待定输入与这次组合不能误并 |
| 更新/替换候选 | 仅更新当前组合投影、marked 和选区，推进工作代次，不生成已确认历史步、不触发结构命令或图表预览提交 |
| 平台确认 | 最终候选形成独立的单区间提交/一步历史，恢复相应选区；块可继续打开 |
| 平台取消 | 恢复组合前文本及选区，不留下空步或丢掉组合前已存在的普通输入 |
| 实际失焦/点击其他块/切模式 | 不以 Blur/Escape 猜确认或取消；先由 UI 获得平台组合完成结果，再处理剩余输入/切换；等待期间保留原上下文，不抢焦点、不丢草稿 |
| Escape | 组合期先由平台处理候选/取消，收到完成结果后才有普通关块语义；非组合期是提交而非丢弃 |
| 外部版本变化 | 不套旧 marked 范围；保留组合/本地候选并交 DocCore 冲突处理，不能重载后继续用旧回调替换新文本 |
| Undo/命令 | 不能由组合键事件误触发格式命令；UI 按平台事件先处理组合状态，再进入普通历史/命令协议，用 V-07/V-01 实测 |
| 自动保存/10 秒恢复 | 自动保存等待组合结束；恢复保留当前输入及临时引用，快照不强行确认组合。恢复记录的组合表示和重新进入内存方式由 V-07/V-08 样例验证 |
| 手动保存/另存为/导出 | 按已确认 ED-01，请求进入可取消等待；平台自然确认或取消后取结束后的当前快照；不发布预编辑候选、不伪造组合结束，取消请求不改输入/历史 |

失焦/模式切换仍由平台输入事件接线；ED-01 已独立决定显式保存/另存为/导出的可取消等待。等待不强制平台确认或取消，取消的是发布请求而非组合输入；平台自然结束后取当时当前快照，取快照本身不封口输入组、不记步或清 redo，不重开 TA-01。恢复仍按独立契约保护组合中的当前输入。

### 10.2 Unicode 与测试边界

UTF-8 字节合法不等于用户字符合法。UTF-16 转换不得截半代理对；普通移动/删除不能拆开 `e + 组合重音`、带肤色 emoji、区域旗帜或家庭 ZWJ 序列。组合替换范围来自平台，必须映射并校验，不能先按字素扩张后无声替换用户未选内容。无法可靠对应时明确失败并保留当前输入。

在中文标点、`\*`、`&amp;`、反引号及 HTML 标签附近，源码编辑允许未闭合语法的中间状态；不因为每键重新呈现而吞字符、跳光标或自动补全标签。阅读投影产生的非精确删除选区先按来源/保护规则处理，必要时进入源码，不删除半个解码实体对应的未知范围。

字符列、上下移动视觉列、字数统计是不同口径。光标列不能直接报 src_off 或 UTF-16 长度；中文/英文/标点/标记/代码/空白/选区的统计规则由 V-07 在 M4 前冻结，两模式相同。统计可后台计算且带版本，不在每键主线程扫描全文。

UI 集成须覆盖真实中文输入法的候选更新/替换/确认/取消、选中文字再组合、组合中点击/借焦点/切块/切模式、候选窗换行/DPI 定位、组合与 Undo/Redo/保存/恢复交错。模拟纯状态机不能替代 V-01 的实际 macOS→Windows/Linux 输入法验证；GPUI 回调签名与候选框实现查锁定快照及后续 UI 专项。

## 11. Markdown、HTML 与特殊语法行为矩阵

### 11.1 解析、定位、修改与拒绝

所有“展示”均要求源片段保留；资产成功与否不决定源文本是否存在。下表是产品边界，具体样例/库覆盖率仍须 V-03/V-07。

| 内容 / PRD | 解析与展示、源码定位 | 可视化修改与命令边界 | 回退 |
|---|---|---|---|
| 标题、段落、分隔线 MD-01 | 块/行内范围、大纲锚点；Setext 等保留实际源码 | 打开原文、合法行内/段落命令；修改标记不重建正文 | 映射失败原文 |
| 引用、Alerts、列表 MD-01/03 | 嵌套范围与原前缀，五类提示块 | 续行、缩进、退出、任务框补丁；不可吞邻段 | 复杂跨结构格式拒绝并定位 Source |
| 行内格式/链接/自动链接/emoji MD-02 | 展示和链接/短代码来源范围分离 | 原始源码输入；格式 toggle 需可证明源边界，链接协议由宿主校验 | 未知短代码原文，未知协议拒绝行为执行 |
| 代码 MD-01、PLUGIN-05 | 围栏/缩进、info 与正文范围，逐行来源 | 原文编辑；更改语言只改 info，必要时转围栏且正文不变；不在字面代码内套普通格式 | 高亮关/失败/未知语言为普通代码；行号/复制不丢 |
| 表格 EDIT-12～14 | 表头、对齐、行列/源单元格范围 | 同一打开槽位逐格输入，核心行列操作/基础右键；复制优先原 Markdown | 不支持结构命令明确拒绝；关闭增强只移除悬停按钮 |
| 图片 MD-02、IMAGE-01～08 | alt/url/引用源范围，图元用来源锚点定位 | 块打开显示源码；插入意图须等资源成功才提交引用 | 失败占位且源引用保留，不请求远程图片 |
| 行内/块公式 MD-05 | 源码范围及定界符独立，资产为投影 | 行内打开显示源码；块级上源码下预览，300ms 防抖由宿主调度；不执行跨公式普通格式 | 插件关显示源码，错误/超限保留源码及错误 |
| Mermaid MD-05、PLUGIN-01 | 围栏/语言/正文来源明确 | 原文输入，上源码下预览；图像操作不成为文档编辑 | 关/失败回源码；具体图类型 V-03 |
| 脚注 MD-02/04/11 | 基础编号/定义/回跳、灰色展示，引用保留导航及受保护源范围 | 可视化内容修改、格式命令和跨块破坏都拒绝；只能 Source 改 | 编号/重复/未定义样例 V-07，不因插件设计移除基础能力 |
| `[toc]` MD-04/11 | 灰色目录展示及标题目标索引 | 可视化只读，Source 改；大小写/重复标题锚点 V-07 | 生成目录不是新源码，不写回生成条目 |
| Front matter MD-06/11 | BOM 后文首完整配对 `---`/`+++`，灰色原文 | 可视化只读，Source 改；不做属性解析 | 未闭合不识别为吞全文区域，按原文/普通语法回退 |
| 行内/块 HTML MD-07～10 | 核心解析/映射及语义身份，见下节 | 允许原始 HTML 输入；格式/块命令触及或跨边界拒绝，不能有 Clear 绕过 | 异常/超限退原文，不执行 HTML |
| 引用定义、未知语法、不完整输入 | 已有语义按解析器展示；未支持内容原文，隐藏定义仍保留定位 | Source 总有安全入口；无法证明安全的结构转换拒绝，普通已开放原文输入不要求语法完成 | 不因保存/格式化删除或静默规范化 |

基础跨块选择/复制/删除/粘贴必须交付，不能用“复杂命令可拒绝”取消基线。写操作统一检查 MD-11；只读命中允许导航/复制。HTML 禁止的是格式/块转换，不能因此禁止其原文编辑；表格基础能力也不能放到 table 插件才存在。

### 11.2 HTML 的有限解析与映射

必须支持 PRD 的标签样式映射：`b/strong`、`i/em`、`s/del/strike`、`u`、`mark`、`code/kbd`、`a`。`a` 需有效 href 才有链接行为；实体解码和协议 allowlist 校验是不同环节，解码后仍要安全检查。其他属性不成为脚本/CSS 执行入口。

HTML 块消费普通标签、保留可见文字，块级标签换行、折叠空白、忽略展示注释、解码实体/emoji；代码字面上下文不得误替 emoji。显示成 Paragraph 不会抹掉 Html 源语义。注释仅从展示忽略，源码、查找和保存仍能访问。HTML 块中 Markdown 文字不能被另一条 Markdown 解析链重复解释。

过滤集合沿 PRD：`script/style/iframe/title/textarea/xmp/noembed/noframes/plaintext` 等按字面文本显示，不执行脚本、不加载 iframe、不采用网页盒模型。旧“过滤标签本身字面、后续内容继续扫描”、属性内实体/emoji 与未闭合 HTML 行为须在 V-07 金样中明确；本稿不把它们扩成完整 HTML5 raw-text/浏览器兼容保证。

| 旧算法候选 | 可保留的机制价值 | 必须补的验证/修正 |
|---|---|---|
| `reopens` / `breaks` / `closes_p`、a 互斥 | 有限标签栈可处理错误交叉嵌套 | 集中维护有限表；验证 `<b><i>x</b>y</i>`、重复链接、隐式 p/li 结束、mark 不误延伸；不是 HTML5 完整修复算法 |
| `tag_end` 引号感知扫描 | 避免属性中的 `>` 被误作结束 | 未闭合引号/注释/`<a` 重复输入必须有扫描预算，不得每个 `<` 重新扫余下全文 |
| `owed` 延迟空白/换行 | 折叠空白时延后输出，可同时调整样式范围 | 欠写空白必须携带来源/合成锚点，不能像旧实现“纯空白不记映射”；反复闭合/重开样式后端点仍合法 |
| `Escapes::Html` + 实体表 | 展示字符能回完整实体来源 | 区分文本与属性、命名/数值/legacy/非法码点；多字符实体和缺分号金样；静态表/实例数据替代旧 OnceLock 全局表 |
| `LineMap` | 代码/HTML 原文与事件文字逐行对应 | 明确 tab 展开、缩进去除、源换行与合成换行；不是“有 LineMap 即自动正确” |

未闭合标签不得照搬旧 `rest = ""` 静默隐藏剩余内容；必须以原文回退并保留来源，或由 V-07 明确一个可定位且不吞内容的有限规则。超限导致安全来源不完整时，受影响区域作为原文投影，禁用依赖失效语义的格式命令。有限规则如最终迫使缩减 MD-07/08 产品结果，必须取得新决定，不能用降级宣布完成。

HTML 核心金样至少包含支持标签/无 href、引号内 `>`、交叉嵌套、注释前后空白、`&amp;`/十进制/十六进制/多字符实体、`<br>`、过滤标签嵌套、不完整输入、仅标签零可见文字、深栈与重复未闭合扫描。保留源范围、展示、样式、命中精确性和命令拒绝六类期望。

### 11.3 特殊资产的边界

引擎提供公式/图表/代码/图片的源片段、内容身份和必要语义参数；plugin/宿主计算资产，UI 校验版本与配置代次后采纳。关闭或失败保留源文本，不改变历史，插件关闭后的旧任务不能挂回预览。

代码语义着色与编程语言高亮分开：核心 Markdown 标记着色仍在；主题颜色、行号、复制按钮、图像生成与字体归 plugin/UI。SVG、data URI、图片解码在资产入口验协议/输入/输出预算，不能让引擎解析触发网络或执行任意 HTML。

## 12. 增量、缓存、调度与预算

### 12.1 先全量正确，再复用派生结果

当前基线为全量快照解析，再按结构与对应源片段相等作头尾配对/splice；这是**增量采纳/渲染复用**，不是已经实现局部增量 Markdown 解析器。引用定义、脚注、目录、围栏或列表结构可能影响远处，不能简单“只解析修改块”就宣布全局 Parsed 新鲜。

建议打开块内只维护源码输入及轻量标记着色；局部解析仅作提示。提交、结构变化、解析配置变化和局部边界不确定时必须以全量路径恢复权威 Parsed。未来局部优化需对完整重算做差分比较，失败自动退全量，不以错误映射换速度。

复用条件除源片段/结构相等，还包括所有影响语义的解析配置及全局依赖结果相容。前文插入使后块绝对偏移变化，后块内容相同也必须 rebase 或使用经映射管理的块相对坐标；旧“映射对象原样复用不失效”不成立。仅凭渲染文本相同会漏掉隐藏 HTML、链接目标及前缀变化。

**验证建议：**优化分支与全量路径比较的不仅是可见文字，还包括块/Gap、全部源范围、映射来源与精确性、保护区及导航目标；记录实际命中优化/回退路径，避免用全部回退的测试冒充增量验证。样本包含前文引用定义改变后文链接、脚注重排、未闭合围栏/HTML、列表缩进及 Front matter 边界变化。[Splat §5](./splat-study.md#5-解析局部更新性能与异常输入)有窗口扩展、全局回退和布局差分的源码先例，仍不改变本节的全量基线。UI 若实验分批派生刷新，占位升级不得改变同一投影的文字、来源或编辑权限；资产尺寸变化另按源码锚点保持定位，任何旧投影都不能接收并静默丢弃当前输入。方法、样本和通过条件归 V-05/V-07，具体调度仍由 UI 负责。

### 12.2 失效与采纳

| 派生状态 | 键/依赖 | 何时失效及正确回退 |
|---|---|---|
| Parsed、保护区、导航 | 文本版本 + 解析配置代次 | 提交/草稿语义变更后不作新文本权限依据；新 Parsed 前按源码入口或保守拒绝语义命令 |
| 块相对映射、输入 UTF-16/字素索引 | 源片段 + 投影种类/版本 | 草稿/组合更新、展示变换变更后重建相关部分；旧 UTF-16 不能复用 |
| 行索引/锚点 | Buffer 内容 + 补丁变换 | 与文本同事务更新；行表全重建/增量维护由 V-05 决定 |
| 查询/统计 | WorkingVersion + query/规则代次 | 每次相关输入立即标无效，再重算；未计算不冒充零结果 |
| 命令/格式化差异 | 工作版本 + 选区/命令参数 + 语义配置 | 任一不符重新规划，用户确认旧差异不授权覆盖新文本 |
| 布局（UI） | 文本/投影 + 字体代次、宽度、缩放、换行、有效 token | 主题/字体/宽度变更重新测量，不改源内容/历史 |
| 资产（plugin/UI） | 内容/语言、有效颜色/背景/尺寸、插件代次、资源身份/文件版本 | 内容/开关/路径/配置变化后旧结果不填新槽位，失败源码/占位 |

UI 调度任务，引擎只处理显式输入。结果至少携带文档身份、输入工作版本、相应配置代次和请求身份；回调先验目标存活再验键。Undo 即使恢复相同文字也不能让旧 request_id 自动复活。取消不等于任务已停，需合作式预算检查及队列限额。

解析结果只采纳当前匹配版本；保存只登记其实际写入快照，不把较新输入标已保存；导出可以交付明确标明的旧冻结版本产物，但不能覆盖新请求状态。这三种结果规则不同，不能统一成“版本不同一律丢弃或一律接受”。

### 12.3 资源预算与超限

必须在分配/扫描前检查输入量，并在循环/构树/展开中检查步骤、嵌套、节点/输出增长预算；无后台线程不能中断的事实不等于允许无限 CPU。建议可注入预算/取消检查接口，纯状态机不读取全局时钟。第三方长调用须有可说明的限额/终止策略，不能只将超时结果藏起来。

| 面 | 需要冻结的预算维度 | 超限出口 |
|---|---|---|
| 文件/source | 输入 bytes、解码/编码及快照内存 | 硬超限明确拒绝打开，原文件不变；>4 MiB 视图降级不代替硬上限 |
| pre/build/tree/HTML | 扫描步数、嵌套、节点、改写膨胀、映射规模 | 能可靠隔离则该区原文投影，否则整体源码回退；不截断原文 |
| 单段/单表/单格 | 字节、行列、单元格、布局规模 | 源码入口及诊断，不继续无界布局；具体降级经 V-06 验收 |
| edit/find/formatter/history | 命中/补丁数量、预演内存、历史 bytes | 返回 BudgetExceeded/取消计划；不部分替换、不先丢草稿 |
| 图片/公式/图表/高亮 | 压缩及解码体积、像素、源长、输出/耗时、缓存 | 宿主限制分配与并发，失败原引用/源码保留 |

所有具体资源数值仍待 V-06；旧 HTML 栈深、64 KiB 高亮、图片 8192px/256MiB 等均不作为新默认。StringBuffer 是建议起点，行表每键全重建是否满足预算必须实测；ropey 不预装。缓存可淘汰，源文本/未提交输入/仍被引用的恢复材料不能作为普通缓存淘汰。

### 12.4 性能目标与证据

PRD §7.2 的目标保留：≤32 KiB/≤128 KiB 典型文档块提交分别 <10ms/<50ms；可视化块内文本处理 <1ms/键；4 MiB Source 文本处理 <4ms/键；1 MiB 编辑滚动可交互；>4 MiB 默认 Source 并提示且阈值可配。它们都不是 Aline 实测结果。

V-05 必须分别测输入核心处理、组提交（预检/补丁/历史/解析采纳各子段）及端到端输入至呈现，不把后台排队时间藏掉。32/128 KiB、1/4 MiB、巨型单段/表格、HTML 密集/资源密集/敌意输入均测，冷/热缓存、Release、设备/OS/锁定版本、P50/P95、最长主线程停顿及峰值内存都记录。

旧同步 128 KiB、全文解析防抖 300ms、40rem overdraw、60fps、HTML ≤30ms、峰值 ≤2×、alike <5ms、10% 回归门槛是候选实验参数或历史说法，不是保证。MD-05 公式/图表预览的 300ms 是产品要求，应与“全文解析防抖”区分。正式计时边界和发布门槛按 V-05 冻结，三平台先 macOS 后 Windows/Linux 验证。

## 13. 错误、拒绝和安全降级

WC-01已确认：引擎只输出带身份/版本的领域诊断，UI在其上维护容量受限、按类去重、显式会话/文档/版本归属和生命周期的内存降级汇总并呈现；文档关闭释放相关条目、会话关闭释放集合，版本变化不采纳旧结果。不持久化正文/IME候选/敏感路径，不在引擎建thread-local或全局账本；具体容量/状态归V-06/V-09。WC-02已确认V1不新增通用UI命令panic捕获/回滚；受检预检/预演/原子补丁及既有有限资产隔离保持，不接入catch+drop_open。

下列名称为建议枚举变体，责任和零副作用契约必须保留，不用 Option 吞掉可诊断失败。

| 类别 | 典型原因 | 必须效果 |
|---|---|---|
| `DecodeError` | InvalidUtf8、UnsupportedEncoding、InputLimit | 不建有损文档、不覆盖原文件；source 返回类型/受检位置，UI 翻译 |
| `MappingError` | OutOfRange、InvalidBoundary、StaleProjection、Unmapped、AmbiguousEdit | 不执行推测的编辑；保留源选区/草稿，提供原文定位或重算 |
| `PatchError` | RangeOrder、Overlap、InvalidBoundary、LengthOverflow、Changed | 整批零修改、零历史步，不能部分提交 |
| `EditRefusal` | ProtectedRegion、Html、Code、Math、UnsupportedStructure、UnsafeRewrite、Changed | 反馈原因及受检源码入口，原文/选区/草稿/历史不变；定位 Source 是后续导航动作 |
| `ParseDiagnostic` | MalformedExtension、MappingUnavailable、BudgetExceeded、InvalidEventRange | 局部或整体原文回退；保留覆盖账本，禁用依赖失效语义的命令 |
| `InputConflict` | DraftBaseChanged、CompositionVersionChanged | 保留候选、本地输入与基线，交宿主重新定位/冲突处理；不默默取消组合 |
| 资产/I/O/任务错误 | 解码/渲染失败、过期、取消、写失败/冲突 | 按宿主对应事务处理，不能变成文档删除或伪成功 |

用户输入的无效范围、超限和不完整语法不得 panic；第三方 `catch_unwind` 最多是资产隔离的辅助，不能证明引擎安全。日志记录文档/任务身份、版本和错误类型，不把全文、候选或隐私路径内容作为默认日志。

Source 模式只解除 Markdown 产品只读限制，不解除 UTF-8/补丁版本/资源预算。源码回退仍有可能达到文件硬限额，必须明确拒绝而非声称“源码可以无限打开”。支持范围内正常夹具若只能回退，仍是未达标，不是完成验收。

### 18.2 依赖准入与未解决实现风险

仅 pulldown-cmark 的单解析器路线及 GPUI 精确锁快照是当前约束；具体版本以 M0 实际登记/lockfile 为准。`entities`/`emojis` 是 HTML 实体/短代码的历史候选，`similar` 是 diff 候选，`proptest` 是测试候选；引入时核用途、归属、版本/许可证和同类库，不因旧清单出现就全部添加。

第 1 组隔离消费者已实际解析 `pulldown-cmark 0.13.6` 的事件，并验证 toml/rust-embed 的当前 catalog 依赖组合，归属/精确 features/源码来源和纯候选闭包见[纯引擎候选审计](./validation/m0-engine-foundation/pure-candidates-2026-10-30/report.md)及架构 §3.2。此处只登记依赖可消费性，GFM/产品语法的运行期 Options 与映射/HTML 金样仍须第 6 组验证；不能将单一事件计数探针当作语法或保真验收。当前未准入实体/emoji/分段/随机/diff 等额外候选。

ratex/ratex-svg、mermaid-rs-renderer、usvg、syntect/two-face 属插件/资产候选，不让纯引擎为展示而直接依赖 GPUI。ropey 只在性能证据要求时评估；V1 禁 notify/regex/tokio/Wasmtime/WASI/动态宿主，与架构 §3.2 一致。2026-10-30 批准的 GPUI 0.3.9 精确例外仅适用 app/ui/plugin：regex 既有路径及 all-target 图中的非桌面 WASI p2 绑定，完整身份、边、target 与变更复审要求以架构 §3.2 为准；五引擎完整闭包继续无 GPUI、无禁用依赖。见[实际审计](./validation/m0-engine-foundation/admission-2026-10-30/report.md)，不能以单条合法路径掩盖其它入边，也不能把 metadata 过近似包视为实际启用或忽略解析失败。主题 ZIP/导出及 Unicode 分段等新增依赖按专项验证准入，不猜定后端或冻结旧版本。

后续实现的主要待验证影响：ED-01 决策阻塞已解除，组合期显式发布的等待/取消与结束后快照须按 V-07/V-08 验证；V-07 同时决定映射算法/有限 HTML/改写/命令金样能否安全开放；V-05/V-06 决定 StringBuffer、巨块与扫描预算是否满足目标；V-03 决定特殊语法后端覆盖；V-08 决定快照/重载/资源能否正确接线。任何一项缺证据，都不能以“旧项目跑过”代替。
