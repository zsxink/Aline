**2026-11-12 受控失败实验（engineering 2.2c，负结果；V-09 仍未整项通过）：** 用户按决定 §35 其六批准非侵入实验，不改产品代码、不注入后门。用 `sandbox-exec` 从进程外部剥夺 WindowServer 访问后启动同一 Release 二进制（`app_sha256=dbbb3340…`），两条剖面（仅禁 windowserver 服务 / 禁全部 mach-lookup）均得：进程存活、窗口数 0、stderr 无 `startup.window_failed` 文案、不自退；对照基线正常建窗（在屏 1、全部 6）、stderr 为空。**结构性依据**：锁定 `gpui-pre 0.3.9` 的 `Window::new` 全函数唯一可失败点是 `platform.open_window`，`MacPlatform::open_window` 唯一 `Err` 出口是 `WindowKind::AnchoredPopup`，`MacWindow::open` 返回 `Self` 而非 `Result`；Aline 使用 `WindowKind::Normal`，故 `open_initial_window` 的 `Err` 分支在锁定 macOS 后端下**结构不可达**。**结论：** 真实初窗失败收据仍未取得，且在当前后端下无法通过非侵入手段闭合；同时观察到「窗口服务不可达时无窗口、无提示、进程不退」是当前实际行为，属待裁决的产品质量缺口，本轮不提出实现方案。`deny-windowserver` 是人为条件，不等于用户真实环境。证据 `logs/validation/m1-single-window-readonly/2026-11-12-startup-failure/`。本段只记录负结果，不把静态结论写成平台通过。
