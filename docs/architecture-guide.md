## 0. 定位、权威关系与执行方式

本文规定跨 crate、跨模块的依赖、数据所有权、写入、传播与失败边界，回答“实现必须遵守什么、怎样判定违规”。架构指引负责 V1 模块与实施顺序，引擎指引负责解析、映射、输入和保真机制；本文引用这些契约，不冻结其中可替换的算法、目录或 Rust 签名。

权威按职责划分：AGENTS.md 规定架构铁律及工作规则，当前 PRD 规定产品范围与结果，已确认架构、引擎及专项规范约束实现，验证计划记录方法、证据状态与待验证边界；决定记录和确认归档用于追踪选择。阅读顺序不是同级规范的裁决优先级，同级资料无法按职责解释的冲突须列出，不能按日期、文件位置或实现便利自行选择。历史规范与调研不自动取得规范效力，已删除目录不作开发必需输入；证据入口见第 18/21 节。

适用仓库全部实现与评审。接口、实体、常量名称是契约示意，不表示已有代码。本文用 `R-章节-序号` 标识规则，`K-xx` 标识检查组；`AG-xx` 只保留给新增待确认问题，不能与规则编号混用。

| 等级 | 含义与例外处理 |
|---|---|
| **必须** | 可由当前铁律、已决定契约或其正确性边界支持的要求；条款表中的 R 规则均为必须。表内列出的例外才可直接使用，未列例外不能以实现方便放行 |
| **建议** | 可替换的组织或实现方式；替代方案须保持所属强制规则及对应检查，不因没有采用建议而拒绝合规实现 |
| **待验证** | 尚需 V-编号实验、样本或平台证据才能冻结的技术参数/能力；不能以旧项目成绩代替 |
| **待确认** | 资料无法裁决的行为或架构选择；不执行依赖该选择的分支，不将建议作为默认答案 |

**R-0-01（文档变更，K-08）：**影响依赖、所有权、公共契约或传播机制的实现，必须在实现前明确对应文档的变更方案，并随同交付可审查的回写和测试影响。技术方案替换记录依据、影响范围和验证；若改变铁律或产品契约，须取得相应裁决后再实施。例外不是注释中的豁免：须列原规则、理由、适用边界、替代保证、检查及退出条件；不能用下位规范授权违反上位契约。

## 1. crate 分层、依赖方向与准入

### 1.1 允许方向与职责

```text
app → aline-ui → aline-plugin → aline-edit → aline-markdown → aline-buffer
 │       │
 └───────┴──→ aline-source（独立文件字节层）

其余层 → aline-app-core（共享纯模型，无反向依赖）
GPUI 允许范围：app / aline-ui / aline-plugin
```

主链可向下直接消费公开 API，方向不表示所有相邻依赖都必须引入。source 由 UI/app 调用，不反向导入 buffer/UI 的类型；app-core 不导入应用或其他业务层。完整职责及模块规划见[架构 §4](./v1-architecture.md#4-crate-图职责与公开边界)。

| crate / 范围 | 必须守住的职责边界 |
|---|---|
| `aline-source` | 字节解码/编码、存储元数据、磁盘版本及受检 I/O 原语；不持有文档历史、窗口、计时器或目录单例 |
| `aline-buffer` | 源码、合法补丁、选区、锚点及历史原语；不解析 Markdown，不落盘，不依赖 source |
| `aline-markdown` | 带版本的解析、源码映射、语义/保护范围及纯数据扩展契约；不持有主题颜色或插件注册表 |
| `aline-edit` | 命令/查找/格式化的纯计划与校验，输出 Change 或拒绝；不自行写真实 Buffer、不弹窗、不调度 |
| `aline-app-core` | theme/settings/i18n 纯数据、校验与显式上下文查询；不注册字体、不安装主题、不存全局 locale |
| `aline-plugin` | 公共能力契约、注册/生命周期/分发、当前内置实现与宿主桥接；不依赖 UI，不直接写 Buffer，不自建保存队列 |
| `aline-ui` | DocCore、会话/资源/持久化协调、任务调度和采纳、GPUI 适配；是跨模块事务的编排入口 |
| `app` | 初始化、菜单和平台/单实例接线；调用 UI 服务，不复制编辑、保存或配置状态机 |

### 1.2 跨层检查规则

| 编号 | 约束、适用范围与例外 | 判定方式 |
|---|---|---|
| R-1-01 | 内部 crate 依赖仅沿上图允许方向；禁止反向依赖、循环，以及通过公共接口偷偷引入上层类型。source 独立，buffer 不依赖 source | K-01：Cargo metadata 的内部边及公开签名审查；图示逻辑调用不能替代 Cargo 方向证明 |
| R-1-02 | source/buffer/markdown/edit/app-core 五引擎 crate 的完整依赖闭包不得含 GPUI；可无窗口测试。不因 plugin 可以用 GPUI 而向下泄漏 GPUI 类型 | K-01/K-02：解析实际 `gpui-pre` package、别名及传递依赖；各引擎无头构建/测试 |
| R-1-03 | UI 控件、菜单、插件及 app 只能向所属协调器提交意图；文档写入归 DocCore，文件事务归 UI 协调器。允许内部 buffer 补丁原语被该入口调用，不允许对外暴露可随意写的 Buffer 句柄 | K-01/K-03：可变句柄与调用链评审；不同入口执行同命令结果一致 |

### 1.3 依赖准入与拆分

| 编号 | 约束、适用范围与例外 | 判定方式 |
|---|---|---|

| R-1-05 | 仅 pulldown-cmark 解析 Markdown；同类功能不得再引第二库。V1 禁 notify、regex、tokio、Wasmtime/WASI 和动态插件宿主；不以导出或测试路径绕过 | K-01：覆盖 workspace 成员、features、目标平台及构建/测试依赖；不能只搜 import |

| R-1-07 | 新增模块或拆 crate 必须说明职责/所有者、公开契约、依赖影响和验证。当前按八 crate 推进，不因目录美观提前拆分；新增 crate 先记录架构变更，不能靠拆分绕过铁律 | K-08：职责冲突或编译/性能/隔离证据及替代方案；不设“等到编译一分钟才允许拆”的门槛 |

**建议：**渲染后端与重资产依赖沿当前架构放在 plugin 的内置提供者，平台/资源适配放在 UI/app；纯引擎不为展示引入资产后端。历史“所有图像/SVG 依赖只能直接出现在 plugin”不升级成排斥 UI 解码职责的通用禁令；实际归属逐项按 R-1-04 审查。

## 3. 唯一真源、状态所有权与传播

### 3.1 数据所有权账本

下面的“所有者”是逻辑写入责任，不要求固定使用某个 Rust 字段布局。其余模块只能借用、提交意图或持有标明来源的不可变副本。

| 数据 | 唯一所有者 / 写入者 | 派生与失效触发 |
|---|---|---|
| 已提交源码、历史及源码选区 | UI 的 DocCore 持有 buffer/history，经统一输入/Change 协议写入 | 内容提交、Undo/Redo、重载推进 DocumentRevision；行索引/锚点同事务更新 |
| 打开块草稿、待定输入组及组合态 | DocCore 的唯一输入状态机；平台适配只转发 | 每次草稿/组合变化更新 draft_generation，取消也不复用旧代次；输入投影另有身份 |
| 当前全文 | 上述 Buffer + 至多一个受控源码替换的逻辑视图 | `WorkingVersion = (DocumentRevision, draft_generation)`；搜索/保存等统一取当前快照 |
| 原 bytes、BOM/行尾策略、DiskVersion | 文档会话的存储基线，由持久化协调器在成功读取/写盘后更新；source 处理字节 | 不随 Undo/Redo 回退；失败不更新；不是第二份可编辑全文 |
| Parsed、块/Gap、来源映射、保护/导航索引 | DocCore 采纳 markdown 的不可变结果 | 文本/解析配置改变即失效；禁止在渲染中修补可变树 |
| 查询、统计、格式化差异 | 所属功能状态，由 DocCore/会话协调管理 | 工作版本、查询/请求代次、规则或选区改变即作废 |
| DocumentId、路径关联、写队列 | UI 应用级 SessionRegistry 与每文档 PersistenceCoordinator | 身份稳定；路径变化另增代次，作废相对资源及目标相关任务 |
| 资源身份、文件版本、当前/历史/恢复/在途引用 | UI 资源协调器，与持久化流程共同提交关联 | 资源/路径/引用变化；非可丢弃缓存，清理按 §15 |
| 主题/设置/locale、插件有效状态 | app-core 提供纯模型；UI 应用服务持有/发布权威配置，插件 lifecycle 维护由其驱动的能力状态 | 发布有效配置/插件代次；窗口与插件只消费快照，不各自落一份权威配置 |
| 窗口布局、标签视图、滚动/焦点 | 各 Workspace/TabViewState | tab 引用身份；不持有独立 dirty 或文档写副本；持久字段受 TA-03 限制 |
| 布局/图像/公式/图表/高亮缓存 | 对应 UI/资产服务 | 按实际输入与环境键失效，见 §7 |

**R-3-01（文本真源，K-02/K-03）：**禁止第二份可独立编辑的全文模型和双向同步。只读 SourceSnapshot、存储基线 bytes、导出冻结文本、查找字符串和唯一草稿允许存在；不能用“UI 有 String 字段”一刀切判违规。只读副本须带来源身份，不能反向覆盖新内容。

**R-3-02（当前快照，K-03/K-04）：**保存、恢复、导出、搜索及切模式读取同一当前内容协议，包含未离块的输入；取快照不封口输入组、不记步、不清 redo。允许任务启动时物化，禁止每键复制全文。组合期显式保存/另存为/导出按已确认 ED-01 进入可取消等待，平台自然确认或取消后取结束后的当前快照；不发布预编辑候选，取消请求不改输入/历史。

**R-3-03（版本分工，K-03/K-04）：**DocumentRevision 单调推进，包括 Undo/Redo/重载；WorkingVersion 覆盖草稿和组合变化。DocumentId、路径代次、DiskVersion、查询/请求/配置代次分别使用，禁止一个 `edits` 计数器兼任所有身份。投影映射须区分模式和具体块，不因全文版本相同复用上一输入投影。

### 3.2 每帧与高频路径

**R-3-04（热路径，K-07）：**render/布局读取派生快照和可见范围；按键、选区移动等高频 UI 路径不执行全文解析、指纹/等价比较、统计、序列化、配置文件读取/解析或文件 I/O，不同步解码资源。读取已发布的类型化配置快照允许。组提交/显式命令触发的昂贵计算由状态所有者调度；是否可同步执行某段纯计算须有 V-05 预算证据，不能因函数名叫 commit 就允许长时间阻塞。

**R-3-05（分配，K-07）：**预格式化文本与可复用派生数据由所属缓存准备，render 不反复生成整篇 String/Vec。可见元素/局部几何分配不在通用禁令内；评审查分配量是否随全文而非可见范围增长，V-05 测巨型单块，不能用“大对象”这种无判据表述代替测量。

### 3.3 阈值、超时和资源预算的单一来源

**R-3-06（配置归属，K-01/K-07/K-08）：**每个产品默认值或技术限额有一个定义者；跨层通过类型化配置/预算传递，不各写一份常量。产品默认值映射 PRD/需求编号，技术参数记录 V-编号、单位、触发条件、拒绝/降级、可配置性和证据。公开常量仅在跨 crate 消费必需时导出，不强制全部 `pub const`。文档保留可审查数值及来源，代码形成后关联名称，不能禁止 PRD 记数字。

| 类别 | 定义者与使用者 | 当前状态 |
|---|---|---|
| 900ms 相邻普通输入组 | buffer/history 的纯分组参数，宿主传时间 | TA-01/EDIT-06 已定；具体计时/相邻性样例 V-07 |
| 1 秒自动保存、10 秒恢复 | UI 会话/持久化策略 | SAFE-04/08 已定；不把恢复周期当自动保存周期 |
| 300ms 公式/Mermaid 预览 | UI 资产调度消费插件配置 | MD-05 已定；不是全文解析防抖 |
| >4 MiB 默认 Source 且阈值可配 | 应用设置模型定义、UI 模式策略消费 | PRD §7.2 已定；不是文件硬上限 |
| 同步解析界限、全文防抖、overdraw、缓存/历史/资源限额 | 领域定义预算结构；UI 汇总并传给任务，具体值经验证冻结 | V-05/V-06；主题解包/字体另属 V-04。旧 128 KiB/300ms/40rem 不冻结 |

### 3.4 事件、回调与重复触发

**R-3-07（单向变化，K-03/K-04/K-08）：**子视图/插件向所有者发送语义意图；所有者先校验并提交，再发布带身份/版本的变化。订阅者只失效/刷新派生数据，不把收到的 Changed 无条件再写回源。一个意图由一个入口提交；回执只更新其请求状态，不能再触发同一提交。菜单、快捷键和右键共享命令身份/门控，执行时重验条件。

**R-3-08（生命周期，K-04/K-05）：**跨实体订阅/回调须声明拥有者、取消/释放点及重入行为；关闭目标不被强引用意外保活。允许 UI 注入平台服务及受控 handler，禁止引擎保存反向操纵 UI 的闭包。具体 EventEmitter/WeakEntity API 及 handler 类型由锁定 GPUI 决定，不以“实体内有回调”直接判违规。评审跟踪一个输入到提交/解析/自动保存的事件链，测试重复事件、重入和关闭后回调不重复提交。

## 4. 坐标系与映射边界

| 编号 | 约束与边界 | 判定方式 |
|---|---|---|
| R-4-01 | 文档持久选区/命令/历史使用所属源码快照的 UTF-8 字节坐标。按 RS-02，跨模块/跨 crate 的源码、绘制、UTF-16 偏移和范围须 newtype/受检封装，模块内部单坐标可明确命名 usize；补丁原语保留 `Vec<(Range<usize>, String)>` 并在受检边界转换。局部字节、磁盘字节与像素明确命名和版本，偏移禁裸名 `pos`/`idx` | K-01/K-02：类型/命名与 API 审查；UTF-8/UTF-16 非法端点拒绝，具体类型布局不改变分层 |
| R-4-02 | 源码/绘制/块局部/输入 UTF-16 的转换统一走 markdown 映射层，包括恒等路径；补丁后源码锚点变换归 buffer，存储 bytes 转换归 source。UI 只做像素命中与几何，不手算 `src_off - range.start` 或重建 UTF-16 表 | K-01/K-02/K-05：调用点审查、映射属性及真实命中；不是禁止映射实现内部受检运算 |
| R-4-03 | 映射结果保留投影身份、版本、方向和来源/精确性；隐藏、合成、多对一不能冒充精确编辑范围。失效或歧义时重算/源码定位，禁止猜区间应用编辑 | K-02/K-03：实体/转义/重复空白/emoji/组合字符、无可见文本、过期布局金样 |

详细契约引用[引擎 §7](./engine-design.md#7-源码绘制文本与其他坐标)。不在本文冻结 Escapes 存储、尾部字符回找或 LineMap 算法；不要求任意源码字节严格双射。UI 输入 UTF-16 只在平台边界使用，内部状态不据此另建源码选区。

## 5. 命令、输入组与编辑事务

| 编号 | 约束与例外 | 判定方式 |
|---|---|---|
| R-5-01 | 任何内容变化通过 DocCore 的明确输入/命令事务。Change 绑定当前工作版本、选区/语义前置条件、同基线源码补丁、目标选区及分组原因；UI/插件不能拿裸范围直接改 Buffer | K-02/K-03：公开写入口与 Change 调用链；执行时重验，不信任菜单打开时状态 |
| R-5-02 | 在真实写入前完整预检：版本/源片段、UTF-8 边界、范围升序不重叠、长度运算、after 选区、保护/命令能力。必要的预演/reread 也在应用前，验证命令宣称保留的源片段/语义，不只比较可见文字 | K-02/K-03：非法最后一个补丁、隐藏 HTML/链接、删除/任务框预期差异；整批成功或整批零修改 |
| R-5-03 | 发布文本、行索引、选区、revision 和历史是一个提交边界；拒绝保持调用前文本、草稿、组合、选区、undo/redo，不产生空步。若命令需先处理待定组，先在候选状态准备并重验，不能先清草稿再拒绝 | K-03：拒绝前后完整状态比较；源入口定位是拒绝后的独立导航动作 |
| R-5-04 | 至多一个打开编辑块，普通输入组提交一个源码区间，排除尾部分隔换行。提交与关块分离，按 900ms/IME 分组；离块只处理剩余组，不压缩/重复已有历史。结构命令可显式修改 Gap，多区间命令一组只记一步 | K-02/K-03：TA-01、引擎 I-02/03，块+Gap 覆盖及长时间同块逐组撤销 |
| R-5-05 | Visual/Source 共用文本与历史；切模式自身零字节/零历史步。Undo/Redo 恢复内容及源选区，按统一协议先处理当前待定组；子编辑器不另建文档历史 | K-03/K-05：两模式交错、输入中保存、离块、Undo/Redo；AC-02～05 |
| R-5-06 | 基线失配时保留草稿/组合和选区，交 DocCore 重新定位或冲突处理；未有当前版本映射时不按旧块下标开块。不允许 `drop_open()` + 日志代替保护输入 | K-03/K-04：外改/重载与点击/输入交错，不写旧范围也不丢字 |
| R-5-07 | 所有可视化写入口统一执行 MD-11 保护，含跨块删除/粘贴、查找替换和插件意图。HTML 则拒绝触及/跨边界的格式与块命令，允许受检的原始 HTML 编辑，不将 HTML 整体设为只读。导航/复制允许；Source 解除产品只读限制但仍验版本、字符和预算 | K-02/K-03：脚注引用子区间、灰色区、HTML 原文可改/格式拒绝、普通正文仍可改；AC-08/09 |
| R-5-08 | 查找读取含草稿源码，结果带工作版本/查询代次及命中文本；替换前重验。全部替换一次事务一步历史；格式化仅手动差异确认，输入变化作废旧差异，取消零修改 | K-03/K-04：FIND-01～03、FORMAT-01/02；AC-08/17，金样 V-07 |

## 6. 并发、异步结果与任务生命周期

### 6.1 线程与共享状态

| 编号 | 约束与边界 | 判定方式 |
|---|---|---|
| R-6-01 | 五引擎 crate 零线程、零全局状态，不创建执行器/运行时、线程或计时器；配置、预算、时间显式注入。编译期不可变表允许；运行期全局可变表/惰性注册缓存不允许 | K-01/K-02：调用/依赖扫描加人工审查、可注入时间/预算的单线程测试；不把 `OnceLock` 隐藏在 helper 中绕过 |
| R-6-02 | 调度归 UI 状态所有者，app 只适配平台；引擎不持有用于并发编排的共享可变锁。后台只接不可变输入/私有任务数据，不捕获可变 Buffer 或 UI 实体；UI 不以 Arc<Mutex<DocCore>> 另建并行写路径 | K-01/K-04：所有权、捕获及锁用途审查；同步读写原语在 source 不等于 source 可自行 spawn |
| R-6-03 | UI 状态采纳串行进行，不持锁跨 await/调用未知回调或等待 I/O；共享只读快照允许。锁/共享可变对象必须说明数据所有者、获取顺序、作用域及无环依据，不能代替主线程消息/意图通道 | K-04/K-08：锁范围与重入评审、竞争集成；无锁设计无需虚构锁清单 |
| R-6-04 | 防抖/任务归其状态所有者，不由多个视图各开保存/解析计时器。可见动画/光标计时属于视图，不能用“视图有定时器”笼统判违规 | K-04/K-05：一文档一条调度链、重复事件不重复保存；UI 时钟可替换以确定性测试 |

### 6.2 结果采纳矩阵

**R-6-05（采纳门，K-04）：**每条异步出口携带其实际输入键；先验目标生命周期/DocumentId，再验任务、文本、路径及配置依赖。不是只验一个 stamp，也不是所有结果都要求等于当前文本。各任务至少满足下表；不适用维度可省略，理由在接口说明中登记。

| 任务 / 所有者 | 采纳判据 | 失效与失败出口 |
|---|---|---|
| 解析 / DocCore | 当前工作文本版本、解析配置一致 | 丢弃过期候选、调度最新；新映射前保留安全源码入口 |
| 查找/统计/格式化差异 / 所属功能状态 | 工作版本、query/request 代次及相关规则/选区相符 | 作废而非冒充零结果；差异需重生并重新确认 |
| 公式/图表/高亮 / UI 资产服务 | 内容/语言、有效主题参数、插件启用代次、目标槽位相符 | 旧结果不挂新内容；失败保留源码，关闭后不能复活 |
| 图片/图片 tab / UI 资源服务 | 资源身份、文件版本、路径代次及目标视图存活 | 失败占位保留引用；路径变更重解析，不挂旧路径图片 |
| 保存/恢复 / 持久化协调器 | 当前文档身份、对应请求/目标队列和资源清单；登记实际写入快照 | 不以“当前文本已变”否认已发生的写盘；较新输入仍脏，旧目标不更新新路径，旧失败不覆盖新成功 |
| 导出 / UI 导出协调器 | 对应 request_id、冻结输入/配置/资源及确认过的输出目标 | 可交付明确版本的旧文本产物；不覆盖新请求状态、不未经确认覆盖文件 |

**R-6-06（取消与关闭，K-04/K-05）：**取消、插件关闭、路径/模式改变及文档关闭时，所有者作废相关任务的结果采纳资格并撤订阅；任务持有的资源引用，须在计算/I/O 实际完成或确认停止并结算后才释放，不能在发出取消请求时提前释放。协调器保留结算身份，不能把“丢弃回调”当作写入没有发生。应用退出共用关闭 guard，未完成写盘不得提前报保存成功/清恢复材料；等待或取消处理须通过 V-08 的关闭样例，不新设未确认的退出超时。

**R-6-07（真实资源限制，K-04/K-07）：**取消不保证计算已停；每条昂贵任务须有输入/输出/队列/并发预算与可说明的终止策略，循环合作检查或宿主限制实际消耗。不能只隐藏超时结果任由任务无限占用资源。具体数值按 V-05/V-06，后续隔离选型不能自行引入被禁运行时。

## 7. 缓存所有权与失效

**R-7-01（派生缓存，K-04/K-07）：**缓存只存可重建派生数据，有明确所有者、来源键、失效触发和淘汰预算；源文本、草稿、历史及仍被引用的恢复资源不能当普通缓存淘汰。内存预算待 V-05/V-06，不允许无界应用全局缓存。

| 缓存 / 所有者 | 最小依赖 | 谁在何时失效 / 期望结果 |
|---|---|---|
| Parsed/保护/导航 / DocCore | 源文本及解析配置 | 提交/草稿相关变化/配置更新时立即标不适用；不等重算完才作废旧编辑权限 |
| 映射/UTF-16/字素索引 / 映射数据所属投影 | 源片段、投影种类/身份/版本 | 输入/组合、开块切换或展示变换改变时作废；旧索引拒绝输入回调 |
| 布局/块高度 / UI render | 文本/投影、字体代次、宽度、缩放、换行、有效排版 token | 主题/字体激活/宽度/换行更新时失效测量，保留源码滚动锚点 |
| 语义/语言高亮 / 对应服务 | 文本/语言规则；颜色另依赖有效代码配色 | 源文/语言变更重算语义，配色变更更新颜色；关语言高亮不关核心 Markdown 着色 |
| 资产 / UI 资产服务 | 内容/语言、有效颜色/背景/尺寸、插件代次、资源文件版本 | 输入/配置/开关/文件改变后旧结果不进新槽；theme_id 相同也可能需重算 |
| 相对资源路径 / UI resources | DocumentId、路径代次、引用及资源设置 | 保存迁移/移动/重命名提交关联时失效；引用新基准可解析 |

**R-7-02（失效协议，K-04）：**写入/配置所有者在提交时发布明确失效或推进来源键，消费方在使用和异步回填时重验。时间到期不是正确性判据，框架 notify 不是版本校验。缓存键按实际依赖设计，不强制每种缓存全文 hash；内容身份不能仅凭未核验 hash 判等。

**R-7-03（复用安全，K-02/K-04）：**结构及源片段相同才有复用候选，相关配置/全局语义相容后才能复用；前文编辑后更新定位，禁止把旧绝对范围挂在新文本上。内容已变的旧资产不能冒充新预览；主题重算期间复用旧外观须明确仍属同一内容。算法粒度按 V-05，删除旧“V1 禁一切节点缓存”的无条件禁令。

## 8. GPUI 与状态实体边界

本节只约束生命周期、数据写入与适配责任。用户可见布局、焦点、浮层、菜单与已确认 UI-01～UI-06 由[UI 规范](./ui-spec.md)承接；具体 GPUI 调用及视觉尺寸仍按锁定版本和 V-01/V-09 验证。[历史 Zed 笔记 §0](./archive/migration-evidence/zed-notes.md)明确主线与 `gpui-pre` 有代差，旧签名不作可直接调用的要求。

| 编号 | 约束与边界 | 判定方式 |
|---|---|---|
| R-8-01 | GPUI 只在 app/UI/plugin 允许范围；纯逻辑状态不含 Entity/Window/FocusHandle，UI 适配保存平台句柄和几何，不保存第二份业务状态 | K-01/K-02/K-05：类型/依赖与无头状态机测试 |
| R-8-02 | render 只读业务快照并构建元素，不提交编辑、不写配置/文件、不在 render 中 notify 自激刷新。布局测量可在框架许可阶段回填派生几何，须有收敛条件，不能形成每帧测量→通知死循环 | K-05/K-07：渲染调用链与空闲/尺寸变化测量；具体 prepaint/paint API 按锁定版本验证 |
| R-8-03 | 状态变化由所属实体/服务通知；动画按有效需求请求帧，禁止 RAF 轮询业务状态或布局。虚拟元素身份在复用/重定位后仍对应正确内容，不以可变块数组下标充当文档身份 | K-05/K-07：空闲帧、前文插入/虚拟复用后的焦点/拖拽/选区测试；不冻结“一键一帧”数值 |
| R-8-04 | 文本/选区/IME 语义归统一输入状态机；平台适配负责 UTF-16 事件、候选窗几何和焦点借还。不能以 Blur/Escape 猜平台确认/取消，不能因菜单借焦点丢组合/输入 | K-03/K-05：真实输入法、候选替换/取消、借焦点/切块/切模式；AC-03～05，含 ED-01 已确认的显式请求等待/取消分支 |
| R-8-05 | 启动初始化及测试接线各有可追踪入口，避免重复注册；所有关闭入口共用 guard。浮层/输入入口统一维护焦点与键盘语义，关闭回到可用上下文，不绕过未保存保护 | K-05：系统/自绘关闭、批量关闭、菜单弹窗键盘路径；不要求某未核实 FocusScope/Toaster API |

## 9. 组件形态与复用

**建议选择：**无持久状态的视图用普通函数或构建器；需观察、输入或跨帧状态的控件用宿主实体；仅元素实例的短暂视觉状态用锁定版本支持的局部状态。第二个真实使用者需要共同能力时再评估 trait，不为假想组件库预建抽象。

**R-9-01（组件边界，K-05/K-08）：**无论采用哪种形态，组件不能成为文档、配置或持久化的第二个写入所有者；业务操作输出语义意图，复用通用能力。输入语义、像素布局与外壳样式的职责可分开验证；共享控件不得把文档编辑历史复制为控件自己的历史。

**R-9-02（主题消费，K-05/K-06）：**组件从当前有效配置/主题快照取得语义样式，不永久缓存不带代次的 token；几何计算值不伪装成主题字段。组件变体使用同一映射入口。具体色值、间距、动效和图标细则归 UI/主题规范，不以扫描所有 `px()` 代替设计检查。

旧固定三形态、文本输入文件名、统一闭包签名、220ms 动画、1px 焦点、每窗 Toaster、浮层 `raise` 均不作为本文件强制实现方案。对应产品交互仍须通过 PRD 与 V-09 验收，不能因细节移出而省略键盘、焦点或错误反馈。

## 10. 渲染、虚拟化与资源绘制

| 编号 | 约束与边界 | 判定方式 |
|---|---|---|
| R-10-01 | 可视化按变高块虚拟化，Source 按行虚拟化；视图仅消费匹配版本投影。估算、实测高度和滚动锚点由 UI 管，不通过修改源文本稳定布局 | K-05/K-07：长文/变高资源、模式切换和滚动定位；具体 list/高度 Option 语义核对锁定版本 |
| R-10-02 | 巨型单段/表格不因“只有一个块”绕过预算；源内容、映射及布局安全未满足时提供受限源码入口/诊断，不静默截断 | K-07：V-05/V-06 巨块与资源密集夹具；降级不算完成基线能力验收 |
| R-10-03 | 图片、公式、图表、高亮经宿主任务/资产服务计算；渲染只画已采纳结果或占位，不触发同步解码/网络/写盘。资产尺寸变化只失效相关布局 | K-04/K-05/K-07：错误/慢资源不阻塞输入，过期结果不改变新内容/高度 |

公式/Mermaid 上源码下预览是块内产品布局，不是需要浮层的架构要求；HighlightKey 排序、overdraw、ScrollAnchor/resize API 等方案移交专项验证，不冻结参考项目的内部实现。

## 11. 性能规则与反面实证

**R-11-01（测量，K-07）：**性能结论必须标明设备/系统/锁定版本、Release、样本复杂度、冷/热、计时边界及 P50/P95、最长 UI 停顿与内存。引擎处理、组提交与端到端呈现分别计时，排队不能从体验指标中隐藏。按 V-01 先 macOS 后 Windows/Linux，不用一个平台替代全平台。

**R-11-02（门禁来源，K-07/K-08）：**PRD §7.2 处理预算是当前目标，发布门槛及资源限额经 V-05/V-06 冻结并回填。不能把旧“帧 ≤16ms、解析 ≤50ms/128KiB、回归 10%、一次输入一帧、失焦 250ms”当当前发布门禁；128 KiB 的产品目标是块提交处理，不等于单独解析耗时。优化须通过正确性回归及实测，不以删功能/调小阈值冒充达标。

### MarkFlow 反面实证的适用边界

## 15. 持久化、文件与多资源事务

### 15.1 所有权、保存状态及外部变化

| 编号 | 约束与边界 | 判定方式 |
|---|---|---|
| R-15-01 | 每文档只有一可写会话与串行写盘协调器；手动/自动保存、另存为及路径操作不竞写。全应用身份登记覆盖重复进程转交；路径变更不换 DocumentId，不仅凭文件名/hash(path) 判身份 | K-04/K-05：大小写/链接别名/移动/未存在目标与双进程 V-01/V-08；tab 不各开队列 |
| R-15-02 | 原文档字节编码及受检替换归 source；图片/恢复/设置/主题/导出由 UI 对应服务编排，其磁盘操作不因不在 source 就自动违规。各写目标须有唯一负责的提交入口及失败保全规则，禁止业务回调任意直写 | K-01/K-04：按目标类别审查写调用与队列，不能仅搜全仓 `std::fs::write` 作结论 |
| R-15-03 | 未修改保存返回原 bytes；有实际修改才按存储基线重放 BOM/行尾多数派，平票 LF；不丢孤立 CR、不补尾换行。无效 UTF-8 拒收，不有损转换、不覆盖原文件 | K-02/K-04：SAFE-01～03、AC-01/02；混合行尾统一是明确例外，其余无关字节保持 |
| R-15-04 | dirty 来源是当前内容相对实际保存基线的等价事实，含草稿；保存中/失败/自动保存暂停各有状态。禁止用栈深、revision、粘性“编辑过”或未核验 hash 命中当内容相等。所有标签/状态栏/关闭 guard 共用此事实 | K-03/K-04：同深分支、历史裁剪、中途保存后继续同组、撤销回保存内容；等价结果待定保守判脏，不每键全文比较 |
| R-15-05 | 聚焦及任何写盘前检查外改，mtime/size 只快筛；覆盖确认绑定刚确认的目标版本，再变须重检。冲突暂停自动保存，无本地修改才自动重载；删除/不可读保内存，不当空文件 | K-04：同 size/mtime 内容变化、再次外改、删除、权限、草稿/组合未提交；SAFE-07、V-08 |
| R-15-06 | 自动/显式载盘均建立可撤销历史边界，Undo/Redo 只改内存/选区、基线不退、不直写盘。撤销带回不同旧内容时判脏、提示并暂停自动保存；显式保存/另存为成功或 redo 回磁盘基线才恢复正常策略 | K-03/K-04：TA-02、AC-06；旧历史仅在正确文本上下文使用 |
| R-15-07 | 文档受检替换失败保留原文件、内存及恢复材料，不先删原文件、不原地截断、不偷偷回退非原子写。成功登记实际写入版本/bytes/路径，不能把期间的新输入标已保存 按WC-04，只有权限复制错误明确属于不支持且临时文件创建/替换访问语义已有平台安全证明时才可继续，并说明实际保证；其他权限失败停止保全原文/内存，mode不等于ACL/xattr，V-01/V-08仍未执行。 | K-04：写入各阶段故障、磁盘满/占用/权限、乱序回执；V-08 记录替换/权限/同步平台保证和竞争窗口，不称为跨进程 CAS |

### 15.2 资源、恢复、路径和关闭

**R-15-08（多资源发布，K-03/K-04）：**UI 协调快照、资源计划、目标版本、文档补丁及路径关联。先确保资源可用再发布引用；首次保存/另存为引用重写仍走历史协议，写盘失败不留下坏引用，继续输入须重验/重规划，禁止用旧候选全文覆盖新输入。原文档/资源保留，手写外部引用不静默迁移。多文件不是一次内存原子事务，须逐步定义成功、失败、重试和可恢复中间态；允许保留可恢复副本，不允许伪成功或提前清理。详细流程由[架构 §7.4](./v1-architecture.md#74-图片另存为恢复与路径事务)及 V-08 形成，不在本文件固定文件名/提交算法。

**R-15-09（资源存活，K-04）：**资源协调器追踪当前内容、undo/redo、恢复记录和在途任务引用。撤销插图只撤引用，不自动删除资源；临时资源按 DocumentId 隔离。恢复记录与资源齐备后共同发布，清理按 PRD §5.12 状态表；取消/失败/异常退出/恢复后未保存不删，仍被任何有效引用需要的资源不删。重试须识别此前阶段结果、避免重名覆盖/重复插引用；具体回收策略由 V-08 证明，不把缓存淘汰当资源清理。

**R-15-10（身份/路径事务，K-04/K-05）：**移动/重命名统一预检重名/身份碰撞、目录自身/后代、未完成任务及引用影响；文件操作成功后同步所有标签、图片预览、工作区、恢复关联并失效路径缓存。失败保留源文件；跨卷/外部拖放及回收站不可用行为待 V-08，不静默覆盖或改永久删除。

**R-15-11（恢复与偏好，K-04/K-05）：**恢复先进入内存，不覆盖磁盘，损坏条目隔离反馈不影响其他条目。工作区偏好与异常恢复分开：按 TA-03 常规启动一个窗口，仅恢复最后根及侧栏/布局偏好，不恢复 tabs/活动标签/文档选区/滚动会话；显式打开不额外开偏好窗口。非法偏好回有效默认，不阻止启动。

**R-15-12（关闭 guard，K-04/K-05）：**批量关闭逐 tab 保存/放弃/取消；取消、保存失败或冲突未解决停止后续关闭。已关闭者不重开，当前/未处理者保留状态及恢复材料；图片只读 tab 无 dirty/保存询问。所有关闭入口共用协议，在途任务按 R-6-06 结算，不用窗口销毁掩盖失败。

路径服务由 app 初始化并注入 UI/source 原语，不使用 `aline_source::paths` 全局 OnceLock。偏好存储版本化及校验是要求，“运行布局必须直接 Serialize 同一个类型”不是架构铁律，不能因此序列化 GPUI 句柄。
