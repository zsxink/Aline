# Aline UI 与交互规范

本文把产品原型评审中明确确认的界面与操作要求固化为 V1 验收规范。引擎行为与功能范围仍以 [v1-features.md](./v1-features.md)、[v1-architecture.md](./v1-architecture.md) 和 [architecture-guide.md](./architecture-guide.md) 为准。

## 1. 参照来源与优先级

1. MarkFlow 当前桌面应用是 Aline 的界面结构和交互参照。复刻范围包含主窗口、设置页、弹窗、菜单、浮层及其他窗口；验收不能只覆盖主编辑窗口。
2. 应用身份使用 Aline 的名称和图标。其余界面组成、操作位置、状态反馈与窗口行为按 MarkFlow 对照实现。
3. 已明确确认的浅色主题要求优先于 MarkFlow 原有配色：采用素白画布与 GitHub Primer 风格的中性色、蓝色交互强调色；颜色同时与 Aline 图标协调。
4. MarkFlow 的功能只迁移 V1 功能清单允许的语义，不复制源码，也不因视觉复刻扩大 V1 功能范围。
5. 做 MarkFlow 对照验收时，记录参照应用的版本或提交、窗口尺寸和操作状态；双方使用相同尺寸与状态截图比较。每个控件的默认、悬停、按下、选中、禁用和弹出状态都要对照。

## 2. 浅色主题

- 编辑画布使用纯白色。
- 采用 GitHub Primer 风格的正文与边框中性色、蓝色主强调色和浅灰代码底色；当前原型锚点为：画布 #FFFFFF、正文 #1F2328、次级文字 #59636E、边框 #D1D9E0、强调色 #0969DA、代码底色 #F6F8FA。
- 语法高亮色与 Aline 图标和强调色协调；不同语法 token 保持可辨认和足够对比度。
- 主题色必须通过语义 token 维护。组件不得各自引入与主题无关的硬编码颜色。浅色主题验收不能以灰白画布替代素白编辑画布。

## 3. 图标与操作细节

- 图标、尺寸、描边粗细和状态色使用一致的图标系统，功能图标应与 MarkFlow 对应操作一致。
- 图标必须对应可用操作；工具栏、文件树、标签页、设置、图片和代码块控件需要核对点击目标、悬停态、禁用态、选中态及键盘焦点态。
- 图标颜色使用主题语义色，并与 Aline 图标协调；不能用无关的装饰色代替状态表达。
- 不改变 MarkFlow 的操作含义时，不得只复刻静态图标而遗漏菜单、提示、确认或状态反馈。

## 4. 代码块呈现与操作

围栏代码块和缩进代码块在可视化模式中使用完全相同的外观和控件，不按 Markdown 写法区分样式。

- 代码块显示从 1 开始的行号；空行占行号，软换行不额外编号。
- 语言和复制控件位于代码块右上角。鼠标悬停代码块或键盘焦点进入代码块时显示控件。
- 控件直接贴合代码块顶部，不另设标题栏、分隔线或独立留白区。代码区顶部只为控件留必要空间；当前原型验收值为 22px，控件高度为 18px。
- 语言选择按钮显示当前语言；常见长名称可使用紧凑别名，例如 TypeScript 显示为 ts。
- 语言菜单紧贴语言按钮下沿展开，不留垂直间隙；支持搜索，菜单宽度约 220px，搜索框高度约 32px，选项上下内边距约 3.5px。菜单整体保持紧凑，避免大尺寸空白和宽卡片。
- 未识别或未列出的语言按纯文本显示，不阻止打开文档。
- 复制按钮复制当前代码块的代码内容，不包含行号和界面控件。复制成功后按钮图标变为勾号约 2 秒，再自动恢复；此操作不显示 toast 或其他提示气泡。
- 更改语言只影响当前代码块的语言标识与相应高亮，不得改写代码正文。

### 设计原因

语言菜单贴住触发按钮展开，让按钮与选项保持明确的从属关系，避免菜单像独立浮层一样悬空，也减少菜单打开时多余的视觉断层。

## 5. Markdown V1 展示夹具

- 原型必须提供可直接打开的 Markdown 示例文档，覆盖 [v1-features.md 第 5 节](./v1-features.md#5-行内与块级元素) 中每一种列入 V1 的行内和块级语法。
- 示例文件树根目录提供 `README.md` 作为示例入口，简要说明各示例文档内容与素材位置。
- 展示内容应包含有代表性的长短内容、嵌套层级、空行和边界状态，便于检查实际渲染与交互；不能只用占位符标题代替功能示例。
- 正式实现验收以 V1 功能清单为准。原型夹具需和 V1 清单保持同步；清单新增或移除语法时，夹具与本规范链接的范围一并更新。

- [ ] 多标签栏的标签内容可横向滚动且不显示滚动条；右侧新建和标签列表按钮固定可见。
- [ ] 当前标签或鼠标悬停、键盘聚焦的标签显示关闭 X；悬停关闭按钮时出现浅色圆形底。
- [ ] 新建按钮创建标签；相邻的列表下拉按钮显示所有打开标签，选择后切换到对应标签。
- [ ] 打开的标签列表没有内部横线分隔；“全部关闭”操作固定在顶部，只有下方标签条目区域滚动。
- [ ] 当前打开文件名使用主题强调色显示；“全部关闭”关闭全部已打开标签并显示无文档状态。
- [ ] 浅色画布为纯白，GitHub Primer 中性色、蓝色强调色、语法色与 Aline 图标协调。
- [ ] V1 Markdown 每项语法都有可打开的示例。
- [ ] 围栏和缩进代码块的外观一致，并显示准确行号。
- [ ] 代码块悬停或键盘聚焦时，右上控件与代码块贴合显示；语言菜单紧贴语言按钮下沿，且紧凑、可搜索。
- [ ] 复制只复制代码正文；成功时按钮显示勾号约 2 秒，无 toast。
- [ ] 语言变更不改动代码正文，未知语言以纯文本呈现。
- [ ] 源码模式与可视化模式使用相同的编辑区宽度和最右侧滚动条位置；源码输入区随内容增长，不显示独立滚动条，纵向滚动由编辑区外层统一处理。
- [ ] 文件浏览器顶部固定显示当前文件夹名，名称从最左侧开始且没有根目录折叠按钮；指针悬停文件浏览区域时显示新建文件、新建文件夹、刷新、展开/收起所有子文件夹四个操作。
- [ ] 原型文件树包含多层子文件夹和文件；文件夹可独立展开/收起，文件夹排在同级文件之前，文件缩进比所属文件夹更深。
- [ ] 批量按钮在所有子文件夹收起时显示“展开”操作；只要有任一子文件夹展开，就显示“收起”操作。
- [ ] 外观页提供白天、夜间、护眼模式和随系统切换；手动切换模式会关闭随系统切换，手动选择主题家族不会关闭。
- [ ] 外观页主题配置位于页面最下方，列出 GitHub、Notion、Vue、飞书及用户主题；每张主题卡只展示当前模式对应的实际预览图，悬停显示预览蒙层，点击后打开大图并可用左右按钮或方向键切换三种模式。
- [ ] 主题页提供打开主题文件夹、导入 ZIP、刷新入口；首次运行同步内置主题，ZIP 通过清单与三张图片校验后导入，刷新重新扫描目录。
- [ ] 点击主题卡片立即切换主题，并同步更新卡片选中态、主题强调色及当前模式预览；快速切换主题和外观页使用同一套选择状态。
- [ ] 点击“打开主题文件夹”直接打开主题目录，不再显示路径或预览图数量说明弹窗。
- [ ] 主题卡片的预览图右侧显示主题介绍，最多显示五行；超出部分默认裁切，悬停或键盘聚焦后显示完整介绍。标题旁显示“内置/已导入”状态，不在缩略图右侧留空放状态标记。

## 7. 多文档标签栏

- 标签内容区在横向空间不足时横向滚动，滚动条保持隐藏；触控板横向滚动和鼠标滚轮都可在标签栏上移动标签。
- 新建标签按钮和打开标签列表按钮组成固定在最右侧的操作区，不随标签内容滚动，也不被挤出可视区域。
- 标签提供关闭 X。当前标签始终显示 X；非当前标签在鼠标悬停或键盘聚焦时显示 X。鼠标悬停关闭按钮时，用浅色圆形底突出关闭目标。
- 新建按钮执行新建文档/标签；相邻的下拉按钮打开当前工作区所有已打开标签的列表，列表项可直接切换文档。
- 打开标签列表中“全部关闭”固定在顶部，并在其下方显示一条横向分隔线；文件条目区域独立纵向滚动。标签栏加号左侧不显示竖向分隔线。
- 标签栏的新建与列表图标略大于原尺寸，保持清晰可辨，同时不改变按钮尺寸和操作区布局。
- 当前文件名使用主题强调色及稍高字重突出；关闭全部标签后，工作区进入无打开文档状态，用户仍可从文件树重新打开文档或新建标签。
- 点击标签主体只切换标签；点击关闭 X 只关闭该标签，两种点击区域不得互相触发。

### 设计原因

隐藏滚动条可以让多标签栏保持截图中的简洁外观，同时保留滚轮和触控板滚动，避免标签数量增加后挤压编辑区。把新建与标签列表操作固定在最右侧，可以让用户在标签很多时仍快速创建和查找文档；移除加号左侧竖线，避免操作区与标签栏之间出现不必要的硬分隔。略微放大两个图标，让常用操作更容易辨认。“全部关闭”下方的横线则清楚区分批量操作与可滚动的标签列表，且不影响列表项区域独立滚动。主题色让当前文档一眼可辨。关闭 X 在当前、悬停或键盘焦点状态下出现，并在按钮悬停时加圆形底，可让关闭目标明确，同时减少每个标签常驻图标带来的拥挤和误关风险。

## 8. 文件浏览器

- 当前选择的工作区文件夹名称固定在文件浏览区域顶部，从左侧边距开始显示，不提供根目录折叠按钮；滚动树内容时标题行保持可见。
- 鼠标悬停文件浏览区域或键盘焦点进入该区域时，标题行右侧显示四个操作：新建文件、新建文件夹、刷新、展开/收起所有子文件夹。默认状态隐藏这些按钮，减少文件树上方的常驻控件。
- 第一级子文件夹行左侧缩进为 5px；更深层的子文件夹保持额外缩进，文件行在所属子文件夹基础上继续缩进，清楚表达父子层级。
- 文件夹始终排列在同级文件之前。文件夹使用独立展开/收起状态；全局操作只处理子文件夹，不改变当前工作区根目录。
- 当所有子文件夹均收起时，批量按钮显示“展开所有子文件夹”及向下的展开图标；只要至少一个子文件夹展开，按钮切换为“收起所有子文件夹”及向上的收起图标。
- 原型必须提供多层文件夹、Markdown 文件和至少一个素材文件示例；点击 Markdown 文件可打开对应示例文档，根目录 README 用作内容索引。

### 设计原因

固定工作区标题能在长文件树滚动时保留当前位置上下文，并从左侧开始排列可减少装饰控件对名称的挤压。第一级左侧缩进直接设为 5px，贴合参考图标出的边界，同时保留文件内容的更深缩进来表达层级。四个操作在指针进入文件浏览区域后出现，既符合参考图的按需操作方式，也避免默认挤占文件名空间。文件夹先于文件、文件内容再多缩一级，能让目录层次更容易扫读。根目录 README 提供示例清单，方便首次打开时快速理解目录用途。

## 9. 源码模式滚动

- 源码模式与可视化模式共用同一个编辑区视口、内容列宽和最右侧滚动条位置；切换模式不得横向挪动编辑区或滚动条。
- 源码输入区随源码内容高度增长，不提供独立的内部滚动条；上下滚动统一由编辑区外层滚动容器处理。
- 模式切换沿用同一文档滚动位置，不因 textarea 自身滚动状态导致内容错位。

### 设计原因

源码区内部再出现一根滚动条会与编辑区最右侧的主滚动条并列，造成重复滚动入口，也会让两种模式的视觉宽度和滚动位置看起来不一致。让源码输入区随内容增长后，两个模式都由同一个外层视口滚动，编辑列宽、滚动条位置和文档滚动语义保持稳定。

## 10. 系统菜单栏与窗口栏

- 系统菜单栏按操作系统惯例布局，并使用 Aline 名称与应用图标。
- macOS 菜单位于窗口上方、独立的系统菜单栏区域。菜单顺序为 Aline、文件、编辑、插入、格式、视图、主题、窗口、帮助；Aline 菜单包含关于、设置、服务、隐藏、显示全部与退出等系统操作，帮助菜单不重复放置“关于”。
- Windows 菜单与最小化、最大化/还原、关闭按钮位于同一标题栏行；菜单顺序为文件、编辑、插入、格式、视图、主题、窗口、帮助。设置与退出位于文件菜单末尾，“关于 Aline”位于帮助菜单。MarkFlow 在 Linux 上采用相同的桌面菜单结构。
- “视图”菜单不包含主题入口。“主题”菜单先列出白天、夜间、护眼三种模式，以分隔线与主题家族区分；下方列出全部主题家族，主题列表限高并在溢出时独立滚动。两个分组都显示当前选中项；切换模式会关闭“随系统切换”，切换主题家族不会改变模式。
- 菜单项按 MarkFlow 的分组、分隔线、子菜单、快捷键和可用状态呈现。尚未实现的菜单项保留在对应位置并置灰；需要工作区或文档的操作按当前状态启用或禁用。
- 原型提供 macOS 与 Windows 两种系统栏预览状态，便于分别评审平台布局。

### 设计原因

菜单位置遵循操作系统既有习惯：macOS 的应用菜单属于屏幕顶部系统菜单栏，Windows 则把应用菜单与窗口控制放在同一标题栏。保持各平台熟悉的入口位置，可避免自定义窗口结构与系统操作相互竞争。把主题独立成菜单并按“模式 / 主题家族”分组，能让两类操作一处可达且含义清晰；限制主题列表高度可避免主题变多后菜单过长。按状态置灰未实现或暂不可用的项目，也让菜单结构保持稳定并清楚表达能力边界。

## 11. 右键菜单

- 所有右键菜单使用统一的紧凑菜单表面、行高、圆角、悬停/焦点/禁用状态和屏幕边界定位；一处菜单打开时，只显示该菜单，不叠加其他菜单。
- 菜单位置跟随右键位置；靠近窗口边缘时自动移入可视区域。点击菜单外部、选择菜单项、按 Escape 或滚动页面后关闭。打开时焦点进入菜单，键盘可上下移动、Enter 执行、左右方向键展开或收起子菜单。
- 可视化编辑区的普通文本右键菜单包含新增链接、文本格式、段落设置、插入，以及剪切、复制、粘贴、纯文本粘贴和全选；格式、段落与插入操作使用子菜单。
- 源码模式右键菜单提供剪切、复制、粘贴、纯文本粘贴和全选，操作保留源码光标与选区语义。
- 文件树右键菜单随目标显示对应操作：文件/文件夹提供新建、重命名、复制副本、删除、复制路径、关闭工作区和在文件管理器中显示；空白区域提供工作区级操作。删除使用危险操作样式，且需确认。
- 表格单元格右键菜单提供行列插入、删除行列、删除表格、对齐及表头行操作；图片菜单提供复制、另存为、复制路径和打开所在位置；Mermaid/PlantUML 等图表菜单提供 SVG/PNG 导出与复制。
- 右键标签页可关闭当前、关闭其他或关闭所有标签，并可恢复最近关闭的标签。
- 右键菜单项的启用状态随当前选择、文档是否可编辑和操作对象能力变化；危险项使用主题语义色，不以颜色代替确认流程。

### 设计原因

统一的菜单视觉和键盘行为让不同区域的右键入口容易识别，同时让每种内容只显示与其能力相关的操作。把格式、段落和插入等较长操作收进子菜单，可控制主菜单长度；根据光标、选区与目标类型提供菜单内容，则减少不可用命令和误操作。

## 12. 外观设置与主题

- 外观页先提供“模式”选项：白天、夜间、护眼；三种模式互斥且当前模式有明确选中态。
- “随系统切换”根据操作系统外观在白天与夜间之间切换。用户手动选择白天、夜间或护眼时，自动关闭该开关；系统主题变化只在开关开启时生效。
- 窗口底部状态栏的模式切换按钮旁提供快速切换主题按钮；点击后向上展开 GitHub、Notion、Vue、飞书主题家族选项，选择后立即应用并同步主题配置卡片的选中态。快速切换主题不改变白天/夜间/护眼模式，也不关闭“随系统切换”。
- 选择主题家族只更换配色家族，不改变当前模式，也不关闭“随系统切换”。
- 页面顺序为模式、字体与排版、界面、主题配置；主题配置固定放在外观页最下方。
- 主题配置读取主题目录中的 GitHub（默认）、Notion、Vue、飞书及用户主题。卡片仅展示当前模式的一张实际截图；悬停出现轻量预览蒙层，点击进入大图预览，左右按钮或键盘左右方向键切换白天、夜间、护眼模式。
- 主题卡片边框紧凑，选择态使用主题强调色。主题配置提供打开主题文件夹、导入 ZIP、刷新；内置主题在安装或首次启动时同步，导入仍须通过结构、清单、颜色和三张不同模式预览图片校验，刷新重新扫描目录。主题包必须含三张预览图，但界面不重复提示这一打包要求。
- 卡片在当前模式缩略图旁展示主题简介，最多显示五行；超出部分默认隐藏，悬停或键盘聚焦显示完整内容。将简介放入缩略图原先的剩余空间，避免卡片右侧出现无信息的大块留白；“内置/已导入”状态与主题名同行显示。右侧文本区域足够容纳多行描述，因此比两行简介更充分地说明各主题的阅读风格。
- 主题卡片点击必须立即应用主题，并同步更新卡片选中态、强调色和当前模式预览；外观页和快速切换入口调用相同主题选择状态，避免出现点击无反馈或状态滞后。
- 原型在浏览器中通过新标签直接打开 `prototype/themes/` 目录；ZIP 导入以本地浏览器存储模拟安装。正式应用须连接平台文件系统并直接打开系统主题目录，执行安装与扫描。详见[主题包规范](./theme-package-spec.md)。
- 主题菜单选项、主题默认标记和主题预览标签的文字字号至少为 11px，保证状态栏菜单与缩略说明仍可辨认。

### 设计原因

把模式控制与主题家族分开，用户可以独立选择阅读模式和配色。GitHub 主题沿用 Primer/Markdown CSS 的高对比中性色、蓝色链接、轻量标题分隔线和浅色代码背景；Vue 主题使用 Vue 绿、清爽白色画布与深色代码表面；Notion 和飞书保留各自偏好的低对比界面灰阶与强调色。卡片只展示当前模式的一张小预览，减少设置页占用；悬停提示和大图中的左右切换，让用户仍可检查其他模式。点击卡片应立即更新主题和选择状态，避免点击后视觉不变；打开目录直接进入目录，省掉只重复展示路径与图片数量的中间弹窗。

主题样式参照 [GitHub Primer typography](https://primer.style/product/getting-started/foundations/typography/)、[github-markdown-css](https://github.com/sindresorhus/github-markdown-css) 的 Markdown 元素规则、[Vue 官方文档源码](https://github.com/vuejs/docs) 所用的 [@vue/theme](https://github.com/vuejs/theme)，以及 [VitePress 默认主题扩展文档](https://github.com/vuejs/vitepress/blob/main/docs/en/guide/extending-default-theme.md)。这些来源用于校准排版、代码区、链接和主题强调色；各家三种模式的具体 token 仍由 Aline 主题包维护。

## 13. 插件设置

- 设置页提供“插件”入口，页面按插件分组显示名称、说明、启用开关和所属设置项；一期列出 Mermaid、表格增强、导出、公式、代码高亮。
- 插件设置只影响对应插件。关闭插件后保留设置值；重新启用时恢复。具体入口隐藏与源码回退行为见 [plugin-system.md](./plugin-system.md)。
- Mermaid 设置中的主题选择、导入和自定义主题只作用于 Mermaid 图表，不出现在全局主题配置页，也不改变 Aline 界面配色。
- 表格行列悬停时显示的“＋”控件应贴合目标边界：行下方线左侧插入行，列右侧线顶部插入列。按钮不遮挡单元格内容，表格宽度不足时仍需保持点击区域可达。
