# macOS 句柄元数据复制隔离探针提案（已授权实验）

## 拟执行范围

仅在系统临时目录构造一次性 Rust 独立探针，使用锁定工具链与离线缓存的 `libc =0.2.191`，不修改 Cargo workspace、应用代码、lint 或守卫。拟审查一个固定的自有 `unsafe` 调用点（按样本重复执行），调用 `libc::fcopyfile`，参数限定为两个由探针自身持有的不同普通文件句柄、`state = null`、`COPYFILE_METADATA`；不接收外部路径或任意 flags。`COPYFILE_METADATA = COPYFILE_STAT | COPYFILE_ACL | COPYFILE_XATTR`，不含 DATA；按本机 `man 3 copyfile`，null state 可用，但保留 setuid/setgid 等特殊位的状态选项不可用。用户针对本隔离实验明确答复“准你完成”；该授权仅覆盖本提案所述探针。

探针独占创建权限为 0700 的临时根目录，所有源文件、目标文件及 ACL/xattr 只位于该目录中，退出后清理并记录清理失败。探针在该目录构造不同 inode 的输入/目标，手工设置 ACL allow/deny、权限位、测试 xattr 和已知不同正文，分别记录调用前后 bytes、可观察权限和系统错误。再构造复制失败及 ACL-only 变化样本；无效目标仅指 unsafe 调用前由包装层拒绝的非普通文件/同 inode，或仍持有的合法句柄上的受控失败，不构造悬空或复用 fd；权限复制失败不可发布，任何未知结果均记缺口。拒绝复制同一 inode，并验证这一步发生在调用前。只观察机制，不替换用户文件、不执行真实应用保存，也不测试跨进程 CAS、目录同步或断电保证。

## 批准边界与停止条件

这是一项**可单独裁决的实验**，不是生产 unsafe 例外，不批准修改五引擎的 `forbid` 或引入项目直接依赖。实验执行前仍须完成探针源码的独立安全评审；生产实施另需完成确定 flags/元数据政策、依赖正式准入、最小 lint/守卫配置与反例，并取得具体例外裁决。若依赖包无法离线解析、系统 API 行为不符、权限或错误无法可靠观测，应停止并记录，不能把试验成功外推到其他平台。
