# macOS 文件权限复制：最小例外候选（未批准）

## 问题与状态

当前所审安全封装不能证明可从已打开原文件向已打开临时文件复制 macOS ACL；两项反例与候选调查见 `report.md`、`backend-evaluation.md`。这不证明其他安全封装不存在。本文仅供独立审查和具体裁决，不修改生产代码、Cargo 配置或工程守卫；不得视为任何 unsafe 或新依赖已获批准。

## 候选边界

优先继续寻找满足同一边界的已审计安全封装。若证明确需自有 unsafe，建议仅在 `aline-source` 的一个 macOS 专用私有叶模块内实现窄函数：借用已打开的源普通文件及由本次操作独占创建的临时普通文件，在确认两者文件身份不同后调用系统 `fcopyfile`，以类型化结果报告错误。其余编码、输入、目标检查、写入、同步、发布和回执仍用安全 Rust；不接受调用方传原始 fd、函数指针、任意 flag 或自报权限成功。

候选标志需审查：`COPYFILE_SECURITY` 为 STAT + ACL，不含 XATTR；是否使用 `COPYFILE_METADATA`、如何处理 owner/group、特殊权限位、时间和扩展属性，不能由本文预先裁决。先通过独立样本确定不会扩大访问或丢失应保全的权限，复制失败一律停止，不凭未经平台证明的 Unsupported 继续。调用期间保有文件借用，限制同文件和句柄生命周期；需要对 ABI、参数、状态对象（或 null 的合法性）、错误读取、资源释放及特殊文件受检边界逐项形成 `SAFETY` 证明。系统返回成功也不单独证明 ACL/权限等价。

该边界不解决目标/父目录替换竞态、跨进程 CAS、写盘队列及断电保证。临时文件写入只能触及本次持有的对象；检查到冲突、取消或发布前错误应保留原目标与内存；发布后的同步或清理失败必须携带已发布事实。路径身份、符号链接和残余竞争仍须明确设计和测试。Linux/Windows 的权限能力不因本例外获得批准或视为实现。

## 依赖与工程门禁待裁决

系统 FFI 候选为 macOS target 专用精确版本 `libc =0.2.191`；当前只在 `Cargo.lock` 的其他依赖闭包中存在，校验和 `65cd87c9a6d60536580b316ad985726104730a5151c99845f2490428ef91240a`，这**不是** `aline-source` 直接依赖准入。须先登记来源、许可证、目标/features、传递与 build/dev 边、五引擎闭包并按架构 §3.2 审计；可选的已有安全封装如能满足全部要求应优先。

根 workspace 的 `unsafe_code = "forbid"` 由 `aline-source` 继承，局部 `allow` 无法覆盖 `forbid`；`scripts/check_lints.py` 要求成员继承，`scripts/check_safety.py` 也拒绝自有 unsafe。若提出例外，必须在**隔离样例**先证明可行的最小有效 lint 配置和目标限定，保留 `missing_docs` 与全部既有 Clippy 策略；修改检查器只精确识别经审查的文件/目标/操作，保留其他自有代码的 forbid，反例必须证明旁路 unsafe 和属性降级仍被拒绝。不得仅删除继承或关闭守卫。此配置尚未设计完成或验证，禁止将本文当作实施许可。

## 验证与裁决顺序

1. 裁决前仅做静态方案、依赖准入和 lint 隔离设计审查；精确核对 `libc`/平台系统调用合同、拟用 flags 和拟议 unsafe 不变量。实际自有 unsafe 代码、执行探针与生产接入均需先获具体授权，不能把本清单当成执行许可。
2. 手写独立金样与负例：ACL allow/deny、继承、特殊模式位、owner/group、复制与读取失败、目标为同一对象、符号链接替换、目标仅权限或 ACL 变化、目标内容变化、短写、取消、同步、发布和清理失败；比较 bytes 与可观察权限事实。
3. 实测 macOS APFS、实际临时目录和支持范围，报告未覆盖文件系统、Windows/Linux、ACL 变体、资源限制及平台竞态；不宣称 V-01/V-08 或 M0 出口通过。
4. 实施前获得本具体例外及依赖准入的用户裁决；如安全能力、lint 隔离或正常输入仍无法保证，应停止并回到设计，不以静默降级或普遍拒绝为替代。
