## 1. 根因

修复前 `tables()` 是逐行状态机：

- 见到 `line.startswith("[") and line.endswith("]")` 就把括号内容当作表名；
- 见到 `key = value` 就按 `([A-Za-z0-9_-]+)\s*=\s*("..."|true|false)` 正则塞进「当前表」。

它对 TOML 的**词法**一无所知，因此把多行字符串内部的行当成真实语法。夹具
`/tmp/aline-m0-independent-review.pTFf8u/D/lint-decoy/crates/aline-buffer/Cargo.toml`：

```toml
[package]
description = """
[lints]
workspace = true
[package.metadata.decoy]
"""
name="aline-buffer"
```

真实 Cargo 把中间三行读作 `description` 字符串的内容，该成员**根本没有 `[lints]` 表**；
旧扫描器却在第 3 行开了 `lints` 表、第 4 行填入 `workspace = true`，于是
`parsed["lints"] == {"workspace": True}` 成立 → 守卫判通过（exit 0）。

Cargo 实测对照（`cargo-control.txt`）：同样源码 `pub fn undocumented() {}`，
伪继承夹具 `cargo clippy ... -D warnings` exit 0，真实继承夹具 exit 101
（`missing documentation for the crate`）。两者行为差异恰好被旧守卫漏判。

这是**安全方向错误**：守卫对「伪装成继承」的成员放行，属于 fail-open。

## 2. 解析器方案

用内置的递归下降 TOML 解析器替代逐行扫描，只依赖标准库（Python 3.9.6 无
`tomllib`，环境无 `tomli`/`toml`，未联网安装）。

结构：

| 组件 | 职责 |
| --- | --- |
| `_TomlParser` | 词法 + 语法：表头、键、值、字符串、数字、日期、数组、内联表 |
| `parse_toml(text, source)` | 入口；出错一律抛 `CheckError`（带 `文件:行号: 原因`） |
| `tables(path)` | 读文件 → 解析 → 展平成 `{"a.b.c": table}`，保持原调用方签名 |
| `_strict_equal` | 区分 `bool`/`int`（避免 `True == 1` 混过 lint 值校验） |
| `audit_member_manifest` | fail-closed：`lints` 缺失 / 类型错 / 键集不等于 `{"workspace"}` / 值不是 `True` 都拒绝 |

覆盖的 TOML 构造：

- `[table]`、`[[array-of-tables]]`、`[a.b.c]` 点分表头；
- 裸键、基本字符串键、字面字符串键、点分键、空引号键；
- 基本字符串（全部转义 `\b \t \n \f \r \" \\ \uXXXX \UXXXXXXXX`）、多行基本字符串
  `"""..."""`（含行尾反斜杠续行、结尾 4/5 引号、拒绝 6 引号）；
- 字面字符串 `'...'`、多行字面字符串 `'''...'''`；
- 注释、布尔、十进制/十六进制/八进制/二进制整数（含 `_` 分隔与 i64 范围检查）；
- 浮点（含 `inf`/`nan`）、日期/时间/日期时间（校验月日时分秒与偏移）；
- 数组（多行、尾随逗号、嵌套、内联表元素）、内联表 `{ ... }`（允许换行，见第 5 节）。

**无法安全解释的构造一律拒绝（`CheckError`）**，不静默忽略：

- BOM、裸 CR 行结束符、注释/字符串中的控制字符；
- 未知转义、`\u` 位数不足、代理区码位；
- 未闭合字符串、基本字符串跨行；
- 重复键、重复表、点分键与非表值冲突；
- 内联表被后续 `[表头]` 扩展、点分键已定义的表再用表头定义；
- 普通表与数组表同名、数组表与非数组值冲突、内联表尾随逗号；
- 表头缺 `]`、行尾残留内容、非 ASCII 裸键。

语义校验（brief 目标 3）落在真实解析结果上：

- 成员：`parsed["lints"]` 必须**恰好**是 `{"workspace": True}`；`[lints.*]` 子表、
  `[[lints]]` 数组表、额外键都会让键集或类型不匹配 → 拒绝。
- 根：`[workspace.lints.rust]` / `[workspace.lints.clippy]` 用 `_strict_equal`
  与 `EXPECTED_RUST` / `EXPECTED_CLIPPY` 全等比较。

## 5. 未覆盖的 TOML 构造（诚实清单）

以下为**已知未覆盖或有意偏离**的构造。差异均已用参考实现实测确认，
方向要么「拒绝本可接受的输入」（fail-closed，安全），要么是语料中未出现的边缘情形。

**有意偏离（守卫更严，不会 fail-open）：**

1. **内联表尾随逗号**：参考实现（TOML 1.1）接受 `{ b = 1, }`；本解析器拒绝。
   方向为拒绝，不影响任何真实清单。
2. **BOM**：参考实现接受文件开头的 BOM；本解析器直接拒绝。fail-closed。

**未实现 / 未纳入自检的构造：**

3. **TOML 1.1 的 `\e`（ESC）与 `\x41`（`\x` 十六进制）转义**：TOML 1.0 无此两种，
   本解析器按 1.0 拒绝。Cargo 用的 crate 是 spec-1.1，因此理论上含 `\e`/`\x` 的
   合法清单会被我们拒绝。仓库语料中未出现。
   **实测**：`a = "\x41"` → `未知转义序列 \x`；`a = "\e"` → `未知转义序列 \e`；
   参考实现均接受（`{"a":"A"}` / `{"a":"\u001b"}`）。
4. **TOML 1.1 宽松数组类型**（`[1, "x"]` 允许异构）：本解析器不做类型检查，
   因此也不拒绝——与参考实现行为一致，但**未写自检断言**（无 lint 语义影响）。
5. **多行字符串内的裸 CR**：解析前统一做 `\r\n → \n`，因此 `"""x\r\ny"""` 会被
   规整为 `\n`；参考实现保留 `\r\n`。只影响字符串值内容，不影响表结构判定。
   未纳入自检。
6. **秒可省略的本地时间/日期时间**（`07:32`、`1979-05-27T07:32`、`...07:32Z`）：
   参考实现（1.1）接受；本解析器的 `_TIME` / `_DATETIME` 要求秒字段，会拒绝。
   fail-closed。未纳入自检。
   **实测**：三条均报 `无法识别的 TOML 值`；参考实现三条均 OK。
7. **小数秒位数上限**：本解析器对小数秒只做「至少一位」匹配，不限制 9 位精度。
   参考实现会拒绝超过精度的值。方向为宽松，但小数秒不参与 lint 语义。
8. **Unicode 裸键**（`é = 1`、`日本語 = 1`）：TOML 1.0/1.1 均不允许，本解析器拒绝；
   与参考实现一致。未写自检断言（自检里只覆盖了非 ASCII 裸键的拒绝路径）。
9. **`+0x1` / `0x_1` 这类前缀数字的符号与下划线位置**：本解析器因前缀正则不匹配而
   拒绝，与参考实现一致；未写专门自检断言。
10. **`\U` 之后的非 BMP 码位组合校验**：只校验码位范围与代理区，未做 Unicode
    非字符（noncharacter）检查。不影响表结构。
11. **表/数组表的深层语义边界**：如 `[[a.b]]` 后再 `[a]`、`[[a]]` 元素内点分键再被
    子表头定义等组合，已用差分探测确认方向正确，但只有 2 条纳入自检
    （`reject-inline-table-extended-by-header`、`reject-array-table-then-normal-table`）；
    其余组合**未固化为断言**。
12. **注释中的非 ASCII 与超长行**：未做专门断言，仅按「控制字符拒绝」处理。

计数：上述未覆盖/偏离项共 **12 条**（其中 2 条为有意偏离，10 条为未覆盖）。

## 6. 结论

F-08 已修复且方向正确：

- 伪继承夹具 exit 1（拒绝），真实继承 exit 0，正常仓库 exit 0；
- `--self-test` exit 0，原有 30 条断言不减，总数增至 57 条；
- 解析器对仓库内 9464 个真实 Cargo 清单零失败；
- 与 Cargo 同版本 `toml` crate 的 81 条差分测试一致 79 条，差异 2 条均为 fail-closed。

残余风险：第 5 节第 3、6 条（TOML 1.1 新转义、可省略秒的时间字面量）会让守卫
**过度拒绝**，不会误放行；若未来仓库清单引入这些写法，需扩展解析器。
